Appendix A

Remote Access Setup

This appendix covers three ways to access your AI development environment from outside — Tailscale VPN, NoMachine, and Windows RDP.

What This Appendix Covers
  • Why remote access is needed
  • Tailscale VPN setup (from anywhere in the world)
  • NoMachine setup (high-performance remote desktop)
  • Windows RDP setup (built into Windows)
  • Comparison and selection guide
  • Troubleshooting

Why Remote Access?

AI development environments are usually built on a powerful desktop computer — they need a fast CPU, plenty of RAM, and a dedicated GPU. But you cannot always be sitting in front of that machine. Sometimes you want to work from a laptop at a cafe, check things from a tablet while traveling, or connect from another room.

Once remote access is set up, you can connect to your powerful desktop computer from anywhere. Running Claude Code, managing projects, and putting AI agents to work can all be done without being physically present at the machine.

Remote access is like "using your home computer from the outside." Just as you use a TV remote control, you can operate the powerful computer sitting at home exactly as it is, from a cafe or the office.
You do not need to set up all three methods explained in this appendix. Pick the one that fits your situation. The Comparison & Selection Guide at the end will help you decide.

Tailscale VPN Setup

Tailscale is a WireGuard-based mesh VPN service. Even behind routers and firewalls, it creates a secure private network between your devices. Without complex network configuration, just a few clicks let you reach your computer from outside.

What is Tailscale?

Tailscale is a private network that connects your devices over the internet. Install it on both your laptop and your desktop, and you can reach the desktop as if it were on the same local network. No port forwarding, no static IP, and no router configuration required.

How Tailscale works: Every device with Tailscale installed joins a virtual private network. Each device receives its own Tailscale IP address. Devices communicate directly through these addresses, regardless of physical location.

Key Advantages

  • Easy setup — installation and activation finish in minutes
  • NAT traversal — no router configuration changes needed
  • Automatic encryption — end-to-end encryption via the WireGuard protocol
  • Free — up to 100 devices at no cost for personal use
  • Cross-platform — Windows, macOS, Linux, iOS, and Android supported

Installation Steps

1. Sign up for Tailscale — Visit tailscale.com and sign up with a Google, Microsoft, GitHub, or email account. The free plan connects up to 100 devices, which is more than enough for personal use.
2. Install Tailscale on the host PC — Install the version for your operating system from the download page.
Windows

Download the Windows installer and run it. When installation completes, the Tailscale icon appears in the system tray.

macOS

Download the macOS app or install it with Homebrew:

brew install --cask tailscale
3. Log in and activate — Open the Tailscale app and click "Log in". When the browser opens, authenticate with the account you created in step 1. After authentication, Tailscale displays the device's Tailscale IP address (e.g., 100.x.x.x).
4. Install Tailscale on the client PC — Also install Tailscale on the devices you will connect from (laptop, tablet, phone). Windows, macOS, Linux, iOS, and Android are all supported.
5. Log in with the same account — Log in on the client device with the same account. Both devices now appear in the Tailscale admin console.
6. Find the host IP — On the client device, open a terminal or command prompt and check the host IP with the following command: 
tailscale ip

You can also check it directly on the host PC:

Windows

Click the Tailscale icon in the system tray to see the IP address.

macOS

Click the Tailscale icon in the menu bar to see the IP address.

7. Test the connection — From the client device, run a ping test against the host: 
ping 100.x.x.x

Replace 100.x.x.x with the host's actual Tailscale IP. If replies come back, the VPN connection is working properly.

The Tailscale free plan is very generous. You can connect up to 100 devices, and subnet routing and MagicDNS (automatic name resolution) are included. Personal remote access costs nothing. For details, see tailscale.com/pricing.

NoMachine Setup

NoMachine is a free remote desktop application that provides a complete graphical desktop environment. Unlike Tailscale, which creates the network tunnel, NoMachine delivers a full visual remote desktop session — you see the screen, windows, and applications exactly as if you were sitting in front of that computer.

What is NoMachine?

NoMachine uses the NX protocol to deliver high-performance remote desktop sessions. It is known for being fast, responsive, and easy to configure. Both the sending side (host) and the receiving side (client) need NoMachine installed.

When should you use NoMachine?: When you want to run the Claude Desktop App GUI remotely, manage multiple windows, or use applications that require a display. In short, it is the right fit whenever you need a complete desktop environment with a visible screen.

Key Advantages

  • Low latency — fast, responsive sessions thanks to the NX protocol
  • High image quality — crisp screen transmission
  • Free — completely free for personal use
  • Cross-platform — Windows, macOS, Linux, iOS, and Android supported
  • Resilient on unstable connections — the session survives even if the internet drops

Installation Steps

1. Download NoMachine — Download the version for your operating system from nomachine.com/download.
Windows

Download and install NoMachine for Windows. Keep the default settings.

macOS

Download NoMachine for macOS and drag it into the Applications folder.

Linux

Download the .deb, .rpm, or .tar.gz package that matches your distribution.

2. Install on the host PC — Install NoMachine on the AI development desktop (host). After installation, NoMachine starts automatically as a service.
3. Enable the service — Open the NoMachine app and go to Settings → Server → Security. Make sure "Allow connections from other computers" is enabled.
4. Check the host IP — The NoMachine main window shows the host computer's local IP address (e.g., 192.168.1.100). Connecting over the internet requires a public IP address, or you can use the Tailscale IP address instead. 
# Check the local IP (Windows)
ipconfig

# Check the local IP (macOS / Linux)
ifconfig
5. Install on the client PC — Download and install NoMachine on the device you will connect from. Windows, macOS, Linux, iOS, and Android clients are all supported.
6. Connect to the host — Open NoMachine on the client device and click "New connection". Enter the host's IP address. If you are using Tailscale, enter the Tailscale IP (e.g., 100.x.x.x). Click "Connect" and enter the host computer's username and password.
NoMachine keeps working well even on unstable internet connections. Enabling "Low bandwidth mode" in the session settings or lowering the resolution makes it even more stable.

Windows RDP Setup

The Remote Desktop Protocol (RDP) is built into Windows Professional, Enterprise, and Education editions. Without any additional software, you can connect remotely to a Windows computer using the built-in Remote Desktop Connection tool.

What is Windows RDP?

Windows RDP is Microsoft's remote desktop protocol. It provides a full graphical remote session and is built directly into Windows, so the host computer needs no third-party software. Client devices can connect from Windows, Mac, iOS, and Android using the free Microsoft Remote Desktop app.

Windows Home editions do not support RDP hosting. Acting as an RDP host requires Windows Professional, Enterprise, or Education. If you are on Windows Home, use NoMachine instead.

Setup Steps

1. Enable Remote Desktop — On the host computer (Windows), press Win + S, type "Remote Desktop Settings", and press Enter. Toggle "Enable Remote Desktop" on. If Windows asks for confirmation, click Confirm.
2. Check the firewall rule — When you enable Remote Desktop, Windows automatically creates a firewall rule allowing RDP connections on port 3389. Under Windows Defender Firewall → Allow an app or feature through Windows Defender Firewall, verify that Remote Desktop is checked.
3. Verify the user account — Confirm the Windows user account and password you will use to log in remotely. An account with administrator privileges is recommended. 
# Check the current user name
whoami

# Check system information
systeminfo | findstr /B /C:"Host Name" /C:"OS Name"
4. Set up RDP port forwarding (for internet access) — To connect from outside the local network, your router must forward port 3389 to the host machine's local IP.
  1. Log in to the router's admin panel (usually 192.168.1.1 or 192.168.0.1).
  2. Find the Port Forwarding (or NAT) section.
  3. Create a new rule: external port 3389, internal port 3389, internal IP = the desktop's local IP (e.g., 192.168.1.100), protocol = TCP.
  4. Save and apply the rule.
5. Find the host's public IP — On the host computer, open a browser and visit whatismyipaddress.com or search for "what is my IP address". Write this address down — you will use it when connecting from the client.
6. Connect from the client — On the remote device, open the Remote Desktop Connection tool.
Windows client

Press Win + R, type mstsc, and press Enter. Enter the host's public IP address and click "Connect".

mstsc
Mac / iOS / Android

Download the free Microsoft Remote Desktop app from the App Store or Google Play. Add a new connection using the host's public IP address.

Security warning: Exposing RDP directly to the internet is very risky. Automated bots constantly scan for open RDP ports. To reduce the risk: (1) use a strong, unique password on the host Windows account, (2) enable Network Level Authentication (NLA) in the Remote Desktop settings, and (3) it is strongly recommended to use the Tailscale VPN instead of port forwarding so that RDP is reachable only within the private network.

Comparison & Selection Guide

Each remote access method has strengths and weaknesses. Use the comparison table below to make the best choice for your situation.

Item Tailscale NoMachine Windows RDP
Difficulty Easy Moderate Easy
Cost Free (100 devices) Free Free
Image quality Moderate Excellent Excellent
Latency Low Very low Low
Cross-platform ✓ ✓ ✗ (Windows only)
VPN required Its own VPN No Separate VPN needed
Installation Install on both sides Install on both sides Not required
GUI environment CLI-focused Full GUI Full GUI

Tailscale VPN

  • WireGuard-based encryption
  • No port forwarding needed
  • Passes through NAT / firewalls
  • Free for up to 100 devices
  • Best for command-line access
  • Minimal bandwidth overhead
  • The most secure option

NoMachine

  • Complete graphical desktop
  • High performance (NX protocol)
  • Free for personal use
  • Cross-platform
  • Easy installation
  • Best for GUI workflows
  • Adjustable image quality

Windows RDP

  • Built into Windows Pro+
  • No extra host software
  • Complete desktop environment
  • Port forwarding needed for internet access
  • Security risk if exposed directly
  • Best for pure Windows environments
  • Microsoft Remote Desktop client

Recommended Combinations

Situation Recommended setup Why
Connecting only within your home Windows RDP No extra installation, convenient on the same WiFi network
Command line only (Claude Code CLI, SSH, terminal) Tailscale alone Lightweight and secure, with no GUI overhead
Using the Claude Desktop App GUI remotely Tailscale + NoMachine Tailscale provides the secure tunnel, and NoMachine provides the graphical session
Windows Pro + maximum security Tailscale + Windows RDP Tailscale replaces port forwarding, and RDP is reachable only inside the private VPN
Recommendation for beginners: Set up Tailscale first. It is the simplest and most secure. If you need a graphical environment, use the Tailscale + NoMachine combination. Install Tailscale on both devices to create the secure network, then use NoMachine for a full remote desktop session. It works on both Windows and macOS, requires no router configuration, and keeps the connection secure.

Troubleshooting

Here are the most common remote access problems and how to solve them.

1. Cannot connect — First check that the host computer is powered on and connected to the internet. Then check each tool:
  • Tailscale: Both devices must show as online in the Tailscale admin console. Try restarting the Tailscale service.
  • NoMachine: Check that NoMachine is running on the host and that "Allow connections" is enabled in the server settings.
  • RDP: Check that Remote Desktop is enabled in Windows Settings and that port 3389 is not blocked by your router or ISP.
2. Speed is too slow or the session stutters — Remote desktop performance depends on your internet speed. Try the following:
  • Lower the display resolution in the remote desktop client settings.
  • Close unnecessary applications on the host computer to free resources.
  • With NoMachine, enable "Low bandwidth mode" in the session settings or lower the image quality.
  • With RDP, lower the color depth in the connection options and disable wallpaper and font smoothing.
  • Connect through Tailscale (the local VPN path) instead of the public internet via port forwarding.
3. Authentication or login fails — If you cannot log in:
  • Double-check the username and password. With Windows RDP you must use the host computer's Windows account credentials.
  • With Tailscale, check that both devices are logged in with the same Tailscale account.
  • With NoMachine, enter the host computer's OS username and password (unless you set up a separate NoMachine password).
  • If you recently changed the password on the host, the client may have cached the old credentials. Clear the saved password and try again.
4. Blocked by a firewall — If the connection is blocked by a firewall:
  • In Windows Defender Firewall, check that Tailscale, NoMachine, and Remote Desktop are "Allowed".
  • In the router firewall, check that the required ports are open: Tailscale (handled automatically), NoMachine (port 4000), RDP (port 3389).
  • On a corporate or school network, the network administrator may be blocking VPN traffic. Contact the administrator or try a different network.
5. Multiple monitor issues — If multiple monitors do not display correctly in the remote session:
  • RDP: Before connecting, check the "Use all my monitors" option under the "Display configuration" tab.
  • NoMachine: You can adjust the monitor layout in the session settings. Switching to a single monitor may improve performance.
  • Inside the remote session, press Win + P to change the display mode (duplicate, extend, single screen).
  • If the problem persists, reconnect with only one monitor attached to the client device, then adjust the display settings within the session.
Still not solved? If none of the fixes above resolve the problem, check each tool's official documentation: Tailscale Knowledge Base, NoMachine Support, Microsoft RDP Documentation.
