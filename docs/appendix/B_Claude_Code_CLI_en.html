Appendix B

Claude Code CLI Guide

This appendix covers the Claude Code CLI — installation, basic usage, key commands, and project mode. While this handbook primarily uses Claude Desktop App, the CLI offers more powerful automation capabilities.

What This Appendix Covers
  • CLI vs Desktop App comparison
  • Claude Code CLI installation
  • Basic usage (terminal conversation)
  • Key commands
  • Project mode
  • Practical tips

CLI vs Desktop App

Anthropic provides two ways to interact with Claude for development work: the Claude Desktop App (a graphical application you have been using throughout this handbook) and the Claude Code CLI (a command-line tool that runs in your terminal). Both connect to the same Claude model, but they serve different purposes.

The Desktop App is ideal for conversations, brainstorming, and interactive tasks. The CLI, on the other hand, is designed for direct integration with your codebase — it can read your files, run commands, edit code, and execute scripts — all from the terminal. For multi-agent harness workflows, the CLI is the engine that powers agent execution.

Claude Desktop App

  • Graphical interface (GUI)
  • Conversational chat experience
  • Artifacts for previewing code and documents
  • Best for learning, brainstorming, and exploration
  • No direct file system access
  • Easier for beginners

Claude Code CLI

  • Terminal-based interface
  • Direct file read/write and code editing
  • Runs shell commands and scripts
  • Best for automation, CI/CD, and agent workflows
  • Full access to your local project files
  • More powerful for advanced users
Which one should you use? Start with the Desktop App if you are new to Claude — it is the most approachable. Once you are comfortable and want to run multi-agent harness workflows (co-consult, co-deck), the CLI becomes essential. Many users end up using both: the Desktop App for exploration and the CLI for execution.
The Claude Code CLI requires a Claude Pro or Claude Max subscription, the same as the Desktop App. Your subscription covers both interfaces. If you can use the Desktop App, you can use the CLI.

Installing Claude Code CLI

The Claude Code CLI is installed via npm (Node Package Manager). Before installing Claude Code CLI itself, make sure you have Node.js installed on your system.

Step 1: Install Node.js — Claude Code CLI requires Node.js version 18 or later.
Windows
winget install OpenJS.NodeJS.LTS

Or download the installer from nodejs.org.

macOS
brew install node
Linux (Ubuntu/Debian)
sudo apt update && sudo apt install -y nodejs npm
Step 2: Verify Node.js installation — Confirm that Node.js and npm are properly installed. 
node --version
npm --version

Expected result: v20.x.x or higher for Node.js, 10.x.x or higher for npm.

Step 3: Install Claude Code CLI — Install the Claude Code CLI globally using npm. 
npm install -g @anthropic-ai/claude-code
Step 4: Verify the installation — Check that Claude Code CLI is available. 
claude --version

If a version number is displayed, the installation was successful.

Step 5: Authenticate — Before using Claude Code CLI for the first time, you must authenticate with your Anthropic account. 
claude auth login

A browser window will open. Log in with the same Anthropic account you use for Claude Desktop App. Once authentication is complete, you can start using Claude Code CLI.

On Windows, if you see a "claude is not recognized" error after installation, restart your terminal. If the issue persists, verify that the npm global bin directory (usually %APPDATA%\npm) is in your system PATH environment variable.

Basic Usage

Once Claude Code CLI is installed and authenticated, you can start a conversation directly in your terminal. The basic flow is simple: navigate to your project folder, launch Claude, and start chatting.

Starting a Session

To start using Claude Code CLI, open a terminal and follow these steps:

Navigate to your project folder — Use cd to move to the directory containing your project files. 
cd ~/git/project/my-harness
Launch Claude Code — Type claude and press Enter. 
claude
Claude will load your project context and display a welcome message. You can now type your request in natural language, just like chatting with Claude Desktop App.
Interact with Claude — Type your question or instruction and press Enter. Claude can read files, edit code, run terminal commands, and explain its reasoning. When Claude needs permission to execute a command or modify a file, it will ask you first.
End the session — Type /exit or press Ctrl+C to end the Claude Code session.
When you start Claude Code CLI in a project directory, Claude automatically reads the project structure and configuration files (such as CLAUDE.md, AGENTS.md, or .claude/ directories). This context helps Claude understand your project and follow your workspace rules.

Key Commands

Claude Code CLI provides a set of slash commands that give you quick access to common actions. These commands are typed at the Claude prompt (prefixed with /).

Command Description Example
/help Display a list of all available commands and their descriptions /help
/exit End the current Claude Code session and return to the terminal /exit
/clear Clear the conversation history within the current session /clear
/compact Summarize the conversation so far to free up context window space /compact
/model Switch to a different Claude model (e.g., Claude Sonnet, Claude Opus) /model claude-sonnet-5
/cost Display token usage and estimated cost for the current session /cost
/config View or modify Claude Code configuration settings /config
/doctor Run diagnostics to check Claude Code health and configuration /doctor
/login Re-authenticate with your Anthropic account /login
/logout Sign out of your Anthropic account /logout

Common Usage Patterns

Beyond slash commands, the most common way to use Claude Code CLI is through natural language instructions. Here are some typical patterns:

Reading project files — Ask Claude to read and explain any file in your project. 
Read agents/pm.md and explain the PM Agent's role
Editing files — Ask Claude to make changes to your code or configuration files. 
Add a new agent entry for "translator" to the AGENTS.md roster table
Running commands — Claude can execute terminal commands on your behalf. 
Run bun scripts/audit.ts and show me the results
Claude will ask for your permission before executing any command.
Debugging — Paste error messages and ask Claude to diagnose and fix the issue. 
I get a "module not found" error when running the audit script.
  Check the dependencies and suggest a fix.
Permission model: Claude Code CLI asks for your permission before performing potentially destructive actions such as writing files, executing shell commands, or making network requests. You can grant or deny each request individually. This gives you full control over what Claude does in your project.

Project Mode

When you launch Claude Code CLI inside a project directory, it automatically enters project mode. This is the most important concept for multi-agent harness users to understand.

What is Project Mode?

In project mode, Claude Code reads configuration files that define how it should behave within your project. These files act as "instructions" that Claude follows for every interaction in that project. The key files are:

File Purpose Read by
CLAUDE.md Main instruction file for Claude — contains project rules, coding standards, and workflow definitions Claude Code CLI
AGENTS.md Agent ecosystem registry — defines all agents, their roles, phases, and dispatch rules PM Agent (orchestrator)
agents/*.md Individual agent definition files — each agent's detailed instructions and scope Respective specialist agent
.claude/commands/*.md Custom slash commands — reusable prompt templates you can invoke Claude Code CLI
.claude/skills/*/SKILL.md Skill definitions — specialized capabilities loaded on demand Claude Code CLI

Why Project Mode Matters for Harness Users

When you run a multi-agent harness (such as co-consult or co-deck), Claude Code CLI reads the project configuration files and automatically:

  • Loads agent definitions — It knows which agents exist, what they do, and when to dispatch them.
  • Follows workflow rules — It respects the phase gates, quality checks, and handoff contracts defined in your configuration.
  • Applies coding standards — It follows the coding conventions and file organization rules specified in your project.
  • Enforces permissions — It understands which agents can edit which files, preventing unauthorized modifications.
Key insight: The power of Claude Code CLI comes from the combination of the CLI itself and the project configuration files. Without configuration files, Claude Code CLI is a general-purpose coding assistant. With configuration files, it becomes a specialized orchestrator that follows your team's rules and workflows automatically.

Launching with a Specific Prompt

You can pass an initial prompt directly when launching Claude Code CLI, which is useful for automation and scripting:

# Start Claude with an initial prompt
claude "Run the audit script and report any issues"

# Start Claude in non-interactive mode (for automation)
claude -p "Generate a summary of all agent definitions"
The -p (print) flag runs Claude in non-interactive mode. Claude processes the prompt, outputs its response, and exits. This is especially useful for scripting and CI/CD integration.

Practical Tips

Here are five practical tips to help you get the most out of Claude Code CLI, based on common patterns from multi-agent harness users.

Tip 1: Keep CLAUDE.md Updated — Your CLAUDE.md file is Claude's primary instruction set for your project. Keep it current with your latest coding standards, workflow rules, and project conventions. An outdated CLAUDE.md leads to inconsistent behavior. Whenever you change your project structure or agent definitions, review and update CLAUDE.md accordingly.
Tip 2: Use /compact When Context Fills Up — Long conversations consume the context window. When you notice Claude starting to "forget" earlier parts of the conversation or its responses becoming less accurate, type /compact. This summarizes the conversation history so far, freeing up space for new interactions without losing the essential context.
Tip 3: Grant Permissions Wisely — Claude Code CLI asks for permission before executing commands and modifying files. While it is tempting to always approve, take a moment to review what Claude is about to do, especially for rm, git push, or other irreversible operations. This habit prevents accidental data loss.
Tip 4: Leverage Non-Interactive Mode for Automation — Use claude -p "your prompt" to run Claude in non-interactive mode within shell scripts. This enables powerful automation patterns, such as running quality checks, generating documentation, or triggering agent workflows as part of a CI/CD pipeline. Combine this with shell pipes and redirection to integrate Claude's output into your existing toolchain.
Tip 5: Use the /cost Command to Monitor Usage — Claude Code CLI tracks token usage for each session. Type /cost at any time to see how many tokens you have consumed and the estimated cost. This helps you stay within your subscription limits and understand which types of tasks consume the most resources. If a session is getting expensive, consider starting a fresh session with /clear.
Getting help: If you run into issues with Claude Code CLI, the official documentation is at docs.anthropic.com/en/docs/claude-code. You can also type /help within Claude Code CLI for a quick reference of available commands, or run /doctor to diagnose common configuration problems.
