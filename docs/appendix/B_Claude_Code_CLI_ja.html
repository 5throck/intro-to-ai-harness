Claude Code CLIガイド

この付録ではClaude Code CLIの — インストール、基本的な使い方、主要コマンド、プロジェクトモードについて説明します。このハンドブックでは主にClaude Desktop Appを使用していますが、CLIはより強力な自動化機能を提供します。

この付録で扱う内容
  • CLIとDesktop Appの比較
  • Claude Code CLIのインストール
  • 基本的な使い方（ターミナルでの会話）
  • 主要なコマンド
  • プロジェクトモード

CLIとDesktop Appの比較

Anthropicは開発作業用にClaudeと対話する2つの方法を提供しています:Claude Desktop App（このハンドブックで使ってきたグラフィカルアプリケーション）とClaude Code CLI（ターミナルで動作するコマンドラインツール）です。両方とも同じClaudeモデルに接続しますが、用途が異なります。

Desktop Appは会話、ブレインストーミング、インタラクティブなタスクに最適です。一方、CLIはコードベースとの直接的な統合のために設計されています — ファイルの読み取り、コマンドの実行、コードの編集、スクリプトの実行をすべてターミナルから行えます。マルチエージェントハーネスのワークフローでは、CLIがエージェント実行を駆動するエンジンです。

Claude Desktop App

  • グラフィカルインターフェース（GUI）
  • 会話型チャット体験
  • コードやドキュメントのプレビュー用アーティファクト
  • 学習、ブレインストーミング、探索に最適
  • ファイルシステムへの直接アクセスなし
  • 初心者向けで使いやすい

Claude Code CLI

  • ターミナルベースのインターフェース
  • ファイルの直接読み書きとコード編集
  • シェルコマンドとスクリプトの実行
  • 自動化、CI/CD、エージェントワークフローに最適
  • ローカルプロジェクトファイルへのフルアクセス
  • 上級者により強力
どちらを使うべき？ Claudeに不慣れな場合はDesktop Appから始めるのが最もアプローチしやすいです。マルチエージェントハーネスのワークフロー（co-consult、co-deck）を実行できるようになったら、CLIが必須になります。多くのユーザーは両方を使い分けています: 探索にはDesktop App、実行にはCLI。
Claude Code CLIにはClaude ProまたはClaude Maxサブスクリプションが必要です。Desktop Appと同じです。サブスクリプションは両方のインターフェースで利用できます。Desktop Appが使えれば、CLIも使えます。

Claude Code CLIのインストール

Claude Code CLIはnpm（Node Package Manager）経由でインストールします。Claude Code CLI自体をインストールする前に、システムにNode.jsがインストールされていることを確認してください。

ステップ1: Node.jsをインストールする — Claude Code CLIにはNode.jsバージョン18以降が必要です。
Windows
winget install OpenJS.NodeJS.LTS

またはnodejs.orgからインストーラーをダウンロードします。

macOS
brew install node
Linux (Ubuntu/Debian)
sudo apt update && sudo apt install -y nodejs npm
ステップ2: Node.jsのインストールを確認する — Node.jsとnpmが正しくインストールされていることを確認します。 
node --version
npm --version

期待される結果: Node.jsが v20.x.x 以上、npmが 10.x.x 以上。

ステップ3: Claude Code CLIをインストールする — npmを使用してClaude Code CLIをグローバルにインストールします。 
npm install -g @anthropic-ai/claude-code
ステップ4: インストールを確認する — Claude Code CLIが利用可能であることを確認します。 
claude --version

バージョン番号が表示されれば、インストールは成功しています。

ステップ5: 認証する — Claude Code CLIを初めて使用する前に、Anthropicアカウントで認証する必要があります。 
claude auth login

ブラウザウィンドウが開きます。Claude Desktop Appで使用しているのと同じAnthropicアカウントでログインしてください。認証が完了すると、Claude Code CLIを使い始めることができます。

Windowsでインストール後に"claude is not recognized"エラーが出る場合は、ターミナルを再起動してください。問題が解決しない場合、npmのグローバルbinディレクトリ（通常は %APPDATA%\npm）がシステムのPATH環境変数に含まれていることを確認してください。

基本的な使い方

Claude Code CLIがインストールされ、認証が完了したら、ターミナルで直接会話を始めることができます。基本的な流れはシンプルです: プロジェクトフォルダに移動し、Claudeを起動し、チャットを始めます。

セッションの開始

Claude Code CLIを使い始めるには、ターミナルを開き、以下の手順に従います:

プロジェクトフォルダに移動する — cdを使ってプロジェクトファイルがあるディレクトリに移動します。 
cd ~/git/project/my-harness
Claude Codeを起動する — claudeと入力してEnterを押します。 
claude
Claudeがプロジェクトコンテキストを読み込み、ウェルカムメッセージを表示します。Claude Desktop Appとチャットするのと同じように、自然言語でリクエストを入力できます。
Claudeと対話する — 質問や指示を入力してEnterを押します。Claudeはファイルの読み取り、コードの編集、ターミナルコマンドの実行、推論の説明を行えます。Claudeがコマンドの実行やファイルの変更に許可が必要な場合は、事前に尋ねます。
セッションを終了する — /exitと入力するか、Ctrl+Cを押してClaude Codeセッションを終了します。
プロジェクトディレクトリでClaude Code CLIを起動すると、Claudeは自動的にプロジェクト構造と設定ファイル（CLAUDE.md、AGENTS.md、.claude/ディレクトリなど）を読み込みます。このコンテキストはClaudeがプロジェクトを理解し、ワークスペースのルールに従うのに役立ちます。

主要なコマンド

Claude Code CLIは、一般的なアクションに素早くアクセスできるスラッシュコマンドセットを提供します。これらのコマンドはClaudeプロンプトで入力します（/プレフィックス付き）。

コマンド 説明 例
/help 利用可能なすべてのコマンドとその説明を表示する /help
/exit 現在のClaude Codeセッションを終了してターミナルに戻る /exit
/clear 現在のセッション内の会話履歴をクリアする /clear
/compact これまでの会話を要約してコンテキストウィンドウの空きを確保する /compact
/model 別のClaudeモデルに切り替える（例: Claude Sonnet、Claude Opus） /model claude-sonnet-5
/cost 現在のセッションのトークン使用量と推定コストを表示する /cost
/config Claude Codeの設定を表示または変更する /config
/doctor Claude Codeのヘルスチェックと設定診断を実行する /doctor
/login Anthropicアカウントで再認証する /login
/logout Anthropicアカウントからサインアウトする /logout

よく使うパターン

スラッシュコマンド以外に、Claude Code CLIを自然言語の指示で使うのが最も一般的です。以下に典型的なパターンを示します:

プロジェクトファイルの読み取り — Claudeにプロジェクト内の任意のファイルを読み取って説明してもらいます。 
agents/pm.mdを読んで、PMエージェントの役割を説明して
ファイルの編集 — Claudeにコードや設定ファイルの変更を依頼します。 
AGENTS.mdのロスターテーブルに「translator」の新しいエージェントエントリを追加して
コマンドの実行 — Claudeはあなたに代わってターミナルコマンドを実行できます。 
bun scripts/audit.tsを実行して結果を表示して
Claudeはコマンドを実行する前に許可を求めます。
デバッグ — エラーメッセージを貼り付け、Claudeに診断と修正を依頼します。 
監査スクリプトを実行すると「module not found」エラーになります。
  依存関係をチェックして修正案を提案して。
パーミッションモデル: Claude Code CLIは、ファイルの書き込み、シェルコマンドの実行、ネットワークリクエストの送信など、破壊的な可能性のあるアクションを実行する前に許可を求めます。各リクエストを個別に許可または拒否できます。これにより、Claudeがプロジェクトで行うことを完全に制御できます。

プロジェクトモード

プロジェクトディレクトリ内でClaude Code CLIを起動すると、自動的にプロジェクトモードに入ります。これはマルチエージェントハーネスユーザーが理解すべき最も重要な概念です。

プロジェクトモードとは？

プロジェクトモードでは、Claude Codeはプロジェクト内での動作方法を定義する設定ファイルを読み込みます。これらのファイルはClaudeがそのプロジェクトのすべての対話で従う「指示」として機能します。主要なファイルは以下の通りです:

ファイル 目的 読み取り元
CLAUDE.md Claude用のメイン指示ファイル — プロジェクトルール、コーディング規格、ワークフロー定義を含む Claude Code CLI
AGENTS.md エージェントエコシステムレジストリ — すべてのエージェント、その役割、フェーズ、ディスパッチルールを定義 PMエージェント（オーケストレーター）
agents/*.md 個別のエージェント定義ファイル — 各エージェントの詳細な指示とスコープ 各スペシャリストエージェント
.claude/commands/*.md カスタムスラッシュコマンド — 呼び出せる再利用可能なプロンプトテンプレート Claude Code CLI
.claude/skills/*/SKILL.md スキル定義 — オンデマンドで読み込まれる専門的な機能 Claude Code CLI

ハーネスユーザーにとってプロジェクトモードが重要な理由

マルチエージェントハーネス（co-consultやco-deckなど）を実行すると、Claude Code CLIはプロジェクト設定ファイルを読み込み、自動的に以下を行います:

  • エージェント定義の読み込み — どのエージェントが存在し、何を行い、いつディスパッチされるかを把握します。
  • ワークフロールールの遵守 — 設定で定義されたフェーズゲート、品質チェック、引き継ぎコントラクトを尊重します。
  • コーディング規格の適用 — プロジェクトで指定されたコーディング規約とファイル編成ルールに従います。
  • 権限の強制 — どのエージェントがどのファイルを編集できるかを理解し、不正な変更を防止します。
重要なポイント: Claude Code CLIの力は、CLI自体とプロジェクト設定ファイルの組み合わせから来ます。設定ファイルがなければ、Claude Code CLIは汎用的なコーディングアシスタントです。設定ファイルがあれば、チームのルールとワークフローを自動的に従う専門のオーケストレーターになります。

初期プロンプトを指定して起動する

Claude Code CLIを起動する際に初期プロンプトを直接渡すことができます。これは自動化やスクリプティングに便利です:

# 初期プロンプト付きでClaudeを起動
claude "監査スクリプトを実行して問題を報告して"

# 非対話モードでClaudeを起動（自動化用）
claude -p "すべてのエージェント定義の要約を生成して"
-p（print）フラグはClaudeを非対話モードで実行します。Claudeはプロンプトを処理し、レスポンスを出力して終了します。スクリプティングやCI/CD統合に特に便利です。

実践的なヒント

マルチエージェントハーネスユーザーの一般的なパターンに基づいた、Claude Code CLIを最大限に活用するための5つの実践的なヒントを紹介します。

ヒント1: CLAUDE.mdを常に最新に保つ — CLAUDE.mdファイルはClaudeにとってプロジェクトの主要な指示セットです。最新のコーディング規格、ワークフロールール、プロジェクト規約で常に最新の状態を保ってください。古いCLAUDE.mdは動作の不整合を招きます。プロジェクト構造やエージェント定義を変更した場合は、CLAUDE.mdを見直して更新してください。
ヒント2: コンテキストがいっぱいになったら/compactを使う — 長い会話はコンテキストウィンドウを消費します。Claudeが会話の最初の部分を「忘れ」始めたり、レスポンスの精度が落ちたりしたら、/compactと入力してください。これまでの会話履歴を要約し、重要なコンテキストを失わずに新しい対話のための空きを作ります。
ヒント3: パーミッションは慎重に許可する — Claude Code CLIはコマンドの実行やファイルの変更の前に許可を求めます。常に承認するのは魅力的ですが、rm、git push、その他の不可逆的な操作の前に、Claudeが何をしようとしているかを確認する時間を取ってください。この習慣で誤ったデータ損失を防げます。
ヒント4: 非対話モードを自動化に活用する — claude -p "プロンプト"を使用して、シェルスクリプト内でClaudeを非対話モードで実行します。これにより、品質チェックの実行、ドキュメントの生成、エージェントワークフローのトリガーなど、強力な自動化パターンが可能になります。シェルパイプとリダイレクションと組み合わせて、Claudeの出力を既存のツールチェーンに統合できます。
ヒント5: /costコマンドで使用量を監視する — Claude Code CLIは各セッションのトークン使用量を追跡します。いつでも/costと入力して、消費したトークン数と推定コストを確認できます。サブスクリプション制限内に収まるようにし、どの種類のタスクが最もリソースを消費するかを理解するのに役立ちます。セッションが高額になりそうな場合は、/clearで新しいセッションを開始することを検討してください。
ヘルプの取得: Claude Code CLIで問題が発生した場合は、公式ドキュメントはdocs.anthropic.com/en/docs/claude-codeにあります。Claude Code CLI内で/helpと入力すると利用可能なコマンドのクイックリファレンスが表示され、/doctorを実行すると一般的な設定問題を診断できます。
