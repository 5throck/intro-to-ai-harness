Explorar el contexto del repositorio con graft

graft es un grafo de contexto del repositorio construido de antemano. Cuando necesitas entender código, encontrar dónde hacer un cambio o rastrear el alcance de una edición, preguntarle primero a graft —en lugar de usar grep o abrir archivos a ciegas— te da una respuesta exacta con file:line usando muchos menos tokens.

Lo que cubre este apéndice
  • Qué es graft y por qué existe
  • Por qué recurrir a graft antes que a grep o leer archivos directamente
  • Los cinco comandos principales (ask, grep, skeleton, callers, map)
  • Usar graft como herramientas MCP (en entornos compatibles)
  • Un ejemplo de flujo de trabajo real
  • Actualizar el grafo tras cambios de código

1. Qué es graft

graft analiza un repositorio y genera un grafo de pequeños nodos en markdown —uno por archivo— que explica qué hace cada archivo, qué símbolos define y quién los llama. Este grafo vive en un directorio graft/ y se mantiene sincronizado con el código a través de git a medida que evoluciona el proyecto.

grep solo te dice dónde aparece una cadena de texto. graft es un mapa ya construido que te dice dónde se define un concepto, cómo se comporta y quién lo usa. Es la diferencia entre recorrer una ciudad nueva calle por calle y que alguien ya te entregue el mapa.

graft se puede usar de dos formas:

  • CLI — ejecutar graft <subcommand> directamente desde la terminal
  • Herramientas MCP — cuando el host (p. ej. Claude Code) expone herramientas como graft_find_code, graft_find_all, graft_trace_calls, graft_file_api y graft_repo_map, se consulta el mismo grafo mediante llamadas a herramientas
En este espacio de trabajo, un hook de SessionStart recuerda usar graft al inicio de cada sesión. En la práctica, eso significa: para cualquier tarea que implique entender o cambiar código, recurre primero a graft — esa es la regla base aquí.

2. Por qué graft en lugar de grep

Situación grep / leer archivos directamente graft
"¿Cómo funciona esta función?" Hay que adivinar qué archivos son relevantes y abrir varios graft ask devuelve resultados clasificados con fragmentos de código incluidos, al instante
"¿Quién llama a este símbolo?" Búsqueda de texto más verificación manual (muchos falsos positivos) graft callers lee las conexiones exactas de llamada directamente del grafo
"Encontrar cada aparición de este patrón" Posible con grep -rn, pero los resultados quedan desorganizados graft grep agrupa cada coincidencia por el símbolo que la contiene
"Quiero repasar toda la API de este archivo" Hay que leer el archivo completo (costoso en tokens) graft skeleton da cada firma a un costo ~10 veces menor
"Nuevo en este repositorio, ¿por dónde empiezo?" Leer el README y abrir carpetas una por una graft map resume clústeres de directorios, hubs y puntos calientes dentro de un presupuesto de tokens
El principio central: elige la única herramienta que se ajuste a la forma de la tarea y actúa según su respuesta. Llamar la misma herramienta una y otra vez, o repreguntar con palabras ligeramente distintas, desperdicia esfuerzo. Si una llamada no basta, cambia a la otra herramienta que se ajuste a la siguiente necesidad.

3. Comandos principales

3.1 graft map — orientación en un repositorio desconocido

Ejecútalo primero cuando seas nuevo en un repositorio. Sin llamadas a LLM (gratis), muestra la estructura de directorios, archivos hub y puntos calientes dentro de un presupuesto de tokens.

graft map

Nota: map es la respuesta por sí sola. Seguir con skeleton en cada subsistema que menciona es un uso excesivo.

3.2 graft ask — encuentra dónde entender o editar

Para preguntas como "¿cómo funciona esto?" o "¿dónde está definido esto?", devuelve resultados clasificados con fragmentos de código incluidos.

graft ask "cómo se comporta la lógica de reintento al fallar el inicio de sesión" --source
  • --source — muestra el código esencial de cada resultado (8 líneas por defecto)
  • --full — cuando 8 líneas no bastan, muestra la definición completa
  • Para entender o editar, el primer resultado ES la respuesta. Cita el file:line de covers: y edita directamente desde la salida de --source.
No uses ask para tareas exhaustivas como "encontrar cada aparición de este patrón". ask está clasificado, solo top-N — no garantiza cobertura total. Para búsquedas exhaustivas usa graft grep.

3.3 graft grep — búsqueda exhaustiva

Encuentra todas las apariciones de una cadena literal o símbolo, agrupadas por el símbolo que las contiene.

graft grep "processPayment"

Recurre a grep -rn sin procesar solo cuando necesites cubrir archivos no indexados.

3.4 graft skeleton — toda la API de un archivo de un vistazo

Muestra la firma y ubicación de cada definición sin leer el archivo completo, a un costo ~10 veces menor. Útil para repasar una superficie de API.

graft skeleton src/services/payment.ts

3.5 graft callers — rastrea relaciones de llamada exactas

Antes de cambiar un símbolo, averigua exactamente quién lo llama (o qué llama él). Ejecuta esto siempre antes de una refactorización o un cambio de nombre.

# Quién llama a este símbolo (por defecto)
graft callers formatCurrency

# Qué llama este símbolo
graft callers formatCurrency --direction out

# Alcance total (todos los archivos conectados)
graft callers formatCurrency --depth all
El error clásico en refactorizaciones, cambios de nombre o modificaciones multiarchivo es editar solo el archivo principal y detenerse ahí. Ejecuta primero graft callers <symbol> --depth all para mapear todos los archivos conectados, y luego edita.

4. Usarlo como herramientas MCP

En entornos host como Claude Code, se puede consultar el mismo grafo mediante llamadas a herramientas MCP en lugar del CLI. La correspondencia es:

Comando CLI Herramienta MCP
graft askgraft_find_code
graft grepgraft_find_all
graft callersgraft_trace_calls
graft skeletongraft_file_api
graft mapgraft_repo_map
Información de bordes —quién llama a qué— vive solo en el grafo, no en los archivos markdown de los nodos. graft callers / graft_trace_calls es la única forma de leerlos.

5. Flujo de trabajo real

Paso 1: ¿Repositorio nuevo? Empieza con map

Si no conoces un proyecto, ejecuta graft map primero para obtener la visión general.

Paso 2: Elige la herramienta que se ajusta a la tarea

Entender o editar → ask --source. Búsqueda exhaustiva → grep. Repasar una API → skeleton. Mapear el alcance → callers.

Paso 3: Edita directamente desde el resultado

Cita el file:line y el fragmento devuelto por ask --source y edita directamente desde ahí. Si un tramo aparece truncado (+N more lines), abre el archivo en ese rango exacto para confirmarlo antes de finalizar.

Paso 4: Actualiza el grafo tras grandes cambios

Después de un cambio de código significativo, ejecuta graft build para poner el grafo al día.

6. Actualizar el grafo (graft build)

El grafo de graft se genera de forma determinista y se puede actualizar de forma gratuita, sin necesidad de una clave de API de LLM. Después de un cambio de código grande —archivos nuevos, una refactorización mayor— reconstruye el grafo para mantenerlo al día.

graft build
No es necesario ejecutar build después de cada pequeña edición. El grafo está bajo control de versiones junto con git; actualizarlo una vez tras un bloque de trabajo significativo es suficiente.
En resumen: entender o editar → graft ask, encontrar todo → graft grep, repasar una API → graft skeleton, rastrear el alcance → graft callers, repositorio nuevo → graft map. Solo necesitas recordar estos cinco.
