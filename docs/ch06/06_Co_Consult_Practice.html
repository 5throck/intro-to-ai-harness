co-consult: AI 컨설팅 실습

co-consult는 AI 에이전트 팀이 컨설팅 프로젝트를 수행하는 시스템입니다. 이 장에서는 co-consult의 구조를 이해하고, Claude Desktop App을 통해 실제로 간단한 시장 분석 프로젝트를 진행해봅니다.

co-consult란

정의

co-consult는 AI 에이전트 팀이 전략 컨설팅 프로젝트를 수행하는 시스템입니다. 5장에서 살펴본 ai-workspace-standards의 variant 중 하나로, 다중 AI 에이전트가 협력하여 시장 분석, 경쟁사 분석, 진입 전략 수립, 비즈니스 모델 검토 등 전략 컨설팅 업무를 자동화합니다.

위치: ai-workspace-standards 안의 templates/co-consult/ — bun scripts/new-project.ts "<이름>" --variant co-consult로 나만의 사본을 스캐폴딩할 수 있습니다.

어떤 문제를 해결하는가?

전략 컨설팅은 다음과 같은 단계를 거쳐야 합니다. co-consult는 이 전체 과정을 AI 에이전트 팀이 수행합니다.

  • 시장 분석 — 시장 규모, 성장률, 트렌드 파악
  • 경쟁사 분석 — 주요 경쟁사의 강약점, 시장 점유율 비교
  • 진입 전략 — 신규 시장 진출 방법, 타이밍, 채널
  • 비즈니스 모델 — 수익 구조, 가치 제안, 핵심 자원 분석
  • 기술 동향 — 관련 기술 트렌드와 도입 가능성
초보자 비유: co-consult는 가상의 "컨설팅 회사"입니다. PM(프로젝트 매니저)이 파트너(사용자)와 미팅하여 요구사항을 듣고, 전문가 에이전트들이 각자 맡은 분석을 수행합니다. 실제 컨설팅 펌에서 시니어 컨설턴트가 주니어들을 이끄는 것과 비슷한 구조입니다.

co-deck와의 차이

co-deck이 프레젠테이션(슬라이드) 제작에 특화되어 있다면, co-consult는 전략 분석과 보고서 작성에 특화되어 있습니다. 두 시스템 모두 ai-workspace-standards를 기반으로 하지만, 목적과 에이전트 구성이 다릅니다.

co-deck

  • 프레젠테이션 슬라이드 제작
  • research, storyline, html-build, pdf-export 등
  • 11-Stage 파이프라인
  • 산출물: HTML 슬라이드 + PDF

co-consult

  • 전략 컨설팅 분석 및 보고서
  • research, data-analyst, market-analyst, strategy 등
  • 7-Phase 파이프라인
  • 산출물: 분석 보고서 HTML + PDF

시스템 아키텍처

에이전트 구성

co-consult는 PM 에이전트 1명과 11개 전문 에이전트로 구성됩니다. PM이 중심에서 전체 프로젝트를 조율하고, 전문 에이전트들이 각자의 영역에서 작업을 수행합니다.

전문 에이전트 역할

각 전문 에이전트의 역할을 요약하면 다음과 같습니다.

에이전트 역할 설명
research 리서치 전문가 웹에서 관련 자료와 데이터를 수집하여 research_notes.md에 정리합니다
source-verifier 소스 검증자 수집된 출처의 신뢰성을 검증하고 Trust Score를 산출합니다 (선택적)
data-analyst 데이터 분석가 수치 데이터를 분석하고 시각화 자료를 생성합니다
market-analyst 시장 분석가 시장 규모, 성장률, 트렌드 등 시장 환경을 분석합니다
strategy 전략 컨설턴트 분석 결과를 바탕으로 전략 제안과 실행 로드맵을 작성합니다
tech-analyst 기술 분석가 관련 기술 동향과 도입 가능성을 분석합니다
storyline 스토리라이너 보고서의 전체 구조와 내러티브를 설계합니다
html-build HTML 빌더 분석 내용을 HTML 형식의 보고서로 변환합니다
pdf-export PDF 익스포터 보고서를 PDF 형식으로 내보냅니다
version 버전 관리자 파일 수정 전 자동 백업을 수행합니다
auditor 품질 감사자 최종 산출물의 품질과 일관성을 검토합니다
PM 에이전트는 위 전문 에이전트를 직접 실행하지 않습니다. PM은 사용자의 요청을 분석하고, 각 전문 에이전트에게 작업을 지시(디스패치)하는 오케스트레이터 역할만 수행합니다. 4장의 PM Gateway 섹션을 참조하세요.

7-Phase 워크플로우

co-consult는 7개의 Phase로 구성된 워크플로우를 따라 컨설팅 프로젝트를 진행합니다. 각 Phase에서 특정 에이전트가 담당하며, 정해진 산출물을 출력합니다.

Phase별 핵심 산출물

  1. Phase 0 — 프로젝트 시작
    PM이 사용자와 미팅하여 프로젝트의 주제, 범위, 대상 시장, 일정을 확정합니다. 이 단계에서 consult-profile.md와 project_state.json이 생성됩니다.
  2. Phase 1 — 리서치
    research 에이전트가 웹 검색을 통해 관련 자료, 통계, 보고서를 수집합니다. 산출물은 research_notes.md로, 전체 프로젝트의 정보 기반이 됩니다.
  3. Phase 1.5 — 소스 검증 (선택적)
    source-verifier 에이전트가 수집된 출처의 URL 접근성과 내용 일치 여부를 검증합니다. Trust Score를 산출하며, 70% 미만이면 프로젝트가 일시 중단됩니다.
  4. Phase 2-3 — 분석 및 전략 수립
    data-analyst, market-analyst, strategy, tech-analyst 등이 리서치 결과를 바탕으로 각 분야의 분석을 수행하고 전략을 제안합니다. storyline 에이전트가 보고서 구조를 설계합니다.
  5. Phase 4 — 보고서 작성
    html-build 에이전트가 분석 결과를 HTML 형식의 보고서로 변환합니다. 차트, 다이어그램, 표가 포함된 완성된 형태의 보고서가 생성됩니다.
  6. Phase 5 — 품질 검토
    auditor 에이전트가 보고서의 품질, 일관성, 데이터 정확성을 검토합니다. 문제점이 발견되면 수정 요청을 보냅니다.
  7. Phase 6 — 최종화
    pdf-export 에이전트가 최종 보고서를 PDF로 변환하여 deliverables/reports/에 저장합니다. 프로젝트 상태를 완료로 업데이트합니다.
사용자는 Phase 0에서 요구사항을 정의하고, Gate 2 (Phase 2-3 완료 후)와 Gate 5 (Phase 5 완료 후)에서 승인합니다. 나머지 Phase는 PM이 에이전트를 자동으로 디스패치하여 진행합니다. Gate 승인 없이는 다음 Phase로 넘어가지 않으므로, 중간에 방향 수정이 가능합니다.

PM에게 말하는 법

co-consult를 사용하려면 Claude Desktop App에서 co-consult 프로젝트를 열고 PM 에이전트에게 요청을 보내야 합니다. 효과적인 요청은 프로젝트의 품질을 크게 높입니다.

요청의 4가지 핵심 요소

좋은 요청에는 다음 네 가지가 포함되어 있습니다.

  1. 목적 (Purpose) — 무엇을 분석하고 싶은가?
  2. 범위 (Scope) — 어느 시장, 어느 영역을 대상으로 하는가?
  3. 대상 (Target) — 누구를 위한 분석인가? (우리 회사, 경쟁사 등)
  4. 일정 (Timeline) — 언제까지 결과가 필요한가?

요청 예시

예시 1: 시장 분석
"한국의 배달 앱 시장을 분석해줘. 경쟁사 비교와 진입 기회를 중점적으로. 2주 내 완료."
예시 2: 비즈니스 모델 검토
"우리 스타트업의 SaaS 비즈니스 모델을 검토해줘. 타겟 시장은 일본 B2B 기업. 가격 전략과 확장 가능성에 대해."
예시 3: 기술 도입 검토
"우리 회사에 AI 챗봇을 도입하는 것을 검토해줘. 교육 업계 대상. 비용, 기술 스택, 경쟁사 사례를 포함해줘."

좋은 요청 vs 아쉬운 요청

좋은 요청

  • 목적이 명확함: "시장 분석해줘"
  • 범위가 구체적임: "한국 배달 앱 시장"
  • 중점 영역 명시: "경쟁사 비교와 진입 기회"
  • 일정이 있음: "2주 내"
  • PM이 바로 에이전트를 디스패치 가능

아쉬운 요청

  • 목적이 모호함: "뭐 좀 분석해줘"
  • 범위가 없음: 시장? 기술? 경쟁사?
  • 중점 영역 불명확: "전부 다"
  • 일정이 없음: 기한이 정해지지 않음
  • PM이 사용자에게 질문해야 함
처음에는 간단한 주제로 시작해보세요. 복잡한 프로젝트는 경험이 쌓인 후에 도전하세요. "한국 카페 시장의 주요 트렌드를 분석해줘" 정도의 간단한 요청으로 co-consult의 동작 방식을 익히는 것을 추천합니다.

팀 구성 패턴

co-consult는 프로젝트의 규모와 복잡도에 따라 4가지 팀 구성 패턴을 제공합니다. PM이 프로젝트 요구사항을 분석하여 가장 적합한 패턴을 선택합니다.

4가지 팀 구성 패턴

초보자는 Quick Assessment나 Standard 패턴을 추천합니다. Quick Assessment는 1-2일 안에 결과를 볼 수 있어 co-consult의 동작 방식을 이해하는 데 좋습니다. Standard 패턴으로 진행하면서 점차 복잡한 프로젝트에 도전해보세요.

실습: 간단한 시장 분석

이 실습에서는 co-consult를 사용하여 간단한 시장 분석 프로젝트를 수행해봅니다. Quick Assessment 패턴으로 진행하며, 한국 카페 시장의 주요 트렌드를 분석하는 것을 목표로 합니다.

실습 목표

  • co-consult 저장소를 클론하고 프로젝트를 설정합니다
  • Claude Desktop App에서 PM 에이전트에게 요청을 보냅니다
  • 7-Phase 워크플로우의 진행 과정을 관찰합니다
  • Gate 승인 과정을 경험합니다
  • 최종 산출물을 확인합니다

사전 준비

3장에서 설치한 도구가 정상 동작하는지 확인하세요.

  1. Claude Desktop App — Claude AI 대화가 가능한 상태여야 합니다
  2. Git — 저장소를 클론할 수 있어야 합니다
  3. 텍스트 편집기 — VS Code 등 산출물을 열어볼 수 있는 편집기

실습 단계

  1. 워크스페이스 클론 및 프로젝트 스캐폴딩
    앞선 장에서 아직 워크스페이스를 클론하지 않았다면 먼저 클론한 뒤, new-project.ts로 co-consult variant에서 새 프로젝트를 스캐폴딩합니다.
    git clone https://github.com/5throck/ai-workspace-standards.git
    cd ai-workspace-standards
    bun scripts/new-project.ts "co-consult" --variant co-consult
    이 명령은 Projects/co-consult/를 독립된 Git 저장소로 생성하고, co-consult variant의 에이전트·스킬·설정을 이미 복사해 넣습니다.
  2. Claude Desktop App에서 프로젝트 열기
    Claude Desktop App을 실행하고, Projects/co-consult/ 폴더를 프로젝트로 엽니다. Claude에게 다음과 같이 말하여 PM을 시작합니다.
    "새 프로젝트를 시작할게요."
    PM이 Stage 0(프로젝트 시작) 단계로 진입하여 주제, 범위, 일정을 물어봅니다.
  3. PM에게 요청하기
    PM의 질문에 답하며 프로젝트를 설정합니다. 다음과 같이 응답해보세요.
    "한국 카페 시장의 주요 트렌드를 분석해줘. 프랜치아이즈 카페와 독립 카페의 비교를 중점적으로. 빠른 평가(Quick Assessment)로 부탁해."
    PM이 요청을 분석하고, Quick Assessment 패턴에 맞는 에이전트 구성을 안내합니다.
  4. Phase 진행 관찰
    PM이 자동으로 에이전트를 디스패치합니다. 화면에서 다음과 같은 과정을 관찰할 수 있습니다.
    • Phase 1: research 에이전트가 "한국 카페 시장 트렌드"를 검색하며 research_notes.md를 작성합니다
    • Phase 2-3: market-analyst 에이전트가 시장 데이터를 분석하고, strategy 에이전트가 핵심 인사이트를 도출합니다
    • Phase 4: html-build 에이전트가 분석 결과를 보고서 HTML로 변환합니다
    • Phase 5: auditor 에이전트가 보고서 품질을 검토합니다
    각 Phase가 완료될 때마다 PM이 진행 상황을 알려줍니다. 이때 project_state.json 파일이 자동으로 업데이트됩니다.
  5. Gate 승인하기
    워크플로우 중 두 번의 Gate에서 PM이 승인을 요청합니다.
    • Gate 2 (Phase 2-3 완료 후): 분석 방향과 인사이트가 적절한지 확인합니다. 수정이 필요하면 이 시점에서 방향을 조정합니다.
    • Gate 5 (Phase 5 완료 후): 최종 보고서의 품질을 확인하고 PDF 출력을 승인합니다.
    Gate에서는 다음과 같이 응답하면 됩니다.
    "분석 내용 확인했습니다. 다음 단계로 진행해줘."
    또는 수정이 필요하면 구체적으로 알려주세요.
    "경쟁사 분석 부분에 배민의 배달 카페 데이터도 추가해줘."
  6. 산출물 확인
    모든 Phase가 완료되면 deliverables/reports/ 폴더에서 산출물을 확인할 수 있습니다. 구체적인 확인 방법은 다음 섹션에서 설명합니다.
실습 중 오류가 발생하면 3장의 문제 해결 섹션을 참조하세요. Claude Desktop App의 응답이 없거나, 에이전트 디스패치 오류가 발생하면 Claude를 재시작하거나 프로젝트 폴더를 다시 열어보세요.
주의: co-consult의 에이전트들은 Claude API를 통해 동작합니다. 실습 중 Claude의 응답 속도가 느려지거나 시간 초과가 발생할 수 있습니다. 복잡한 분석은 시간이 더 오래 걸릴 수 있으며, 이는 정상적인 동작입니다.

산출물 확인

co-consult 프로젝트가 완료되면 여러 가지 산출물이 생성됩니다. 이 섹션에서는 각 산출물의 위치와 확인 방법을 설명합니다.

산출물 위치

모든 산출물은 deliverables/reports/ 디렉토리에 저장됩니다. 프로젝트 루트에서 다음 경로로 접근할 수 있습니다.

Projects/co-consult/deliverables/reports/

주요 산출물

파일 설명 생성 Phase
research_notes.md 웹 검색으로 수집한 자료, 통계, 출처의 정리 Phase 1
source-verification.md 출처 신뢰성 검증 결과와 Trust Score (선택적) Phase 1.5
storyline.md 보고서의 전체 구조와 섹션별 내러티브 설계 Phase 2-3
analysis_*.md 분석 전문가들의 개별 분석 결과 Phase 2-3
report.html HTML 형식의 최종 분석 보고서 Phase 4
report.pdf PDF 형식의 최종 분석 보고서 Phase 6

산출물 확인 방법

  1. 프로젝트 폴더 열기
    터미널에서 Projects/co-consult/deliverables/reports/ 디렉토리로 이동합니다.
    cd Projects/co-consult/deliverables/reports/
    ls
  2. research_notes.md 확인
    리서치 결과를 확인합니다. 수집된 출처, 핵심 데이터, 참고 링크가 포함되어 있습니다.
    cat research_notes.md
    또는 VS Code에서 열어보세요.
  3. 보고서 HTML 확인
    report.html 파일을 브라우저에서 열어 완성된 보고서를 확인합니다. 차트, 표, 다이어그램이 포함된 인터랙티브한 형태입니다.
    open report.html
  4. PDF 확인
    report.pdf 파일을 열어 인쇄용 보고서를 확인합니다. 공유나 보관에 적합한 형식입니다.
  5. project_state.json 확인
    프로젝트의 전체 진행 상태를 확인할 수 있습니다. 각 Phase의 완료 여부와 Gate 승인 상태가 기록되어 있습니다.
    cat project_state.json

파일 구조 요약

co-consult/
├── agents/                    # 에이전트 정의 파일
│   ├── pm.md
│   ├── research.md
│   ├── market-analyst.md
│   ├── strategy.md
│   └── ...
├── deliverables/
│   └── reports/
│       ├── research_notes.md   # Phase 1 산출물
│       ├── storyline.md        # Phase 2-3 산출물
│       ├── report.html         # Phase 4 산출물
│       └── report.pdf          # Phase 6 산출물
├── project_state.json          # 프로젝트 진행 상태
├── consult-profile.md          # 프로젝트 설정
└── memory/                     # 세션 기록
    └── YYYY-MM-DD.md
산출물은 Claude Desktop App의 Artifacts에서도 확인할 수 있습니다. Claude가 생성한 파일이나 다이어그램은 대화 화면에서 직접 미리보기 가능합니다. 또한 project_state.json을 통해 현재 프로젝트가 어느 Phase에 있는지 실시간으로 확인할 수 있습니다.
산출물을 활용하는 방법: 완성된 보고서는 팀원들과 공유하거나, 프레젠테이션의 자료로 활용할 수 있습니다. co-deck(7장)과 함께 사용하면 분석 보고서를 기반으로 한 프레젠테이션을 만들 수 있습니다.
