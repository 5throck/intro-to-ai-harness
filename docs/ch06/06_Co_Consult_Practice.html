co-consult: AI 컨설팅 실습

co-consult는 AI 에이전트 팀이 컨설팅 프로젝트를 수행하는 시스템입니다. 이 장에서는 co-consult의 구조를 이해하고, Claude Desktop App을 통해 실제로 간단한 시장 분석 프로젝트를 진행해봅니다.

이 장에서 다루는 것
  • co-consult 시스템 소개와 아키텍처
  • PM이 전문가를 디스패치하는 방식 이해 (고정 파이프라인 없음)
  • PM 에이전트에게 요청하는 방법
  • 4가지 팀 구성 패턴
  • 실습: 간단한 시장 분석 프로젝트
  • 산출물 확인 방법

co-consult란

정의

co-consult는 AI 에이전트 팀이 전략 컨설팅 프로젝트를 수행하는 시스템입니다. 5장에서 살펴본 ai-workspace-standards의 variant 중 하나로, 다중 AI 에이전트가 협력하여 시장 분석, 경쟁사 분석, 진입 전략 수립, 비즈니스 모델 검토 등 전략 컨설팅 업무를 자동화합니다.

위치: ai-workspace-standards 안의 templates/co-consult/ — bun scripts/new-project.ts "<이름>" --variant co-consult로 나만의 사본을 스캐폴딩할 수 있습니다.

어떤 문제를 해결하는가?

전략 컨설팅은 다음과 같은 단계를 거쳐야 합니다. co-consult는 이 전체 과정을 AI 에이전트 팀이 수행합니다.

  • 시장 분석 — 시장 규모, 성장률, 트렌드 파악
  • 경쟁사 분석 — 주요 경쟁사의 강약점, 시장 점유율 비교
  • 진입 전략 — 신규 시장 진출 방법, 타이밍, 채널
  • 비즈니스 모델 — 수익 구조, 가치 제안, 핵심 자원 분석
  • 기술 동향 — 관련 기술 트렌드와 도입 가능성
초보자 비유: co-consult는 가상의 "컨설팅 회사"입니다. PM(프로젝트 매니저)이 파트너(사용자)와 미팅하여 요구사항을 듣고, 전문가 에이전트들이 각자 맡은 분석을 수행합니다. 실제 컨설팅 펌에서 시니어 컨설턴트가 주니어들을 이끄는 것과 비슷한 구조입니다.

co-deck와의 차이

co-deck이 프레젠테이션(슬라이드) 제작에 특화되어 있다면, co-consult는 전략 분석과 보고서 작성에 특화되어 있습니다. 두 시스템 모두 ai-workspace-standards를 기반으로 하지만, 목적과 에이전트 구성이 다릅니다.

co-deck

  • 프레젠테이션 슬라이드 제작
  • research, storyline, html-build, pdf-export 등
  • 11-Stage 파이프라인
  • 산출물: HTML 슬라이드 + PDF

co-consult

  • 전략 컨설팅 분석 및 보고서
  • strategy-analyst, industry-expert, sme, communications-lead 등
  • PM이 디스패치, 고정 파이프라인 없음
  • 산출물: 분석 보고서 HTML + PDF

시스템 아키텍처

에이전트 구성

co-consult는 PM 에이전트(Engagement Leader) 1명과 10개 전문 에이전트로 구성됩니다. PM이 중심에서 전체 인게이지먼트를 조율하고, 전문 에이전트들이 각자의 영역에서 작업을 수행합니다.

전문 에이전트 역할

각 전문 에이전트의 역할을 요약하면 다음과 같습니다. 고정된 파이프라인과 달리, 이 에이전트들은 인게이지먼트 중 필요한 시점에 언제든 디스패치될 수 있습니다.

에이전트 역할 설명
change-management-partner 체인지 매니지먼트 파트너 조직 변화 관리, 조직문화 전략, 이해관계자 얼라인먼트
strategy-analyst 전략 분석가 시장 분석, 경쟁사 리서치, 재무 모델링
industry-expert 산업 전문가 산업별 인사이트, 경쟁 역학, 규제 환경
sme 기능 전문가 (Subject Matter Expert) HR, 재무, 운영, 마케팅 등 기능별 전문성
communications-lead 커뮤니케이션 리드 클라이언트 커뮤니케이션, 프레젠테이션, 전략 내러티브
solutions-architect 솔루션 아키텍트 기술 솔루션 설계, 시스템 아키텍처, 실행 로드맵
workstream-lead 워크스트림 리드 워크스트림 관리, 팀 조율, 진행 상황 추적
delivery-manager 딜리버리 매니저 프로젝트 딜리버리, 운영 조율, 리소스 배분
technology-specialist 기술 전문가 협업 플랫폼, 워크플로우 자동화, 디지털 전환
data-analyst 데이터 분석가 통계 분석, 데이터 모델링, 시각화
PM 에이전트는 위 전문 에이전트를 직접 실행하지 않습니다. PM은 사용자의 요청을 분석하고, 인게이지먼트가 요구하는 바에 따라 각 전문 에이전트에게 작업을 지시(디스패치)하는 오케스트레이터 역할만 수행합니다. 4장의 PM Gateway 섹션을 참조하세요.

PM의 전문가 디스패치 방식

co-deck의 고정된 11단계 파이프라인과 달리, co-consult에는 고정된 Phase 순서가 없습니다. PM(Engagement Leader)이 사용자의 요청을 분석하여 어떤 전문가가 필요한지 판단하고 직접 디스패치합니다 — 번호가 매겨진 Phase와 Gate를 순서대로 통과하는 대신, 인게이지먼트의 질문과 산출물이 요구하는 만큼 전문가를 추가로 투입합니다.

실제 인게이지먼트가 진행되는 방식

  1. 킥오프
    PM이 사용자와 대화하여 주제, 범위, 대상 시장, 일정을 파악합니다. 별도의 "Phase 0" 형식은 없으며, PM이 이 맥락을 파악한 후 인게이지먼트에 어떤 전문가가 필요한지 판단합니다.
  2. 질문이 생길 때마다 전문가 디스패치
    PM이 관련된 전문가를 활성화합니다 — 예를 들어 시장·경쟁사 리서치에는 strategy-analyst, 산업별 맥락에는 industry-expert, 기능별 심층 분석에는 sme를 투입합니다. 정해진 순서는 없으며, PM은 여러 전문가를 동시에 디스패치하거나 중간에 공백이 발견되면 추가로 투입할 수 있습니다.
  3. 종합 및 보고서 작성
    충분한 분석이 모이면 PM은 보통 communications-lead를 투입해 내러티브를 구성하고 클라이언트에게 전달할 자료를 만듭니다. 실행 계획이 필요한 인게이지먼트라면 solutions-architect나 workstream-lead도 투입합니다.
  4. 딜리버리 및 마무리
    대규모 인게이지먼트에서는 delivery-manager와 workstream-lead가 실행을 조율하고 진행 상황을 추적합니다. PM은 사용자와 함께 산출물이 완성되었다고 판단되는 시점에 인게이지먼트를 종료합니다.
사용자는 킥오프에서 요구사항을 정의하고, PM이 확인을 요청할 때마다 산출물을 검토합니다. 고정된 파이프라인이 없으므로, 체크포인트는 하드코딩된 번호가 매겨진 Gate가 아니라 — 예를 들어 첫 리서치 라운드 이후, 또는 보고서 최종화 직전처럼 — PM이 유용하다고 판단하는 시점에 자연스럽게 발생합니다. 이 체크포인트마다 인게이지먼트의 방향을 조정할 수 있습니다.

PM에게 말하는 법

co-consult를 사용하려면 Claude Desktop App에서 co-consult 프로젝트를 열고 PM 에이전트에게 요청을 보내야 합니다. 효과적인 요청은 프로젝트의 품질을 크게 높입니다.

요청의 4가지 핵심 요소

좋은 요청에는 다음 네 가지가 포함되어 있습니다.

  1. 목적 (Purpose) — 무엇을 분석하고 싶은가?
  2. 범위 (Scope) — 어느 시장, 어느 영역을 대상으로 하는가?
  3. 대상 (Target) — 누구를 위한 분석인가? (우리 회사, 경쟁사 등)
  4. 일정 (Timeline) — 언제까지 결과가 필요한가?

요청 예시

예시 1: 시장 분석
"한국의 배달 앱 시장을 분석해줘. 경쟁사 비교와 진입 기회를 중점적으로. 2주 내 완료."
예시 2: 비즈니스 모델 검토
"우리 스타트업의 SaaS 비즈니스 모델을 검토해줘. 타겟 시장은 일본 B2B 기업. 가격 전략과 확장 가능성에 대해."
예시 3: 기술 도입 검토
"우리 회사에 AI 챗봇을 도입하는 것을 검토해줘. 교육 업계 대상. 비용, 기술 스택, 경쟁사 사례를 포함해줘."

좋은 요청 vs 아쉬운 요청

좋은 요청

  • 목적이 명확함: "시장 분석해줘"
  • 범위가 구체적임: "한국 배달 앱 시장"
  • 중점 영역 명시: "경쟁사 비교와 진입 기회"
  • 일정이 있음: "2주 내"
  • PM이 바로 에이전트를 디스패치 가능

아쉬운 요청

  • 목적이 모호함: "뭐 좀 분석해줘"
  • 범위가 없음: 시장? 기술? 경쟁사?
  • 중점 영역 불명확: "전부 다"
  • 일정이 없음: 기한이 정해지지 않음
  • PM이 사용자에게 질문해야 함
처음에는 간단한 주제로 시작해보세요. 복잡한 프로젝트는 경험이 쌓인 후에 도전하세요. "한국 카페 시장의 주요 트렌드를 분석해줘" 정도의 간단한 요청으로 co-consult의 동작 방식을 익히는 것을 추천합니다.

팀 구성 패턴

co-consult는 프로젝트의 규모와 복잡도에 따라 4가지 팀 구성 패턴을 제공합니다. PM이 프로젝트 요구사항을 분석하여 가장 적합한 패턴을 선택합니다.

4가지 팀 구성 패턴

초보자는 Quick Assessment나 Standard 패턴을 추천합니다. Quick Assessment는 1-2일 안에 결과를 볼 수 있어 co-consult의 동작 방식을 이해하는 데 좋습니다. Standard 패턴으로 진행하면서 점차 복잡한 프로젝트에 도전해보세요.

실습: 간단한 시장 분석

이 실습에서는 co-consult를 사용하여 간단한 시장 분석 프로젝트를 수행해봅니다. Quick Assessment 패턴으로 진행하며, 한국 카페 시장의 주요 트렌드를 분석하는 것을 목표로 합니다.

실습 목표

  • co-consult 저장소를 클론하고 프로젝트를 설정합니다
  • Claude Desktop App에서 PM 에이전트에게 요청을 보냅니다
  • PM이 필요에 따라 전문가를 디스패치하는 과정을 관찰합니다
  • 진행 중 산출물을 검토하고 피드백을 줍니다
  • 최종 산출물을 확인합니다

사전 준비

3장에서 설치한 도구가 정상 동작하는지 확인하세요.

  1. Claude Desktop App — Claude AI 대화가 가능한 상태여야 합니다
  2. Git — 저장소를 클론할 수 있어야 합니다
  3. 텍스트 편집기 — VS Code 등 산출물을 열어볼 수 있는 편집기

실습 단계

  1. 워크스페이스 클론 및 프로젝트 스캐폴딩
    앞선 장에서 아직 워크스페이스를 클론하지 않았다면 먼저 클론한 뒤, new-project.ts로 co-consult variant에서 새 프로젝트를 스캐폴딩합니다.
    git clone https://github.com/5throck/ai-workspace-standards.git
    cd ai-workspace-standards
    bun scripts/new-project.ts "co-consult" --variant co-consult
    이 명령은 Projects/co-consult/를 독립된 Git 저장소로 생성하고, co-consult variant의 에이전트·스킬·설정을 이미 복사해 넣습니다.
  2. Claude Desktop App에서 프로젝트 열기
    Claude Desktop App을 실행하고, Projects/co-consult/ 폴더를 프로젝트로 엽니다. Claude에게 다음과 같이 말하여 PM을 시작합니다.
    "새 프로젝트를 시작할게요."
    PM이 킥오프 대화를 시작하여 주제, 범위, 일정을 물어봅니다.
  3. PM에게 요청하기
    PM의 질문에 답하며 인게이지먼트를 설정합니다. 다음과 같이 응답해보세요.
    "한국 카페 시장의 주요 트렌드를 분석해줘. 프랜차이즈 카페와 독립 카페의 비교를 중점적으로. 간단한 평가 수준으로 부탁해."
    PM이 요청을 분석하고, Quick Assessment 규모의 인게이지먼트에 맞게 어떤 전문가를 디스패치할지 판단합니다.
  4. 전문가 디스패치 관찰
    PM이 직접 전문가를 디스패치합니다 — 고정된 Phase 순서는 없습니다. 화면에서 대략 다음과 같은 과정을 관찰할 수 있습니다.
    • strategy-analyst 에이전트가 "한국 카페 시장 트렌드"를 리서치하며 시장 규모, 성장률, 경쟁 현황이 담긴 분석 문서를 작성합니다
    • 요청 내용에 따라 PM이 산업별 맥락을 위해 industry-expert도 추가로 투입할 수 있습니다
    • communications-lead 에이전트가 분석 결과를 클라이언트에게 전달할 보고서 형태로 다듬습니다
    각 전문가가 작업을 마칠 때마다 PM이 진행 상황을 알려줍니다. 이때 project_state.json 파일이 자동으로 업데이트됩니다.
  5. 진행 상황 검토 및 피드백
    고정된 파이프라인이 없으므로, PM은 검토할 만한 내용이 생겼다고 판단할 때마다 확인을 요청합니다 — 보통 첫 분석 라운드 이후, 그리고 보고서를 최종화하기 전에 한 번 더 확인합니다.
    • 분석 이후: 분석 방향과 인사이트가 적절한지 확인합니다. 수정이 필요하면 이 시점에서 방향을 조정합니다.
    • 최종화 전: 최종 보고서의 품질을 확인하고 완성된 산출물로 넘어가도 좋을지 승인합니다.
    이 시점에서는 다음과 같이 응답하면 됩니다.
    "분석 내용 확인했습니다. 다음 단계로 진행해줘."
    또는 수정이 필요하면 구체적으로 알려주세요.
    "경쟁사 분석 부분에 배민의 배달 카페 데이터도 추가해줘."
  6. 산출물 확인
    PM이 산출물이 완성되었다고 판단하면 deliverables/reports/ 폴더에서 확인할 수 있습니다. 구체적인 확인 방법은 다음 섹션에서 설명합니다.
실습 중 오류가 발생하면 3장의 문제 해결 섹션을 참조하세요. Claude Desktop App의 응답이 없거나, 에이전트 디스패치 오류가 발생하면 Claude를 재시작하거나 프로젝트 폴더를 다시 열어보세요.
주의: co-consult의 에이전트들은 Claude API를 통해 동작합니다. 실습 중 Claude의 응답 속도가 느려지거나 시간 초과가 발생할 수 있습니다. 복잡한 분석은 시간이 더 오래 걸릴 수 있으며, 이는 정상적인 동작입니다.

산출물 확인

co-consult 프로젝트가 완료되면 여러 가지 산출물이 생성됩니다. 이 섹션에서는 각 산출물의 위치와 확인 방법을 설명합니다.

산출물 위치

모든 산출물은 deliverables/reports/ 디렉토리에 저장됩니다. 프로젝트 루트에서 다음 경로로 접근할 수 있습니다.

Projects/co-consult/deliverables/reports/

주요 산출물

파일 설명 생성 주체
findings_*.md 리서치 결과, 시장/경쟁사 데이터, 분석 과정에서 수집한 출처 strategy-analyst / industry-expert
analysis_*.md 참여한 다른 전문 에이전트의 개별 분석 결과 (예: sme, data-analyst) 관련 전문가
narrative_framework.md 보고서의 전체 구조와 섹션별 내러티브 설계 communications-lead
report.html HTML 형식의 최종 분석 보고서 communications-lead
report.pdf PDF 형식의 최종 분석 보고서 PM (최종화)

산출물 확인 방법

  1. 프로젝트 폴더 열기
    터미널에서 Projects/co-consult/deliverables/reports/ 디렉토리로 이동합니다.
    cd Projects/co-consult/deliverables/reports/
    ls
  2. findings 문서 확인
    리서치 결과를 확인합니다. 수집된 출처, 핵심 데이터, 참고 링크가 포함되어 있습니다.
    cat findings_market.md
    또는 VS Code에서 열어보세요.
  3. 보고서 HTML 확인
    report.html 파일을 브라우저에서 열어 완성된 보고서를 확인합니다. 차트, 표, 다이어그램이 포함된 인터랙티브한 형태입니다.
    open report.html
  4. PDF 확인
    report.pdf 파일을 열어 인쇄용 보고서를 확인합니다. 공유나 보관에 적합한 형식입니다.
  5. project_state.json 확인
    프로젝트의 전체 진행 상태를 확인할 수 있습니다. 어떤 전문가가 디스패치되었는지, 무엇을 산출했는지, PM이 각 검토 시점에서 사용자와 확인했는지가 기록되어 있습니다.
    cat project_state.json

파일 구조 요약

co-consult/
├── agents/                    # 에이전트 정의 파일
│   ├── pm.md
│   ├── strategy-analyst.md
│   ├── industry-expert.md
│   ├── communications-lead.md
│   └── ...
├── deliverables/
│   └── reports/
│       ├── findings_market.md     # strategy-analyst / industry-expert 산출물
│       ├── narrative_framework.md # communications-lead 산출물
│       ├── report.html            # communications-lead 산출물
│       └── report.pdf             # PM 최종화 산출물
├── project_state.json          # 프로젝트 진행 상태
├── consult-profile.md          # 프로젝트 설정
└── memory/                     # 세션 기록
    └── YYYY-MM-DD.md
산출물은 Claude Desktop App의 Artifacts에서도 확인할 수 있습니다. Claude가 생성한 파일이나 다이어그램은 대화 화면에서 직접 미리보기 가능합니다. 또한 project_state.json을 통해 현재 프로젝트가 어느 Phase에 있는지 실시간으로 확인할 수 있습니다.
산출물을 활용하는 방법: 완성된 보고서는 팀원들과 공유하거나, 프레젠테이션의 자료로 활용할 수 있습니다. co-deck(7장)과 함께 사용하면 분석 보고서를 기반으로 한 프레젠테이션을 만들 수 있습니다.
