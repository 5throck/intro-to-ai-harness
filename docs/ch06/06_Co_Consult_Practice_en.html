co-consult: AI Consulting in Practice

co-consult is a system where AI agent teams execute consulting projects. In this chapter, you'll understand co-consult's structure and run a simple market analysis project using Claude Desktop App.

What This Chapter Covers
  • co-consult system introduction and architecture
  • How the PM dispatches specialists (7-phase Phase 0–6 workflow)
  • How to make requests to the PM agent
  • 4 team composition patterns
  • Practice: simple market analysis project
  • Reviewing outputs

What is co-consult

Definition

co-consult is a system in which AI agent teams carry out strategic consulting projects. As one of the variants of ai-workspace-standards that we explored in Chapter 5, multiple AI agents collaborate to automate consulting tasks such as market analysis, competitive analysis, entry strategy development, and business model review.

Location: templates/co-consult/ inside ai-workspace-standards — scaffold your own copy with bun scripts/new-project.ts "<name>" --variant co-consult.

What Problem Does It Solve?

Strategic consulting involves several steps. co-consult has the entire process carried out by an AI agent team.

  • Market analysis — Understanding market size, growth rate, and trends
  • Competitive analysis — Comparing key competitors' strengths, weaknesses, and market share
  • Entry strategy — Determining methods, timing, and channels for entering a new market
  • Business model — Analyzing revenue structure, value proposition, and key resources
  • Technology trends — Reviewing related technology trends and adoption feasibility
Beginner analogy: co-consult is like a virtual "consulting firm." The PM (Project Manager) holds a meeting with the partner (you) to understand your requirements, and specialist agents each carry out their assigned analysis. The structure is similar to how a senior consultant leads junior consultants at a real consulting firm.

Difference from co-deck

While co-deck is specialized for presentation (slide) production, co-consult is specialized for strategic analysis and report writing. Both systems are built on ai-workspace-standards, but they differ in purpose and agent composition.

co-deck

  • Presentation slide production
  • research, storyline, html-build, pdf-export, etc.
  • 11-Stage pipeline
  • Output: HTML slides + PDF

co-consult

  • Strategic consulting analysis and reports
  • strategy-analyst, industry-expert, sme, communications-lead, etc.
  • PM-dispatched 7-phase (Phase 0–6) workflow
  • Output: Analysis report HTML + PDF

System Architecture

Agent Composition

co-consult consists of one PM agent (the Engagement Leader) and 10 specialist agents. The PM sits at the center, orchestrating the entire engagement, while specialist agents carry out work in their respective domains.

Specialist Agent Roles

Here is a summary of each specialist agent's role. Each agent is brought in through a PM dispatch within the phase it is assigned to, and the ordering inside that phase flexes to fit the engagement.

Agent Role Description
change-management-partner Change Management Partner Organizational transformation, culture strategy, and stakeholder alignment
strategy-analyst Strategy Analyst Market analysis, competitive research, and financial modeling
industry-expert Industry Expert Industry-specific insights, competitive dynamics, and the regulatory landscape
sme Subject Matter Expert Functional expertise such as HR, Finance, Operations, or Marketing
communications-lead Communications Lead Client communications, presentations, and strategic narratives
solutions-architect Solutions Architect Technical solution design, system architecture, and implementation roadmaps
workstream-lead Workstream Lead Workstream management, team coordination, and progress tracking
delivery-manager Delivery Manager Project delivery, operations coordination, and resource allocation
technology-specialist Technology Specialist Collaboration platforms, workflow automation, and digital transformation
data-analyst Data Analyst Statistical analysis, data modeling, and visualization
The PM agent does not execute the work of the specialist agents directly. The PM only plays the role of an orchestrator — it analyzes the user's request and dispatches tasks to the appropriate specialist agents, as the engagement requires. See the PM Gateway section in Chapter 4 for details.

How the PM Dispatches Specialists

Like co-deck's 11-stage pipeline, co-consult follows a fixed 7-phase workflow (Phase 0–6): Initiation (Phase 0) → Research & Analysis (Phase 1) → Cross-Validation (Phase 1.5) → Design Review & Approval (Phase 2) → Content Creation (Phase 3) → Coordination & Delivery (Phase 4) → Lifecycle Finalization (Phase 5) → Quality Assurance (Phase 6). Every specialist works within this flow, dispatched by the PM (Engagement Leader) at each phase (as of 2026-08-24). The flexibility lies in the ordering of specialists: within each phase, the PM decides which specialists to activate and in what order, as the engagement's questions and deliverables require. In addition, Phase 2 includes a gate that requires explicit user/client approval, and iteration loops allow the engagement to return to earlier phases when the analysis calls for it.

How an Engagement Actually Proceeds

  1. Kickoff
    The PM talks with you to understand the topic, scope, target audience, and timeline. This is exactly the first step of the workflow — Initiation (Phase 0): the PM captures this context and decides which specialists the engagement calls for.
  2. Dispatch specialists as questions arise
    The PM activates whichever specialists are relevant — for example strategy-analyst for market and competitive research, industry-expert for sector-specific context, or sme for a functional deep dive. Within the Research phase (Phase 1) there is no required ordering; the PM may dispatch several in parallel or bring in more mid-phase if a gap appears.
  3. Synthesis and reporting
    Once enough analysis is in hand, the PM typically brings in communications-lead to shape the narrative and produce client-ready materials, and solutions-architect or workstream-lead if the engagement calls for an implementation plan.
  4. Delivery and wrap-up
    For larger engagements, delivery-manager and workstream-lead coordinate execution and track progress. The PM concludes the engagement once it determines, together with you, that the deliverables are complete.
You define requirements at kickoff and review deliverables whenever the PM checks in with you. Checkpoints happen at the workflow's phase boundaries — e.g., after a first round of research (Phase 1.5 Cross-Validation), and the design approval gate (Phase 2) requires explicit user/client approval. If the analysis does not support approval, iteration loops take the engagement back to earlier phases. You can redirect the engagement at any of these checkpoints.

How to Talk to the PM

To use co-consult, you need to open the co-consult project in Claude Desktop App and send a request to the PM agent. An effective request significantly improves the quality of the project outcome.

The 4 Key Elements of a Good Request

A good request includes the following four elements.

  1. Purpose — What do you want to analyze?
  2. Scope — Which market, which domain?
  3. Target — Who is this analysis for? (your company, competitors, etc.)
  4. Timeline — When do you need the results?

Request Examples

Example 1: Market Analysis
"Analyze the food delivery app market in South Korea. Focus on competitor comparison and entry opportunities. Complete within 2 weeks."
Example 2: Business Model Review
"Review our startup's SaaS business model. Target market is Japanese B2B enterprises. Cover pricing strategy and scalability."
Example 3: Technology Adoption Assessment
"Evaluate introducing an AI chatbot to our company, targeting the education industry. Include cost analysis, technology stack options, and competitor case studies."

Good Requests vs. Poor Requests

Good Request

  • Purpose is clear: "Analyze the market"
  • Scope is specific: "South Korean food delivery app market"
  • Focus areas are stated: "Competitor comparison and entry opportunities"
  • Timeline is set: "Within 2 weeks"
  • PM can dispatch agents immediately

Poor Request

  • Purpose is vague: "Analyze something for me"
  • No scope: Market? Technology? Competitors?
  • Focus areas unclear: "Everything"
  • No timeline: Deadline is undefined
  • PM must ask follow-up questions
Start with a simple topic as a beginner. Save complex projects for after you have gained experience. A straightforward request like "Analyze the key trends in the South Korean coffee shop market" is recommended to learn how co-consult operates before tackling anything more involved.

Team Composition Patterns

co-consult offers 4 team composition patterns depending on the project's scale and complexity. The PM analyzes the project requirements and selects the most appropriate pattern.

The 4 Team Composition Patterns

Beginners are recommended to start with the Quick Assessment or Standard pattern. Quick Assessment delivers results in 1-2 days, making it ideal for learning how co-consult works. Once you are comfortable, gradually progress to more complex projects with the Standard pattern.

Practice: Simple Market Analysis

In this hands-on exercise, you will use co-consult to carry out a simple market analysis project. We will use the Quick Assessment pattern and analyze the key trends in the South Korean coffee shop market.

Exercise Objectives

  • Clone the co-consult repository and set up the project
  • Send a request to the PM agent in Claude Desktop App
  • Observe the PM dispatching specialists as needed
  • Review progress and give feedback along the way
  • Review the final deliverables

Prerequisites

Make sure the tools installed in Chapter 3 are working correctly.

  1. Claude Desktop App — You should be able to have a conversation with Claude AI
  2. Git — You should be able to clone a repository
  3. Text editor — VS Code or any editor where you can open files

Exercise Steps

  1. Clone the workspace and scaffold the project
    If you haven't already cloned the workspace in an earlier chapter, do that first, then scaffold a new project from the co-consult variant using new-project.ts.
    git clone https://github.com/5throck/ai-workspace-standards.git
    cd ai-workspace-standards
    bun scripts/new-project.ts "co-consult" --variant co-consult
    This creates Projects/co-consult/ as its own independent Git repository, with the co-consult variant's agents, skills, and configuration already copied in.
  2. Open the project in Claude Desktop App
    Launch Claude Desktop App and open the Projects/co-consult/ folder as the project. Tell Claude the following to start the PM.
    "I'd like to start a new project."
    The PM starts the kickoff conversation and asks about the topic, scope, and timeline.
  3. Make your request to the PM
    Answer the PM's questions to configure the engagement. Try responding like this.
    "Analyze the key trends in the South Korean coffee shop market. Focus on the comparison between franchise cafes and independent cafes. Keep it a quick assessment."
    The PM analyzes your request and decides which specialists to dispatch for a Quick Assessment-sized engagement.
  4. Observe the specialist dispatch
    The PM dispatches specialists at each phase — the ordering of specialists within a phase flexes with the engagement. You will typically see something like the following.
    • The strategy-analyst agent researches "South Korean coffee shop market trends" and produces a findings document with market size, growth, and competitive notes
    • If the request calls for it, the PM also brings in industry-expert for sector-specific context
    • The communications-lead agent shapes the findings into a client-ready report
    The PM reports progress as each specialist finishes its piece. The project_state.json file is automatically updated throughout.
  5. Review progress and give feedback
    The PM checks in with you at the workflow's checkpoints — typically after the first round of analysis (passing through cross-validation and the design approval gate), and again before finalizing the report.
    • After analysis: Verify that the analysis direction and insights are appropriate. If adjustments are needed, this is the point to change course.
    • Before finalizing: Review the quality of the final report and approve turning it into a finished deliverable.
    At a checkpoint, you can respond like this.
    "I've reviewed the analysis. Please proceed to the next step."
    Or if revisions are needed, provide specific feedback.
    "Add delivery cafe data from Baemin to the competitive analysis section."
  6. Check the deliverables
    Once the PM determines the engagement's deliverables are complete, you can find them in the deliverables/reports/ folder. The specific steps for reviewing them are covered in the next section.
If you encounter errors during the exercise, refer to the troubleshooting section in Chapter 3. If Claude Desktop App does not respond, or an agent dispatch error occurs, try restarting Claude or re-opening the project folder.
Warning: co-consult's agents operate through the Claude API. During the exercise, Claude's response speed may slow down or time out. Complex analyses take longer, and this is normal behavior.

Reviewing Outputs

When a co-consult project is completed, several deliverables are generated. This section explains where each deliverable is located and how to review it.

Output Location

All deliverables are stored in the deliverables/reports/ directory. From the project root, access it via the following path.

Projects/co-consult/deliverables/reports/

Key Deliverables

File Description Produced by
findings_*.md Research findings, market/competitive data, and sources collected during analysis strategy-analyst / industry-expert
analysis_*.md Individual analysis results from other specialist agents involved (e.g. sme, data-analyst) relevant specialist
narrative_framework.md Overall report structure and section-level narrative design communications-lead
report.html Final analysis report in HTML format communications-lead
report.pdf Final analysis report in PDF format PM (finalization)

How to Review Deliverables

  1. Open the project folder
    Navigate to the Projects/co-consult/deliverables/reports/ directory in your terminal.
    cd Projects/co-consult/deliverables/reports/
    ls
  2. Review the findings document
    Check the research results. It contains collected sources, key data points, and reference links.
    cat findings_market.md
    Or open it in VS Code.
  3. Review the HTML report
    Open the report.html file in a browser to view the completed report. It is an interactive format that includes charts, tables, and diagrams.
    open report.html
  4. Review the PDF
    Open the report.pdf file to view the print-ready report. This format is suitable for sharing or archiving.
  5. Check project_state.json
    You can view the overall project progress. It records which specialists have been dispatched, what they've produced, and whether the PM has checked in with you at each review point.
    cat project_state.json

File Structure Summary

co-consult/
  agents/                    # Agent definition files
    pm.md
    strategy-analyst.md
    industry-expert.md
    communications-lead.md
    ...
  deliverables/
    reports/
      findings_market.md    # strategy-analyst / industry-expert output
      narrative_framework.md # communications-lead output
      report.html            # communications-lead output
      report.pdf              # PM finalization
  project_state.json        # Project progress status
  consult-profile.md        # Project settings
  memory/                   # Session logs
    YYYY-MM-DD.md
Deliverables can also be viewed in Claude Desktop App's Artifacts. Files and diagrams generated by Claude can be previewed directly in the conversation screen. Additionally, project_state.json lets you check in real time which Phase the project is currently in.
How to use the deliverables: The completed report can be shared with your team or used as material for a presentation. When used together with co-deck (Chapter 7), you can create a presentation based on the analysis report.
