co-consult: AI Consulting in Practice

co-consult is a system where AI agent teams execute consulting projects. In this chapter, you'll understand co-consult's structure and run a simple market analysis project using Claude Desktop App.

What is co-consult

Definition

co-consult is a system in which AI agent teams carry out strategic consulting projects. As one of the variants of ai-workspace-standards that we explored in Chapter 5, multiple AI agents collaborate to automate consulting tasks such as market analysis, competitive analysis, entry strategy development, and business model review.

GitHub repository: github.com/5throck/co-consult

What Problem Does It Solve?

Strategic consulting involves several steps. co-consult has the entire process carried out by an AI agent team.

  • Market analysis — Understanding market size, growth rate, and trends
  • Competitive analysis — Comparing key competitors' strengths, weaknesses, and market share
  • Entry strategy — Determining methods, timing, and channels for entering a new market
  • Business model — Analyzing revenue structure, value proposition, and key resources
  • Technology trends — Reviewing related technology trends and adoption feasibility
Beginner analogy: co-consult is like a virtual "consulting firm." The PM (Project Manager) holds a meeting with the partner (you) to understand your requirements, and specialist agents each carry out their assigned analysis. The structure is similar to how a senior consultant leads junior consultants at a real consulting firm.

Difference from co-deck

While co-deck is specialized for presentation (slide) production, co-consult is specialized for strategic analysis and report writing. Both systems are built on ai-workspace-standards, but they differ in purpose and agent composition.

co-deck

  • Presentation slide production
  • research, storyline, html-build, pdf-export, etc.
  • 11-Stage pipeline
  • Output: HTML slides + PDF

co-consult

  • Strategic consulting analysis and reports
  • research, data-analyst, market-analyst, strategy, etc.
  • 7-Phase pipeline
  • Output: Analysis report HTML + PDF

System Architecture

Agent Composition

co-consult consists of one PM agent and 11 specialist agents. The PM sits at the center, orchestrating the entire project, while specialist agents carry out work in their respective domains.

Specialist Agent Roles

Here is a summary of each specialist agent's role.

Agent Role Description
research Research Specialist Collects related materials and data from the web and organizes them into research_notes.md
source-verifier Source Verifier Validates the credibility of collected sources and calculates a Trust Score (optional)
data-analyst Data Analyst Analyzes numerical data and generates visualization materials
market-analyst Market Analyst Analyzes the market environment including market size, growth rate, and trends
strategy Strategy Consultant Develops strategic recommendations and an execution roadmap based on analysis results
tech-analyst Technology Analyst Analyzes related technology trends and adoption feasibility
storyline Storyliner Designs the overall structure and narrative of the report
html-build HTML Builder Converts analysis content into an HTML-format report
pdf-export PDF Exporter Exports the report to PDF format
version Version Manager Performs automatic backups before file modifications
auditor Quality Auditor Reviews the quality and consistency of the final deliverable
The PM agent does not execute the work of the specialist agents directly. The PM only plays the role of an orchestrator — it analyzes the user's request and dispatches tasks to the appropriate specialist agents. See the PM Gateway section in Chapter 4 for details.

7-Phase Workflow

co-consult follows a workflow composed of 7 Phases to complete a consulting project. Each Phase is handled by a specific agent and produces defined deliverables.

Key Deliverables by Phase

  1. Phase 0 — Project Kickoff
    PM meets with the user to finalize the project's topic, scope, target market, and timeline. In this step, consult-profile.md and project_state.json are created.
  2. Phase 1 — Research
    The research agent performs web searches to collect related materials, statistics, and reports. The output is research_notes.md, which serves as the information foundation for the entire project.
  3. Phase 1.5 — Source Verification (Optional)
    The source-verifier agent validates the accessibility and content accuracy of collected source URLs. It calculates a Trust Score; if the score is below 70%, the project is temporarily halted.
  4. Phase 2-3 — Analysis and Strategy Development
    data-analyst, market-analyst, strategy, tech-analyst, and others perform analysis in their respective domains and propose strategies based on the research results. The storyline agent designs the report structure.
  5. Phase 4 — Report Writing
    The html-build agent converts analysis results into an HTML-format report. The completed report includes charts, diagrams, and tables.
  6. Phase 5 — Quality Review
    The auditor agent reviews the report's quality, consistency, and data accuracy. If issues are found, it sends fix requests.
  7. Phase 6 — Finalization
    The pdf-export agent converts the final report to PDF and saves it in deliverables/reports/. The project status is updated to completed.
You define requirements at Phase 0 and provide approval at Gate 2 (after Phase 2-3) and Gate 5 (after Phase 5). The remaining Phases proceed automatically as the PM dispatches agents. The workflow does not advance past a Gate without your approval, so you can adjust direction mid-project.

How to Talk to the PM

To use co-consult, you need to open the co-consult project in Claude Desktop App and send a request to the PM agent. An effective request significantly improves the quality of the project outcome.

The 4 Key Elements of a Good Request

A good request includes the following four elements.

  1. Purpose — What do you want to analyze?
  2. Scope — Which market, which domain?
  3. Target — Who is this analysis for? (your company, competitors, etc.)
  4. Timeline — When do you need the results?

Request Examples

Example 1: Market Analysis
"Analyze the food delivery app market in South Korea. Focus on competitor comparison and entry opportunities. Complete within 2 weeks."
Example 2: Business Model Review
"Review our startup's SaaS business model. Target market is Japanese B2B enterprises. Cover pricing strategy and scalability."
Example 3: Technology Adoption Assessment
"Evaluate introducing an AI chatbot to our company, targeting the education industry. Include cost analysis, technology stack options, and competitor case studies."

Good Requests vs. Poor Requests

Good Request

  • Purpose is clear: "Analyze the market"
  • Scope is specific: "South Korean food delivery app market"
  • Focus areas are stated: "Competitor comparison and entry opportunities"
  • Timeline is set: "Within 2 weeks"
  • PM can dispatch agents immediately

Poor Request

  • Purpose is vague: "Analyze something for me"
  • No scope: Market? Technology? Competitors?
  • Focus areas unclear: "Everything"
  • No timeline: Deadline is undefined
  • PM must ask follow-up questions
Start with a simple topic as a beginner. Save complex projects for after you have gained experience. A straightforward request like "Analyze the key trends in the South Korean coffee shop market" is recommended to learn how co-consult operates before tackling anything more involved.

Team Composition Patterns

co-consult offers 4 team composition patterns depending on the project's scale and complexity. The PM analyzes the project requirements and selects the most appropriate pattern.

The 4 Team Composition Patterns

Beginners are recommended to start with the Quick Assessment or Standard pattern. Quick Assessment delivers results in 1-2 days, making it ideal for learning how co-consult works. Once you are comfortable, gradually progress to more complex projects with the Standard pattern.

Practice: Simple Market Analysis

In this hands-on exercise, you will use co-consult to carry out a simple market analysis project. We will use the Quick Assessment pattern and analyze the key trends in the South Korean coffee shop market.

Exercise Objectives

  • Clone the co-consult repository and set up the project
  • Send a request to the PM agent in Claude Desktop App
  • Observe the 7-Phase workflow in action
  • Experience the Gate approval process
  • Review the final deliverables

Prerequisites

Make sure the tools installed in Chapter 3 are working correctly.

  1. Claude Desktop App — You should be able to have a conversation with Claude AI
  2. Git — You should be able to clone a repository
  3. Text editor — VS Code or any editor where you can open files

Exercise Steps

  1. Clone the co-consult repository
    Open a terminal and run the following commands.
    git clone https://github.com/5throck/co-consult.git
    cd co-consult
    Once the repository is cloned, navigate into the co-consult/ directory.
  2. Open the project in Claude Desktop App
    Launch Claude Desktop App and open the co-consult/ folder as the project. Tell Claude the following to start the PM.
    "I'd like to start a new project."
    The PM enters Stage 0 (Project Kickoff) and asks about the topic, scope, and timeline.
  3. Make your request to the PM
    Answer the PM's questions to configure the project. Try responding like this.
    "Analyze the key trends in the South Korean coffee shop market. Focus on the comparison between franchise cafes and independent cafes. Use the Quick Assessment pattern."
    The PM analyzes your request and guides you through the agent composition for the Quick Assessment pattern.
  4. Observe the Phase progression
    The PM automatically dispatches agents. You will see the following process on screen.
    • Phase 1: The research agent searches for "South Korean coffee shop market trends" and writes research_notes.md
    • Phase 2-3: The market-analyst agent analyzes market data, and the strategy agent extracts key insights
    • Phase 4: The html-build agent converts the analysis results into an HTML report
    • Phase 5: The auditor agent reviews the report quality
    The PM reports progress each time a Phase completes. The project_state.json file is automatically updated throughout.
  5. Approve at Gates
    During the workflow, the PM requests your approval at two Gates.
    • Gate 2 (after Phase 2-3): Verify that the analysis direction and insights are appropriate. If adjustments are needed, this is the point to change course.
    • Gate 5 (after Phase 5): Review the quality of the final report and approve the PDF export.
    At a Gate, you can respond like this.
    "I've reviewed the analysis. Please proceed to the next step."
    Or if revisions are needed, provide specific feedback.
    "Add delivery cafe data from Baemin to the competitive analysis section."
  6. Check the deliverables
    Once all Phases are complete, you can find the deliverables in the deliverables/reports/ folder. The specific steps for reviewing them are covered in the next section.
If you encounter errors during the exercise, refer to the troubleshooting section in Chapter 3. If Claude Desktop App does not respond, or an agent dispatch error occurs, try restarting Claude or re-opening the project folder.
Warning: co-consult's agents operate through the Claude API. During the exercise, Claude's response speed may slow down or time out. Complex analyses take longer, and this is normal behavior.

Reviewing Outputs

When a co-consult project is completed, several deliverables are generated. This section explains where each deliverable is located and how to review it.

Output Location

All deliverables are stored in the deliverables/reports/ directory. From the project root, access it via the following path.

co-consult/deliverables/reports/

Key Deliverables

File Description Created in
research_notes.md Materials, statistics, and sources collected via web search Phase 1
source-verification.md Source credibility verification results and Trust Score (optional) Phase 1.5
storyline.md Overall report structure and section-level narrative design Phase 2-3
analysis_*.md Individual analysis results from specialist agents Phase 2-3
report.html Final analysis report in HTML format Phase 4
report.pdf Final analysis report in PDF format Phase 6

How to Review Deliverables

  1. Open the project folder
    Navigate to the co-consult/deliverables/reports/ directory in your terminal.
    cd co-consult/deliverables/reports/
    ls
  2. Review research_notes.md
    Check the research results. It contains collected sources, key data points, and reference links.
    cat research_notes.md
    Or open it in VS Code.
  3. Review the HTML report
    Open the report.html file in a browser to view the completed report. It is an interactive format that includes charts, tables, and diagrams.
    open report.html
  4. Review the PDF
    Open the report.pdf file to view the print-ready report. This format is suitable for sharing or archiving.
  5. Check project_state.json
    You can view the overall project progress. It records whether each Phase is completed and whether each Gate has been approved.
    cat project_state.json

File Structure Summary

co-consult/
  agents/                    # Agent definition files
    pm.md
    research.md
    market-analyst.md
    strategy.md
    ...
  deliverables/
    reports/
      research_notes.md   # Phase 1 deliverable
      storyline.md        # Phase 2-3 deliverable
      report.html         # Phase 4 deliverable
      report.pdf          # Phase 6 deliverable
  project_state.json        # Project progress status
  consult-profile.md        # Project settings
  memory/                   # Session logs
    YYYY-MM-DD.md
Deliverables can also be viewed in Claude Desktop App's Artifacts. Files and diagrams generated by Claude can be previewed directly in the conversation screen. Additionally, project_state.json lets you check in real time which Phase the project is currently in.
How to use the deliverables: The completed report can be shared with your team or used as material for a presentation. When used together with co-deck (Chapter 7), you can create a presentation based on the analysis report.
