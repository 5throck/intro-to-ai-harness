Capítulo 6

co-consult: AI Consulting in Practice

co-consult is a system where AI agent teams execute consulting projects. En este capítulo, you'll understand co-consult's structure and run a simple market analysis project using Claude Desktop App.

Lo que cubre este capítulo
  • co-consult system introduction and architecture
  • How the PM dispatches specialists (no fixed pipeline)
  • Cómo hacer solicitudes al agent PM
  • 4 team composition patterns
  • Practice: simple market analysis project
  • Reviewing outputs

What is co-consult

Definition

co-consult es un sistema en el que AI agent teams carry out strategic consulting projects. Como una de las variantes de ai-workspace-standards que exploramos en el Capítulo 5, múltiples agents de IA colaboran para automatizar tareas de consultoría como análisis de mercado, análisis competitivo, desarrollo de estrategias de entrada y revisión de modelos de negocio.

Location: templates/co-consult/ inside ai-workspace-standards — scaffold your own copy with bun scripts/new-project.ts "<name>" --variant co-consult.

¿Qué problema resuelve?

La consultoría estratégica involucra varios pasos. co-consult hace que todo el proceso sea llevado a cabo por un equipo de agents de IA.

  • Market analysis — Understanding market size, growth rate, and trends
  • Competitive analysis — Comparing key competitors' strengths, weaknesses, and market share
  • Entry strategy — Determining methods, timing, and channels for entering a new market
  • Business model — Analyzing revenue structure, value proposition, and key resources
  • Technology trends — Reviewing related technology trends and adoption feasibility
Beginner analogy: co-consult es como una "consultora" virtual. El PM (Project Manager) celebra una reunión con el socio (tú) para entender tus requisitos, y los agents especializados realizan cada uno el análisis que se le asignó. La estructura es similar a cómo un consultor senior dirige a consultores junior en una consultora real.

Difference from co-deck

Mientras que co-deck está especializado en presentation (slide) production, co-consult está especializado en strategic analysis and report writing. Ambos sistemas están construidos sobre ai-workspace-standards, pero difieren en propósito y composición de agents.

co-deck

  • Presentation slide production
  • research, storyline, html-build, pdf-export, etc.
  • 11-Stage pipeline
  • Resultado: HTML slides + PDF

co-consult

  • Strategic consulting analysis and reports
  • strategy-analyst, industry-expert, sme, communications-lead, etc.
  • PM-dispatched, no fixed pipeline
  • Resultado: Analysis report HTML + PDF

System Architecture

Agent Composition

co-consult consiste en un agent PM (el Engagement Leader) y 10 agents especializados. El PM se sitúa en el centro, orquestando todo el engagement, mientras los agents especializados realizan el trabajo en sus respectivos dominios.

Specialist Agent Roles

Aquí tienes un resumen del rol de cada agent especializado. A diferencia de un pipeline fijo, cualquiera de ellos puede ser despachado en cualquier momento del engagement, según sea necesario.

Agent Role Descripción
change-management-partner Change Management Partner Organizational transformation, culture strategy, and stakeholder alignment
strategy-analyst Strategy Analyst Market analysis, competitive research, and financial modeling
industry-expert Industry Expert Industry-specific insights, competitive dynamics, and the regulatory landscape
sme Subject Matter Expert Conocimiento funcional como RR. HH., Finanzas, Operaciones o Marketing
communications-lead Communications Lead Client communications, presentations, and strategic narratives
solutions-architect Solucións Architect Technical solution design, system architecture, and implementation roadmaps
workstream-lead Workstream Lead Workstream management, team coordination, and progress tracking
delivery-manager Delivery Manager Project delivery, operations coordination, and resource allocation
technology-specialist Technology Specialist Collaboration platforms, workflow automation, and digital transformation
data-analyst Data Analyst Statistical analysis, data modeling, and visualization
El agent PM not ejecuta directamente el trabajo de los agents especializados. El PM solo desempeña el rol de orquestador — analiza la solicitud del usuario y despacha tareas a los agents especializados apropiados, según lo requiera el engagement. Consulta la sección PM Gateway del Capítulo 4 para más detalles.

How the PM Dispatches Specialists

A diferencia del pipeline fijo de 11 etapas de co-deck, co-consult tiene no fixed phase sequence. El PM (Engagement Leader) analiza tu solicitud, decide qué especialistas se necesitan y los despacha directamente — activando más a medida que las preguntas y entregables del engagement lo requieran, en lugar de avanzar por fases numeradas y gates.

How an Engagement Actually Proceeds

  1. Kickoff
    El PM habla contigo para comprender el tema, el alcance, la audiencia objetivo y el cronograma. No hay un formato de archivo separado para la "Phase 0" — el PM simplemente captura este contexto y decide qué especialistas requiere el engagement.
  2. Dispatch specialists as questions arise
    El PM activa a los especialistas que sean relevantes — por ejemplo strategy-analyst para investigación de mercado y competencia, industry-expert para contexto específico del sector, o sme para un análisis funcional profundo. No hay un orden requerido; el PM puede despachar varios en paralelo o incorporar más a mitad del engagement si aparece una laguna.
  3. Synthesis and reporting
    Una vez que se cuenta con suficiente análisis, el PM generalmente incorpora a communications-lead para dar forma a la narrativa y producir materiales listos para el cliente, y a solutions-architect o workstream-lead si el engagement requiere un plan de implementación.
  4. Delivery and wrap-up
    Para engagements más grandes, delivery-manager y workstream-lead coordinan la ejecución y hacen seguimiento del progreso. El PM concluye el engagement una vez que determina, junto contigo, que los entregables están completos.
Tú define requirements at kickoff y revisas los entregables cada vez que el PM se pone en contacto contigo. Como no hay un pipeline fijo, los puntos de control ocurren naturalmente en los momentos que el PM juzgue útiles — p. ej., después de una primera ronda de investigación o antes de finalizar un informe — en lugar de en gates numerados predefinidos. Puedas redireccionar el engagement en cualquiera de estos puntos de control.

Cómo hablar con el PM

Para usar co-consult, necesitas abrir el proyecto co-consult en Claude Desktop App y enviar una solicitud al agent PM. Una solicitud efectiva mejora significativamente la calidad del resultado del proyecto.

The 4 Key Elements of a Good Request

A good request includes the following four elements.

  1. Purpose — ¿Qué quieres analizar?
  2. Scope — Which market, which domain?
  3. Audiencia objetivo — ¿Para quién es este análisis? (tu empresa, competidores, etc.)
  4. Cronograma — ¿Cuándo necesitas los resultados?

Request Examples

Example 1: Market Analysis
"Analiza el mercado de apps de entrega de comida en Corea del Sur. Enfócate en la comparación de competidores y las oportunidades de entrada. Completa en 2 semanas."
Example 2: Business Model Review
"Revisa el modelo de negocio SaaS de nuestra startup. El mercado objetivo son empresas B2B japonesas. Cubre la estrategia de precios y la escalabilidad."
Example 3: Technology Adoption Assessment
"Evalúa la introducción de un chatbot de IA en nuestra empresa, dirigido a la industria educativa. Incluye análisis de costos, opciones de stack tecnológico y casos de estudio de competidores."

Good Requests vs. Poor Requests

Good Request

  • Purpose is clear: "Analyze the market"
  • Scope is specific: "South Korean food delivery app market"
  • Focus areas are stated: "Competitor comparison and entry opportunities"
  • Timeline is set: "Within 2 weeks"
  • PM can dispatch agents immediately

Poor Request

  • Purpose is vague: "Analyze something for me"
  • No scope: Market? Technology? Competitors?
  • Focus areas unclear: "Everything"
  • No timeline: Deadline is undefined
  • PM must ask follow-up questions
Comienza con un tema simple como principiante. Guarda los proyectos complejos para después de haber ganado experiencia. Se recomienda una solicitud directa como "Analiza las tendencias clave del mercado de cafeterías de Corea del Sur" para aprender cómo opera co-consult antes de abordar algo más complejo.

Team Composition Patterns

co-consult ofrece 4 team composition patterns dependiendo de la escala y complejidad del proyecto. El PM analiza los requisitos del proyecto y selecciona el patrón más apropiado.

The 4 Team Composition Patterns

Se recomienda que los principiantes comiencen con el patrón Quick Assessment o Standard. Quick Assessment entrega resultados en 1-2 días, lo que lo hace ideal para aprender cómo funciona co-consult. Una vez que te sientas cómodo, avanza gradualmente a proyectos más complejos con el patrón Standard.

Practice: Simple Market Analysis

En este ejercicio práctico, usarás co-consult para llevar a cabo un proyecto simple de análisis de mercado. Usaremos el patrón Quick Assessment y analizaremos las tendencias clave del mercado de cafeterías de Corea del Sur.

Exercise Objectives

  • Clona el repositorio de co-consult y configura el proyecto
  • Envía una solicitud al agent PM en Claude Desktop App
  • Observe the PM dispatching specialists as needed
  • Review progress and give feedback along the way
  • Review the final deliverables

Prerequisites

Asegúrate de que las herramientas instaladas en el Capítulo 3 funcionen correctamente.

  1. Claude Desktop App — Debes poder tener una conversación con Claude AI
  2. Git — Debes poder clonar un repositorio
  3. Text editor — VS Code o cualquier editor donde puedas abrir archivos

Exercise Steps

  1. Clona el workspace y genera el proyecto
    If you haven't already cloned the workspace in an earlier chapter, do that first, then scaffold a new project from the co-consult variant using new-project.ts.
    git clone https://github.com/5throck/ai-workspace-standards.git
    cd ai-workspace-standards
    bun scripts/new-project.ts "co-consult" --variant co-consult
    This creates Proyectos/co-consult/ as its own independent Git repository, with the co-consult variant's agents, skills, and configuration already copied in.
  2. Abre el proyecto en Claude Desktop App
    Launch Claude Desktop App and open the Proyectos/co-consult/ folder as the project. Tell Claude the following to start the PM.
    "I'd like to start a new project."
    The PM starts the kickoff conversation and asks about the topic, scope, and timeline.
  3. Haz tu solicitud al PM
    Answer the PM's questions to configure the engagement. Try responding like this.
    "Analiza las tendencias clave del mercado de cafeterías de Corea del Sur. Enfócate en la comparación entre cafeterías de franquicia e independientes. Mantenlo como una evaluación rápida."
    The PM analyzes your request and decides which specialists to dispatch for a Quick Assessment-sized engagement.
  4. Observa el despacho de especialistas
    The PM dispatches specialists directly — there is no fixed phase sequence. You will typically see something like the following.
    • The strategy-analyst agent researches "South Korean coffee shop market trends" and produces a findings document with market size, growth, and competitive notes
    • Si la solicitud lo requiere, el PM también incorpora a industry-expert para el contexto específico del sector
    • The communications-lead agent shapes the findings into a client-ready report
    The PM reports progress as each specialist finishes its piece. The project_state.json file is automatically updated throughout.
  5. Review progress and give feedback
    Since there is no fixed pipeline, the PM checks in with you whenever it judges there's something worth reviewing — typically after the first round of analysis, and again before finalizing the report.
    • Después del análisis: Verifica que la dirección del análisis y las ideas sean apropiadas. Si se necesitan ajustes, este es el momento de cambiar de rumbo.
    • Before finalizing: Revisa la calidad del informe final y aprueba convertirlo en un entregable terminado.
    At a checkpoint, you can respond like this.
    "I've reviewed the analysis. Please proceed to the next step."
    Or if revisions are needed, provide specific feedback.
    "Añade datos de cafeterías de entrega de Baemin a la sección de análisis competitivo."
  6. Revisa los entregables
    Una vez que el PM determina que los entregables del engagement están completos, puedes encontrarlos en la carpeta deliverables/reports/. Los pasos específicos para revisarlos se cubren en la siguiente sección.
Si encuentras errores durante el ejercicio, consulta la sección de solución de problemas del Capítulo 3. Si Claude Desktop App no responde, o ocurre un error de despacho de un agent, prueba reiniciar Claude o volver a abrir la carpeta del proyecto.
Warning: Los agents de co-consult operan a través de la API de Claude. Durante el ejercicio, la velocidad de respuesta de Claude puede ralentizarse o agotar el tiempo de espera. Los análisis complejos tardan más, y este es un comportamiento normal.

Reviewing Resultados

Cuando se completa un proyecto de co-consult, se generan varios entregables. Esta sección explica dónde se encuentra cada entregable y cómo revisarlo.

Resultado Location

Todos los entregables se almacenan en el directorio deliverables/reports/. Desde la raíz del proyecto, accede a él mediante la siguiente ruta.

Proyectos/co-consult/deliverables/reports/

Key Deliverables

File Descripción Produced by
findings_*.md Research findings, market/competitive data, and sources collected during analysis strategy-analyst / industry-expert
analysis_*.md Individual analysis results from other specialist agents involved (e.g. sme, data-analyst) relevant specialist
narrative_framework.md Overall report structure and section-level narrative design communications-lead
report.html Final analysis report in HTML format communications-lead
report.pdf Final analysis report in PDF format PM (finalization)

How to Review Deliverables

  1. Abre la carpeta del proyecto
    Navigate to the Proyectos/co-consult/deliverables/reports/ directory in your terminal.
    cd Proyectos/co-consult/deliverables/reports/
    ls
  2. Revisa el documento de hallazgos
    Check the research results. It contains collected sources, key data points, and reference links.
    cat findings_market.md
    Or open it in VS Code.
  3. Revisa el informe HTML
    Open the report.html file in a browser to view the completed report. It is an interactive format that includes charts, tables, and diagrams.
    open report.html
  4. Revisa el PDF
    Abre el archivo report.pdf para ver el informe listo para imprimir. Este formato es adecuado para compartir o archivar.
  5. Check project_state.json
    You can view the overall project progress. It records which specialists have been dispatched, what they've produced, and whether the PM has checked in with you at each review point.
    cat project_state.json

File Structure Summary

co-consult/
  agents/                    # Agent definition files
    pm.md
    strategy-analyst.md
    industry-expert.md
    communications-lead.md
    ...
  deliverables/
    reports/
      findings_market.md    # strategy-analyst / industry-expert output
      narrative_framework.md # communications-lead output
      report.html            # communications-lead output
      report.pdf              # PM finalization
  project_state.json        # Project progress status
  consult-profile.md        # Project settings
  memory/                   # Session logs
    YYYY-MM-DD.md
Los entregables también pueden verse en los Artifacts de Claude Desktop App. Los archivos y diagramas generados por Claude pueden previsualizarse directamente en la pantalla de conversación. Además, project_state.json te permite comprobar en tiempo real en qué Phase se encuentra actualmente el proyecto.
Cómo usar los entregables: El informe completado puede compartirse con tu equipo o usarse como material para una presentación. Cuando se usa junto con co-deck (Capítulo 7), puedes crear una presentación basada en el informe de análisis.
