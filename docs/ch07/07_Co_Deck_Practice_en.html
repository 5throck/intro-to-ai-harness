co-deck: AI Presentation in Practice

co-deck is a system where AI agent teams produce presentations (lecture materials, slide decks). This chapter covers the 11-Stage pipeline and walks you through creating a mini presentation.

What This Chapter Covers
  • co-deck system introduction and architecture
  • 11-Stage pipeline
  • Theme and Style selection
  • Gate approvals (Gate 2: content, Gate 5: sample PDF)
  • Practice: create a mini presentation
  • HTML and PDF output review

What is co-deck

Definition

co-deck is a variant of the ai-workspace-standards ecosystem specialized for producing lecture materials and presentation slide decks. It is an L2 variant project that inherits the common workspace structure (agents, skills, governance rules) and adds its own specialized agents and an 11-stage production pipeline.

The name "co-deck" stands for collaborative deck — a slide deck produced through collaboration between a human presenter and a team of AI agents.

What co-deck Produces

co-deck produces two primary output types:

Single-File HTML Slide Deck

  • A self-contained .html file with all slides, CSS, images, and JavaScript embedded
  • Open in any browser — no installation required
  • Supports presenter mode, TTS narration, keyboard navigation, and fullscreen
  • Five HTML themes available (outline, vertical, pitch-enhanced, outlook, zen)

Print-Ready PDF

  • A pixel-perfect PDF suitable for printing or distribution
  • 16:9 aspect ratio, matched to the HTML layout
  • Generated from the same slide data as the HTML version
  • Sample PDF (5 slides) for review, then full PDF export on approval

The Presentation Production Company Analogy

Imagine you are running a presentation production company. You are the executive producer (the human), and you have a team of specialists working under a project manager. Here is how the analogy maps:

Presentation Company

  • Executive Producer (you) — defines the topic, reviews drafts, gives final approval
  • Project Manager — orchestrates the team, schedules tasks, enforces quality
  • Research Team — gathers sources and fact-checks
  • Content Writer — structures the narrative and writes slide content
  • Art Director — picks colors, fonts, and visual style
  • Photographer — finds and downloads images
  • Graphics Team — creates diagrams and charts
  • Web Developer — builds the HTML slide deck
  • Print Specialist — produces the final PDF

co-deck

  • You (the user) — provides the topic, reviews content at Gate 2, approves PDF at Gate 5
  • PM Agent — orchestrates all specialist agents, manages pipeline stages
  • research + source-verifier — web research and URL validation
  • storyline — creates storyline.md and slide_deck.md
  • design — writes design_spec.md with color palette and fonts
  • image-curator — searches Pixabay, Unsplash, Pexels for images
  • diagram-specialist — generates SVG diagrams and data charts
  • html-build — generates the single-file HTML slide deck
  • pdf-export — produces sample and full PDF output
Version control is built in. The version agent acts like a company's document archive manager — it snapshots every file before any change is made, so you can always roll back to a previous state. Think of it as an automatic "Save As" before every edit.

System Architecture

co-deck's architecture follows the PM + Specialist Agent pattern from ai-workspace-standards. The PM Agent acts as the central orchestrator, and a team of specialist agents each handle one aspect of presentation production.

Agent Roles Table

Agent Tier Stage Role
PM High 0 – 11 Orchestrates the entire pipeline, dispatches specialists, enforces gates
research Medium 1 Gathers web sources and writes research_notes.md
source-verifier Medium 1.5 Validates URLs and produces source-verification.md with Trust Score
storyline Medium 2 – 3 Writes storyline.md and slide_deck.md
design Medium 4 Locks visual design — color palette, fonts, layout into design_spec.md
image-curator Medium 3.5 Searches and downloads commercial-use images to assets/images/
diagram-specialist Medium 3.5 Generates SVG concept diagrams and data charts to assets/diagrams/
html-build Medium 5 – 8 Generates the single-file HTML slide deck from slide_deck.md
measure Medium 9 – 10 Auto-measures HTML layout with Playwright, downloads TTF fonts for PDF
pdf-export Medium 11 Generates sample and full PDF from slide data
version Low 0 – 11 Snapshots files before every edit; restores prior states on demand

Agent Composition Diagram

The diagram below shows how the PM Agent sits at the center, dispatching specialist agents for each stage of the pipeline. The version agent runs in parallel as a cross-cutting concern.

The user talks only to the PM. You never directly instruct specialist agents. You tell the PM what you want (for example, "make a presentation about climate change"), and the PM dispatches the right agents in the right order. This is the PM Gateway pattern we learned about in Chapter 4.

11-Stage Pipeline

The co-deck pipeline consists of 11 stages, each handled by a specific specialist agent (or the PM directly). The stages run sequentially, with some optional review gates along the way. Here is a detailed walkthrough of each stage.

Stage 0 — Config (Mandatory)

The PM reads the master docs/lecture-profile.md, copies it to presentations/<name>/lecture-profile.md, and prompts you to fill in lecture-specific details: title, audience, level, keywords. You must also confirm the rendering theme, visual style, whether source verification is enabled, divider mode, and background image preferences. The PM initializes project_state.json and memory/keywords.md.

Stage 1 — Research

The research agent performs web research on the topic (in both Korean and English if needed), collecting sources and writing research_notes.md with sections for sources, key facts, and credibility notes. This becomes the knowledge base for the entire presentation.

Stage 1.5 — Source Verification (Optional)

If source verification is enabled (the default), the source-verifier agent validates every URL from research_notes.md via HTTP check and content cross-check, producing source-verification.md with a Trust Score. The pipeline halts only if the Trust Score falls below 70%.

Stage 2 – 3 — Content (Storyline + Slide Deck)

The storyline agent designs the narrative arc and writes storyline.md, then composes slide_deck.md with per-slide content including titles, bullet points, speaker notes, and image role/query fields for each slide.

Stage 4 — Design

The design agent locks the visual design style: color palette, font families, spacing, and layout rules. It produces design_spec.md with all CSS variables and typography decisions.

Stage 3.5 — Image Curation + Diagram Generation

The image-curator and diagram-specialist agents run in parallel. Image-curator searches Pixabay, Unsplash, and Pexels for commercial-use images. Diagram-specialist generates SVG concept diagrams and data charts. Both produce manifest files (image-manifest.json and diagram-manifest.json).

Stage 5 – 8 — HTML Build

The html-build agent generates the single-file HTML slide deck by combining slide_deck.md content with the selected theme template, design spec, images, and diagrams. The result is a self-contained .html file that works in any browser.

Stage 9 – 10 — Layout Measure

The measure agent uses Playwright to auto-measure the rendered HTML slides, extracting pixel coordinates, fonts, and colors for accurate PDF generation. It also downloads any required TTF fonts.

Stage 11 — PDF Export

The pdf-export agent first generates a sample PDF (5 slides) for your review. Once you approve, it generates the full PDF from the complete slide data.

Pipeline Flow Diagram

Mandatory vs. Optional Gates: Only Gate 2 (content approval) and Gate 5 (sample PDF approval) require your explicit approval. Gates 1.5, 3, and 4 are optional — the PM may auto-advance after a brief review. The pipeline halts at Gate 1.5 only if the Trust Score falls below 70%.

Themes and Styles

One of co-deck's most powerful features is the separation of themes and styles. These two concepts work together to give you full control over how your presentation looks, without touching any code.

Theme vs. Style

Theme (Rendering Paradigm)

  • What: The HTML rendering engine and slide structure
  • Controls: How slides are laid out, navigation behavior, transition effects, TOC structure
  • Examples: outline (vertical outline), vertical (scroll-based), pitch-enhanced (PPT-style), outlook (horizontal scroll), zen (minimal zen)
  • Packaged as: 4 files — template.html, theme.json, theme.css, pdf_layout_spec.json
  • Analogy: The floor plan of a house — it determines the shape and flow of the rooms

Style (Visual Appearance)

  • What: The CSS variable set that defines colors, fonts, and visual mood
  • Controls: Background color, text color, accent color, heading fonts, border styles, shadows, and other visual properties
  • Examples: classic (light, professional), premium-dark (dark, sleek), minimal (ultra-clean), academic (scholarly), visual-heavy (image-forward)
  • Packaged as: Single style.css file defining CSS variable overrides
  • Analogy: The interior design of a house — same floor plan, completely different look and feel

Compatibility Matrix

Not every style works with every theme. Each theme declares its compatible styles in theme.json. For example, the pitch theme supports only classic, minimal, and premium-dark, while the outline theme supports all five styles.

The compatibility matrix is documented in docs/html-themes/THEMES.md and is enforced by the PM at Stage 0. If you try to combine an incompatible theme and style, the PM will reject the combination and explain why.

Wide Compatibility

  • outline — classic, minimal, premium-dark, academic, visual-heavy (5 styles)
  • vertical — classic, minimal, premium-dark, academic, visual-heavy (5 styles)
  • zen — classic, minimal, premium-dark, academic (4 styles)

Narrower Compatibility

  • pitch-enhanced — classic, minimal, premium-dark, academic, visual-heavy (5, but visual-heavy is partial)
  • pitch — classic, minimal, premium-dark (3 styles)
  • outlook — classic, minimal, premium-dark, academic, visual-heavy (5 styles)
Tip for beginners: If you are unsure which theme and style to pick, start with outline theme + classic style. This combination has the widest compatibility, produces a clean vertical layout, and works well for most presentation types. You can always change it later without redoing your content.

Gate Approvals

Gates are checkpoints in the pipeline where the workflow pauses for your review. They exist so that you remain in control of the presentation at critical decision points. The PM never proceeds past a mandatory gate without your explicit approval.

Mandatory Gates

Two gates are mandatory — you must explicitly approve before the pipeline continues.

Gate 2 — Content Approval

  • When: After the storyline agent finishes storyline.md and slide_deck.md
  • What you review: The narrative structure, chapter outline, slide titles, bullet content, and image placements
  • Why it matters: Once you approve, the design, image, and build agents start working based on this content. Changing content later means re-running multiple stages
  • PM message: "Approving starts design and HTML. Approve?"

Gate 5 — Sample PDF Approval

  • When: After the pdf-export agent generates a 5-slide sample PDF
  • What you review: Layout, fonts, colors, spacing, and overall visual quality of the sample
  • Why it matters: This is your chance to catch visual issues before the full PDF is generated
  • PM message: "Check layout and fonts. Generate full PDF? Approve?"

Optional Gates

Three gates are optional — the PM reviews the output and auto-advances unless there is a problem.

  • Gate 1.5 (Source Verification) — After source-verifier produces source-verification.md. The PM outputs the Trust Score and proceeds automatically. Halts only if Trust Score < 70%.
  • Gate 3 (Design Spec) — After the design agent produces design_spec.md. The PM outputs a summary of the theme and visual spec, then proceeds.
  • Gate 4 (HTML Draft) — After the html-build agent generates the HTML slide deck. The PM outputs built file details, then proceeds.
Gate 2 is the most important decision point. Approving Gate 2 triggers the design, image curation, diagram generation, HTML build, and PDF export stages. If you later want to change the content structure (for example, add a chapter, remove slides, or reorganize the flow), the PM will need to reset downstream stages and re-run them. Review the content carefully before approving.
Rework rules: If you request changes after a gate, the PM identifies which downstream stages need re-running, calls the version agent to snapshot current files, dispatches the appropriate specialist, and resets affected stages to "pending" in project_state.json. Stages whose output is unchanged (for example, research) are skipped.

How to Talk to the PM

Since the PM Agent is your single point of contact, knowing how to communicate effectively makes the entire process smoother. You interact with the PM through natural language in your Claude Code or Gemini CLI session.

Starting a New Presentation

To start a new presentation, simply tell the PM what you want to create. Here are some example prompts.

Example prompts for starting a presentation:
  • "Create a presentation about renewable energy for university students."
  • "Make a 20-slide lecture deck on machine learning basics for beginners."
  • "I need a presentation on climate change with lots of diagrams and data charts."
  • "Build a slide deck about the history of the internet for a high school audience."

Good vs. Bad Requests

The quality of your request affects the quality of the output. Here is a comparison to help you formulate effective requests.

Good Requests

  • "Create a presentation about renewable energy for university students. Include data charts showing growth trends."
  • "Make a 15-slide lecture on AI ethics for a general audience. Use the outline theme with premium-dark style."
  • "I want a presentation on space exploration with chapter dividers and speaker notes for each slide."

Requests That Need Improvement

  • "Make a presentation." — Too vague. The PM needs a topic and audience.
  • "Do the whole thing." — The PM needs specifics to dispatch the right agents.
  • "Make it look good." — Specify a theme and style, or let the PM suggest one based on your content.

Requesting Changes

After reviewing gate outputs, you can request changes in natural language. The PM will figure out which agents to re-dispatch and which stages to re-run.

Example prompts for requesting changes:
  • "The storyline has too many slides in Chapter 2. Merge some of them."
  • "Can you change the accent color to blue in the design spec?"
  • "I want to add a comparison diagram on slide 8."
  • "The sample PDF fonts look wrong. Can you re-measure?"
Tip: You do not need to know which agent handles your request. Just describe what you want changed, and the PM will figure out the rest. For example, saying "add more images to Chapter 3" automatically triggers the image-curator agent — you do not need to mention the agent by name.

Practice: Create a Mini Presentation

In this exercise, you will use co-deck to build a 5-slide mini presentation. The topic is "5 Core Concepts of Machine Learning" — a simple presentation aimed at beginners.

Practice Objectives

  • Clone the co-deck repository and set up the project
  • Send a request to the PM Agent from Claude Desktop App
  • Observe the 11-Stage pipeline in action
  • Experience the Gate 2 and Gate 5 approval process
  • Review the final outputs (HTML and PDF)

Prerequisites

Make sure the tools you installed in Chapter 3 are working correctly.

  1. Claude Desktop App — must be able to hold a conversation with Claude
  2. Git — must be able to clone repositories
  3. Browser — a browser that can open the HTML slide deck

Step-by-Step Walkthrough

  1. Clone the workspace and scaffold the project
    If you haven't already cloned the workspace in an earlier chapter, do that first, then scaffold a new project from the co-deck variant using new-project.ts.
    git clone https://github.com/5throck/ai-workspace-standards.git
    cd ai-workspace-standards
    bun scripts/new-project.ts "co-deck" --variant co-deck
    This creates Projects/co-deck/ as its own independent Git repository, with the co-deck variant's agents, skills, and configuration already copied in.
  2. Open the project in Claude Desktop App
    Launch Claude Desktop App and open the Projects/co-deck/ folder as a project. Start the PM by telling Claude the following.
    "Let's start a new project."
    The PM enters Stage 0 (project configuration) and asks about the topic, audience, theme, and style.
  3. Talk to the PM
    Answer the PM's questions to configure the project. Try responding like this.
    "Create a mini presentation about the 5 core concepts of machine learning. 5 slides. For beginners. In English."
    The PM analyzes your request and walks you through the configuration fields in lecture-profile.md (theme, style, source_verification, etc.).
  4. Stage 0 configuration (topic, audience, language)
    The PM confirms the following items. Beginners should stick with the defaults.
    • Rendering theme: pitch-enhanced (default)
    • Visual style: classic (default)
    • Source verification: true (default)
    • Divider mode: auto (default)
    Confirm all the settings and tell the PM to proceed.
  5. Approve Gate 2 (review slide content)
    Once Stage 1 (research) and Stage 2–3 (content) finish, the PM asks for your approval at Gate 2. Review slide_deck.md and check the following.
    • Is the slide structure logical?
    • Is the content of each slide accurate?
    • Are the cover slide and closing slide appropriate?
    After reviewing, respond like this.
    "I've reviewed the slide content. Please proceed to the next stage."
    If changes are needed, be specific.
    "Please explain slide 3's content in simpler terms."
  6. Approve Gate 5 (review the sample PDF)
    Once Stage 11 produces sample_5slides.pdf, the PM asks for your approval at Gate 5. In the sample PDF, check the following.
    • Do the fonts render correctly without breaking?
    • Is the layout well arranged?
    • Do the colors appear as intended?
    After reviewing, respond like this.
    "I've reviewed the sample PDF. Please generate the full PDF."
  7. Review the final outputs
    Once every stage is complete, you can find the final outputs in the presentations/<project>/ folder. The next section explains exactly how to review them.
Start with a short 5–10 slide presentation. A smaller deck lets the whole pipeline finish quickly so you can get a feel for how co-deck works. Once you are comfortable, try a full-scale 20–30+ slide lecture deck.
Note: co-deck's agents run through the Claude API. Claude's responses may slow down or time out during the exercise. Presentations with many images or diagrams can take longer — this is expected behavior.

Reviewing Outputs

After the pipeline completes, your presentation outputs live in the project directory. Let us look at where to find them and how to review each output type.

Output Locations

All outputs for your presentation are stored under presentations/<project-name>/. Here is the directory layout you will see after a complete pipeline run.

Projects/co-deck/presentations/<project-name>/
File / Directory Description
lecture-profile.md Your project configuration (topic, audience, theme, style)
research_notes.md Web research sources and key facts gathered by the research agent
storyline.md Narrative arc and chapter structure designed by the storyline agent
slide_deck.md Per-slide content: titles, bullets, speaker notes, image roles
design_spec.md Visual design: color palette, fonts, CSS variables
assets/images/ Downloaded commercial-use images + image-manifest.json
assets/diagrams/ Generated SVG diagrams + diagram-manifest.json
lecture_v1.html The final single-file HTML slide deck
<project>.pdf The final print-ready PDF
sample_5slides.pdf The 5-slide sample PDF used for Gate 5 review
project_state.json Pipeline progress tracker (status of each stage)

Opening and Reviewing Your Outputs

  1. Open the HTML slide deck. Navigate to presentations/<project-name>/lecture_v1.html and open it in your web browser. You should see your complete presentation with all slides, images, diagrams, and navigation. Try clicking through the slides, using keyboard arrows, and toggling the speaker notes panel.
  2. Test HTML features. Press F for fullscreen, T to open the table of contents, S to view speaker notes, and Escape to exit. These controls let you practice your presentation just like a real slide app.
  3. Open the PDF. Navigate to presentations/<project-name>/<project>.pdf and open it in your PDF viewer. Compare the PDF layout to the HTML version — they should match closely in colors, fonts, and spacing.
  4. Review intermediate files (optional). If you want to understand how the pipeline works, open research_notes.md to see what the research agent found, slide_deck.md to see the structured content, and design_spec.md to see the visual design decisions. These files give you full visibility into every decision the AI agents made.
Pro tip: The HTML slide deck is the primary deliverable. It is self-contained (no server required), supports interactive features like presenter mode and TTS narration, and works offline. The PDF is best for printing or sharing with people who prefer a static document. Use both: present from the HTML, distribute the PDF.
