Chapter 7

co-deck: AI Presentation in Practice

co-deck is a system in which an AI agent team produces presentations (lecture material, presentation slides). In this chapter you will understand co-deck's 11-Stage pipeline and actually build a mini presentation.

What This Chapter Covers
  • Introduction to the co-deck system and its architecture
  • Understanding the 11-Stage pipeline
  • Choosing a Theme and Style
  • Gate approvals (Gate 2: content, Gate 5: sample PDF)
  • Practice: creating a mini presentation
  • Checking the HTML and PDF outputs

What is co-deck

Definition

co-deck is a system in which an AI agent team produces presentations. It is one of the variants of ai-workspace-standards we explored in Chapter 5, where multiple AI agents cooperate to automatically generate high-quality presentations such as lecture material, business presentations, and talk slides.

Location: templates/co-deck/ inside ai-workspace-standards — scaffold your own copy with bun scripts/new-project.ts "<name>" --variant co-deck.

What Outputs Does It Create?

co-deck produces two kinds of output.

  • Single-file HTML slide deck — A self-contained web presentation with all slides, images, and styles packed into one HTML file. You can open it directly in a browser to present, and it supports responsive layout and interactive features.
  • PDF — PDF files for printing and distribution. Layouts, fonts, and colors are preserved, making them ideal for sharing and archiving.
Beginner's analogy: co-deck is a virtual "presentation production studio." The PM (project manager) meets with the client (you), and specialist agents carry out each phase (research, planning, design, production). It resembles the structure of a real design agency, where a planner leads designers, illustrators, and developers.

Difference from co-consult

If the co-consult you learned in Chapter 6 specializes in strategic analysis and report writing, co-deck specializes in producing presentation slides. Both systems are built on ai-workspace-standards, but their purposes and agent compositions differ.

co-deck

  • Presentation slide production
  • research, storyline, html-build, pdf-export, etc.
  • 11-Stage pipeline
  • Outputs: HTML slides + PDF

co-consult

  • Strategic consulting analysis and reports
  • research, data-analyst, market-analyst, strategy, etc.
  • PM-dispatched 7-phase consulting workflow (Phase 0–6)
  • Outputs: Analysis report HTML + PDF

System Architecture

Agent Composition

co-deck consists of one PM agent and ten specialist agents. The PM coordinates the entire project from the center, while the specialist agents each perform work in their own domain.

Roles of the Specialist Agents

The role of each specialist agent can be summarized as follows.

Agent Role Description
research Research specialist Gathers topic-related materials, statistics, and sources from the web and organizes them into research_notes.md
source-verifier Source verifier Verifies the URL accessibility of collected sources and whether their contents match, producing a Trust Score (optional)
storyline Storyliner Designs the overall structure and narrative of the slides based on the research results. Creates storyline.md and slide_deck.md
design Designer Decides visual styles such as colors, fonts, and layouts, and organizes them into design_spec.md
image-curator Image curator Searches and downloads commercial-use images from Pixabay, Unsplash, and Pexels (optional)
diagram-specialist Diagram specialist Generates concept diagrams and data charts as SVG (optional)
html-build HTML builder Builds a single-file HTML slide deck based on slide_deck.md and design_spec.md
measure Layout measurer Measures pixel positions, fonts, and colors of the HTML slides to collect layout information needed for PDF generation
pdf-export PDF exporter Creates the 5-page sample PDF and then the full PDF. Requires user approval at Gate 5
version Version manager Performs automatic backups before files are modified. Can also restore previous versions
The PM agent does not directly execute the specialist agents above. The PM only plays the orchestrator role: it analyzes the user's request and dispatches instructions to each specialist agent. See the PM Gateway section in Chapter 4.

11-Stage Pipeline

co-deck produces presentations by following a pipeline made of eleven Stages. Each Stage is handled by specific agents that emit defined deliverables. Between Stages there are approval points called Gates, letting the user review the content midway and adjust direction.

Stage 1.5, 3.5, and 4 are optional/automatic stages. The user approves only at Gate 2 (content approval) and Gate 5 (sample PDF approval). All remaining Stages proceed with the PM dispatching agents automatically.

Key Deliverables per Stage

  1. Stage 0 — Config (project setup)
    The PM meets the user and confirms the project's topic, target audience, language, Theme, and Style. This stage creates lecture-profile.md and project_state.json.
  2. Stage 1 — Research
    The research agent collects related materials, statistics, and sources via web search. Its output, research_notes.md, becomes the information base for the whole deck.
  3. Stage 1.5 — Source Verifier (source verification, optional)
    The source-verifier agent verifies URL accessibility and content consistency of the collected sources. It produces a Trust Score; below 70%, the project pauses.
  4. Stage 2-3 — Content (storyline + slide deck)
    Based on the research results, the storyline agent designs the deck's overall structure (storyline.md) and the per-slide content (slide_deck.md). At Gate 2 the user approves the slide content.
  5. Stage 4 — Design (design spec)
    The design agent decides visual styles — color palette, fonts, layout — and organizes them into design_spec.md.
  6. Stage 3.5 — Image Curation + Diagram Generation (parallel)
    image-curator and diagram-specialist run in parallel. They search/download images for the slides and generate SVG diagrams and charts.
  7. Stage 5-8 — HTML Build (creating the HTML slides)
    From slide_deck.md and design_spec.md, the html-build agent generates the single-file HTML slide deck (lecture_v1.html).
  8. Stage 9-10 — Layout Measure
    The measure agent measures pixel positions, fonts, and colors of the HTML slides, collecting the layout information required for PDF generation.
  9. Stage 11 — PDF Export (PDF generation)
    The pdf-export agent first creates a 5-page sample PDF. Once the user reviews and approves the sample at Gate 5, the full PDF is generated.

Themes and Styles

co-deck controls the look of a presentation through two concepts: Theme and Style. They can be chosen independently, but certain combinations are compatible with each other.

Theme — HTML Rendering Structure

A Theme determines the HTML rendering structure of the slides. Layout method, navigation structure, slide transition effects, how the TOC (table of contents) appears, and more vary by Theme.

The available Themes are:

Theme Paradigm Characteristics
pitch ppt-engine Traditional PPT style. Bottom footer bar, prev/next buttons, TOC drawer
pitch-enhanced ppt-presenter Advanced PPT style. Transition selection, script toggle, timer, TTS support
outline outline Outline format. TOC drawer + bottom bar, various slide types supported
vertical vertical-scroll Vertical scroll. Sticky top bar, auto advance, progress bar
zen zen Minimal style. TOC drawer + bottom bar, transition selection
outlook horizontal-scroll Horizontal scroll. Overlay TOC panel, autoplay support

Style — CSS Variable Set

A Style determines the CSS variable set of the slides. Color palette, fonts, spacing, background colors, and other visual styling differ by Style.

The available Styles are:

Style Characteristics
classic Clean light style. Bright background, dark text. Widest compatibility
minimal Minimal style. Bare decoration, focus on content
premium-dark Premium dark style. Dark background, bright text, polished feel
academic Academic style. Suited to educational presentations
visual-heavy Visual-first style. Suited to image-rich presentations

Theme × Style Compatibility

Not every Theme pairs with every Style. Follow the compatibility matrix defined in THEMES.md. The PM verifies compatibility automatically at Stage 0.

Theme (structure)

  • Determines HTML rendering structure
  • Layout method (PPT, vertical, horizontal, etc.)
  • Navigation structure
  • Slide transition effects
  • How the TOC is displayed
  • Files: template.html, theme.json, theme.css

Style (appearance)

  • Determines the CSS variable set
  • Color palette (light/dark)
  • Font families and sizes
  • Margins and spacing
  • Background and text colors
  • Files: style.css
Start with the default combination. The pitch-enhanced Theme + classic Style pairing is a stable combination that fits most presentations. Try other Themes and Styles once you're comfortable.

Gate Approvals

co-deck's pipeline includes approval points called Gates. A Gate is a "checkpoint" where the user reviews outputs midway and adjusts direction. Every Gate must be passed before moving to the next Stage.

Required Gates

The following two Gates are mandatory and require explicit user approval.

  1. Gate 2 (required) — Slide content approval
    When Stage 2-3 completes, storyline.md and slide_deck.md have been created. The PM requests approval like this:
    "⚠️ Approving will start design and HTML production. Do you approve?"
    Here you can review the overall slide structure, the content of each slide, the image plan, and the diagram plan. If changes are needed, adjust direction at this point.
  2. Gate 5 (required) — Sample PDF approval
    At Stage 11, the pdf-export agent first creates the 5-page sample_5slides.pdf. The PM requests approval like this:
    "Check the layout and fonts. Generate the full PDF?"
    In the sample PDF, check font rendering, layout placement, color reproduction, and so on. If anything looks wrong, request corrections.

Optional Gates

The following Gates are optional; the PM either proceeds automatically or after a review:

Gate Timing Reviewed content How it proceeds
Gate 1.5 After Stage 1.5 Trust Score in source-verification.md Prints the Trust Score and proceeds automatically if it is 70% or higher
Gate 3 After Stage 4 Theme/style summary in design_spec.md Prints the summary and proceeds automatically
Gate 4 After Stage 5-8 HTML slide deck file Prints the file info and proceeds automatically

Conditions for Passing a Gate

  • Gate 2: The user reviews the slide content (structure, per-slide text, image/diagram plans) and explicitly "approves." If changes are requested, those parts are revised and approval is requested again.
  • Gate 5: The user reviews the sample PDF's layout (fonts, margins, colors, placement) and explicitly "approves." If there are layout problems, they are fixed and approval is requested again.
  • Gate 1.5: Passes automatically when the Trust Score is 70% or higher. Below 70%, the project halts and the PM notifies the user.
Caution: Approving at Gate 2 kicks off heavy work (design, image search, HTML production, PDF generation). Be sure to review the slide contents thoroughly. If content changes after Gate 2, you may need to rerun from that stage onward.

How to Talk to the PM

To use co-deck, open the co-deck project in Claude Desktop App and send a request to the PM agent. An effective request greatly raises the quality of the presentation.

The Five Key Elements of a Request

A good request contains the following five elements.

  1. Topic — What is the presentation about?
  2. Audience — Who will see the presentation?
  3. Level — Beginner level or expert level?
  4. Volume — How many slides are needed?
  5. Language — Korean, English, or both?

Example Requests

Example 1: University lecture material
"Create lecture material for an Introduction to AI course. Undergraduate level, about 20 slides. In Korean."
Example 2: Company earnings briefing
"Create our company's Q3 earnings presentation. For investors. About 15 slides. In Korean."
Example 3: Technical seminar
"Create seminar material on cloud architecture basics. For new IT department hires, about 10 slides. In English."
Example 4: Simple mini presentation
"Create a mini presentation on five key machine learning concepts. 5 slides. For beginners. In Korean."

Good Requests vs Weak Requests

Good request

  • Clear topic: "Introduction to AI"
  • Specific audience: "undergraduates"
  • Level stated: "introductory level"
  • Volume given: "about 20 slides"
  • Language stated: "Korean"
  • The PM can dispatch agents right away

Weak request

  • Vague topic: "make me something"
  • No audience: unclear who will be presented to
  • Ambiguous level: unknown if it's for experts or beginners
  • No volume: cannot tell 5 slides from 50
  • No language: Korean or English unspecified
  • The PM must ask the user extra questions
Start with a simple topic. We recommend getting familiar with how co-deck works using a simple request like "machine learning basics, 5 slides, beginner audience, Korean."

Practice: Create a Mini Presentation

In this exercise you will use co-deck to create a 5-page mini presentation. The topic is "five key concepts of machine learning," simple material aimed at beginners.

Exercise Goals

  • Clone the workspace repository and set up the project
  • Send a request to the PM agent in Claude Desktop App
  • Observe the progress of the 11-Stage pipeline
  • Experience Gate 2 and Gate 5 approvals
  • Check the final outputs (HTML and PDF)

Prerequisites

Confirm that the tools installed in Chapter 3 are working properly.

  1. Claude Desktop App — must be able to converse with Claude AI
  2. Git — must be able to clone repositories
  3. Browser — a browser able to open the HTML slide deck

Exercise Steps

  1. Clone the workspace and scaffold the project
    If you haven't cloned the workspace in earlier chapters yet, clone it first, then scaffold a new project from the co-deck variant with new-project.ts.
    git clone https://github.com/5throck/ai-workspace-standards.git
    cd ai-workspace-standards
    bun scripts/new-project.ts "co-deck" --variant co-deck
    This command creates Projects/co-deck/ as an independent Git repository, already populated with the co-deck variant's agents, skills, and settings.
  2. Open the project in Claude Desktop App
    Launch Claude Desktop App and open the Projects/co-deck/ folder as a project. Tell Claude the following to start the PM:
    "I'd like to start a new project."
    The PM enters Stage 0 (project setup) and asks about topic, audience, Theme, Style, and so on.
  3. Make your request to the PM
    Answer the PM's questions to configure the project. Respond like this:
    "Create a mini presentation on the five key concepts of machine learning. 5 slides. For beginners. In Korean."
    The PM analyzes the request and walks you through the settings in lecture-profile.md (Theme, Style, source_verification, etc.).
  4. Stage 0 setup (topic, audience, language)
    The PM confirms the following items. Beginners should keep the recommended defaults:
    • Rendering theme: pitch-enhanced (default)
    • Visual style: classic (default)
    • Source verification: true (default)
    • Divider mode: auto (default)
    Confirm every setting and instruct the PM to proceed.
  5. Approve Gate 2 (reviewing slide content)
    When Stage 1 (research) and Stage 2-3 (content) finish, the PM requests approval at Gate 2. Open slide_deck.md and check the following:
    • Is the slide structure logical?
    • Is each slide's content accurate?
    • Are the cover slide and closing slide appropriate?
    After review, respond like this:
    "I've reviewed the slide content. Please continue to the next stage."
    If revisions are needed, say so concretely:
    "Explain slide 3 a little more simply."
  6. Approve Gate 5 (reviewing the sample PDF)
    When sample_5slides.pdf is created at Stage 11, the PM requests approval at Gate 5. Check the following in the sample PDF:
    • Do the fonts render properly without breaking?
    • Is the layout placement appropriate?
    • Are the colors expressed as intended?
    After review, respond like this:
    "Sample PDF looks good. Please generate the full PDF."
  7. Check the final outputs
    Once all Stages complete, you can find the final outputs in the presentations/<project>/ folder. The next section explains exactly how to inspect them.
Start with short decks of 5-10 pages. With fewer slides the whole pipeline finishes quickly, helping you grasp how co-deck works fast. After gaining experience, take on serious lecture material of 20-30 pages or more.
Caution: co-deck's agents operate through the Claude API. During exercises, Claude's response speed may slow down or time out occasionally. Complex presentations (many images or diagrams) can take longer — that is normal behavior.

Reviewing Outputs

When a co-deck project finishes, several kinds of outputs have been produced. This section explains where each one lives and how to inspect it.

Where the Outputs Are

All outputs are stored under the presentations/<project>/ directory. From the project root you reach them via the following path.

Projects/co-deck/presentations/<project-name>/

Main Deliverables

File Description Created in Stage
lecture-profile.md Project settings file (topic, audience, Theme, Style, etc.) Stage 0
project_state.json Project progress state (per-Stage completion, Gate approval status) Stage 0+
research_notes.md Organized materials, statistics, and sources gathered by web search Stage 1
source-verification.md Source credibility verification results and Trust Score (optional) Stage 1.5
storyline.md Overall structure and narrative design of the slides Stage 2-3
slide_deck.md Per-slide content (titles, text, image plan, diagram plan) Stage 2-3
design_spec.md Design spec (colors, fonts, layout CSS variables) Stage 4
image-manifest.json List and metadata of downloaded images (optional) Stage 3.5
diagram-manifest.json List and metadata of generated diagrams (optional) Stage 3.5
lecture_v1.html Single-file HTML slide deck (interactive, responsive) Stage 5-8
sample_5slides.pdf 5-page sample PDF (for Gate 5 approval) Stage 11
<project>.pdf Full PDF (generated after Gate 5 approval) Stage 11

Features of the HTML Slide Deck

lecture_v1.html is co-deck's core output. It has the following characteristics:

  • Single file: All slides, images (encoded), CSS, and JavaScript are contained in one HTML file. Send just the file and it opens anywhere.
  • Interactive: Supports slide transitions, keyboard navigation, a TOC drawer, presenter mode, TTS (text-to-speech), and more.
  • Responsive: Layout adjusts automatically to screen size. Usable on desktops and mobile alike.
  • Offline capable: Open it straight in a browser and present without any web connection.

Features of the PDF

<project>.pdf is the print-oriented output:

  • For printing: Layouts, fonts, and colors are preserved, well suited to printing on A4 or Letter paper.
  • For distribution: Easy to share over email or document-sharing platforms.
  • For archiving: When long-term preservation matters, PDF is the most stable format.

How to Open the Outputs

  1. Open the project folder
    Move to the project folder in a terminal.
    cd Projects/co-deck/presentations/<project-name>/
    ls
  2. Open the HTML slide deck
    Open lecture_v1.html in a browser. Try out slide transitions, the TOC, presenter mode, and more.
    # macOS
    open lecture_v1.html
    # Windows
    start lecture_v1.html
    # Linux
    xdg-open lecture_v1.html
  3. Open the PDF
    Open <project>.pdf in a PDF viewer and inspect the print layout. Compare whether fonts, margins, and colors match the HTML version.
  4. Check intermediate outputs
    Open slide_deck.md to examine the content structure of each slide. In research_notes.md you can see the materials the research agent collected.
    cat slide_deck.md
    cat research_notes.md
  5. Check project_state.json
    You can view the project's overall progress. Each Stage's completion status and Gate approval status are recorded here.
    cat project_state.json

Outputs can also be reviewed inside Claude Desktop App's chat screen. Files Claude created can be previewed during the conversation. Also, project_state.json lets you check in real time which Stage the project is currently in.
Ways to make use of the outputs: The finished HTML slide deck can be used immediately in meetings or lectures. The PDF suits sharing with teammates or distributing as lecture material. Combined with the analysis report from co-consult (Chapter 6), you can even build a presentation grounded in the analysis itself.
