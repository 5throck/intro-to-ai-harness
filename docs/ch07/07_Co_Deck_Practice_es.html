Capítulo 7

co-deck: presentaciones con IA en la práctica

co-deck es el sistema con el que un equipo de agentes de IA produce presentaciones (material docente, diapositivas de exposición). En este capítulo comprenderás el pipeline de 11 etapas (Stage) de co-deck y crearás realmente una minipresentación.

Lo que trata este capítulo
  • Presentación del sistema co-deck y su arquitectura
  • Comprensión del pipeline de 11 etapas
  • Elección del Theme y el Style
  • Aprobaciones Gate (Gate 2: contenido, Gate 5: PDF de muestra)
  • Práctica: crear una minipresentación
  • Comprobación de los resultados en HTML y PDF

Qué es co-deck

Definición

co-deck es un sistema en el que un equipo de agentes de IA produce presentaciones. Es una de las variantes de ai-workspace-standards que exploramos en el capítulo 5: varios agentes de IA colaboran para generar automáticamente presentaciones de alta calidad, como material docente, exposiciones de empresa o diapositivas de conferencia.

Ubicación: templates/co-deck/ dentro de ai-workspace-standards — genera tu propia copia con bun scripts/new-project.ts "<name>" --variant co-deck.

¿Qué resultados produce?

co-deck genera dos formas de resultado:

  • Mazo de diapositivas HTML en un único archivo — Una presentación web autosuficiente con todas las diapositivas, imágenes y estilos incluidos en un solo archivo HTML. Se abre directamente en el navegador para exponer, y admite diseño adaptable y funciones interactivas.
  • PDF — Archivos PDF para impresión y distribución. Conservan el diseño, las fuentes y los colores, por lo que resultan ideales para compartir y archivar.
Analogía para principiantes: co-deck es una «productora de presentaciones» virtual. El PM (project manager) se reúne con el cliente (el usuario), y los agentes especialistas se encargan de cada fase (investigación, planificación, diseño, producción). Es parecido a la estructura de una agencia de diseño real, donde un planificador dirige a diseñadores, ilustradores y desarrolladores.

Diferencias con co-consult

Si co-consult, visto en el capítulo 6, está especializado en análisis estratégico y redacción de informes, co-deck está especializado en la producción de diapositivas de presentación. Ambos sistemas se apoyan en ai-workspace-standards, pero difieren en propósito y composición de agentes.

co-deck

  • Producción de diapositivas de presentación
  • research, storyline, html-build, pdf-export, etc.
  • Pipeline de 11 etapas (Stage)
  • Resultados: diapositivas HTML + PDF

co-consult

  • Análisis estratégico e informes de consultoría
  • research, data-analyst, market-analyst, strategy, etc.
  • Flujo de consultoría de 7 fases despachadas por el PM (Phase 0–6)
  • Resultados: informe HTML + PDF

Arquitectura del sistema

Composición de agentes

co-deck se compone de un agente PM y diez agentes especialistas. El PM coordina todo el proyecto desde el centro, mientras que cada agente especialista realiza el trabajo de su ámbito.

Roles de los agentes especialistas

El rol de cada agente especialista se resume así:

Agente Rol Descripción
research Especialista en investigación Recopila materiales, estadísticas y fuentes sobre el tema desde la web y los organiza en research_notes.md
source-verifier Verificador de fuentes Verifica la accesibilidad de las URL de las fuentes recopiladas y si su contenido coincide, produciendo una puntuación de confianza (Trust Score) (opcional)
storyline Storyliner Diseña la estructura general y la narrativa de las diapositivas a partir de los resultados de investigación. Crea storyline.md y slide_deck.md
design Diseñador Decide el estilo visual — colores, fuentes, maquetación — y lo organiza en design_spec.md
image-curator Curator de imágenes Busca y descarga imágenes de uso comercial en Pixabay, Unsplash y Pexels (opcional)
diagram-specialist Especialista en diagramas Genera diagramas conceptuales y gráficos de datos en formato SVG (opcional)
html-build Constructor HTML A partir de slide_deck.md y design_spec.md, genera el mazo de diapositivas HTML en un único archivo
measure Medidor de maquetación Mide coordenadas de píxeles, fuentes y colores de las diapositivas HTML para reunir la información de maquetación necesaria para generar el PDF
pdf-export Exportador PDF Genera primero el PDF de muestra de 5 páginas y después el PDF completo. Requiere aprobación del usuario en el Gate 5
version Gestor de versiones Realiza copias de seguridad automáticas antes de modificar archivos. También puede restaurar versiones anteriores
El agente PM no ejecuta directamente los agentes especialistas anteriores. El PM solo ejerce de orquestador: analiza la petición del usuario y despacha instrucciones a cada agente especialista. Consulta la sección PM Gateway del capítulo 4.

Pipeline de 11 etapas

co-deck produce presentaciones siguiendo un pipeline compuesto por once etapas (Stage). Cada etapa tiene agentes asignados que emiten entregables definidos. Entre etapas hay puntos de aprobación llamados Gate, que permiten al usuario revisar el contenido a mitad de camino y corregir el rumbo.

Las etapas 1.5, 3.5 y 4 son opcionales/automáticas. El usuario solo aprueba en el Gate 2 (aprobación del contenido) y en el Gate 5 (aprobación del PDF de muestra). Las demás etapas avanzan con el PM despachando agentes automáticamente.

Entregables clave por etapa

  1. Stage 0 — Config (configuración del proyecto)
    El PM se reúne con el usuario y confirma el tema, el público destinatario, el idioma, el Theme y el Style del proyecto. En esta etapa se crean lecture-profile.md y project_state.json.
  2. Stage 1 — Research (investigación)
    El agente research reúne materiales, estadísticas y fuentes relacionadas mediante búsquedas web. Su resultado, research_notes.md, será la base informativa de todo el mazo.
  3. Stage 1.5 — Source Verifier (verificación de fuentes, opcional)
    El agente source-verifier verifica la accesibilidad de las URL y la coincidencia de contenido de las fuentes recopiladas. Produce un Trust Score; si queda por debajo del 70%, el proyecto se detiene temporalmente.
  4. Stage 2-3 — Content (storyline + mazo de diapositivas)
    A partir de los resultados de investigación, el agente storyline diseña la estructura global (storyline.md) y el contenido por diapositiva (slide_deck.md). En el Gate 2 el usuario aprueba el contenido de las diapositivas.
  5. Stage 4 — Design (especificación de diseño)
    El agente design decide el estilo visual — paleta de colores, fuentes, maquetación — y lo organiza en design_spec.md.
  6. Stage 3.5 — Image Curation + Diagram Generation (en paralelo)
    image-curator y diagram-specialist se ejecutan en paralelo. Buscan y descargan las imágenes para las diapositivas y generan diagramas y gráficos SVG.
  7. Stage 5-8 — HTML Build (generación de las diapositivas HTML)
    Con slide_deck.md y design_spec.md, el agente html-build genera el mazo de diapositivas HTML en un único archivo (lecture_v1.html).
  8. Stage 9-10 — Layout Measure (medición de maquetación)
    El agente measure mide coordenadas de píxeles, fuentes y colores de las diapositivas HTML y reúne la información de maquetación necesaria para generar el PDF.
  9. Stage 11 — PDF Export (generación del PDF)
    El agente pdf-export genera primero el PDF de muestra de 5 páginas. Cuando el usuario lo revisa y lo aprueba en el Gate 5, se genera el PDF completo.

Theme y Style

co-deck controla el aspecto de la presentación mediante dos conceptos: Theme y Style. Pueden elegirse de forma independiente, pero existen combinaciones compatibles entre sí.

Theme — estructura de renderizado HTML

Un Theme determina la estructura de renderizado HTML de las diapositivas. El método de maquetación, la estructura de navegación, los efectos de transición, cómo se muestra el índice (TOC), etc., varían según el Theme.

Los Themes disponibles son:

Theme Paradigma Características
pitch ppt-engine Estilo PPT tradicional. Barra de pie inferior, botones anterior/siguiente, cajón de TOC
pitch-enhanced ppt-presenter Estilo PPT avanzado. Selección de transiciones, guion desplegable, temporizador, soporte TTS
outline outline Formato de esquema. Cajón de TOC + barra inferior, varios tipos de diapositiva
vertical vertical-scroll Desplazamiento vertical. Barra superior fija, avance automático, barra de progreso
zen zen Estilo minimalista. Cajón de TOC + barra inferior, selección de transiciones
outlook horizontal-scroll Desplazamiento horizontal. Panel superpuesto de TOC, reproducción automática

Style — conjunto de variables CSS

Un Style determina el conjunto de variables CSS de las diapositivas. La paleta de colores, las fuentes, los márgenes, los colores de fondo y demás estilo visual cambian según el Style.

Los Styles disponibles son:

Style Características
classic Estilo claro y limpio. Fondo luminoso, texto oscuro. La mayor compatibilidad
minimal Estilo minimalista. Decoración mínima, centrado en el contenido
premium-dark Estilo oscuro premium. Fondo oscuro, texto claro, acabado refinado
academic Estilo académico. Adecuado para presentaciones educativas
visual-heavy Estilo centrado en lo visual. Adecuado para presentaciones con muchas imágenes

Compatibilidad Theme × Style

No todos los Theme combinan con todos los Style. Hay que seguir la matriz de compatibilidad definida en THEMES.md. El PM comprueba la compatibilidad automáticamente en el Stage 0.

Theme (estructura)

  • Determina la estructura de renderizado HTML
  • Método de maquetación (PPT, vertical, horizontal, etc.)
  • Estructura de navegación
  • Efectos de transición de diapositivas
  • Modo de mostrar el TOC
  • Archivos: template.html, theme.json, theme.css

Style (apariencia)

  • Determina el conjunto de variables CSS
  • Paleta de colores (clara/oscura)
  • Familias y tamaños tipográficos
  • Márgenes y espaciados
  • Colores de fondo y de texto
  • Archivo: style.css
Empieza con la combinación predeterminada. El Theme pitch-enhanced + el Style classic forman una pareja estable que encaja con la mayoría de las presentaciones. Prueba otros Themes y Styles cuando ya tengas soltura.

Aprobaciones Gate

El pipeline de co-deck incluye puntos de aprobación llamados Gate. Un Gate es un «checkpoint» donde el usuario revisa los resultados a mitad de camino y corrige el rumbo. Hay que pasar todos los Gate para avanzar a la siguiente etapa.

Gates obligatorios

Los dos siguientes Gates son obligatorios y exigen aprobación explícita del usuario.

  1. Gate 2 (obligatorio) — aprobación del contenido de las diapositivas
    Al terminar el Stage 2-3 se han creado storyline.md y slide_deck.md. El PM solicita la aprobación así:
    «⚠️ Si apruebas, comenzarán el diseño y la producción del HTML. ¿Apruebas?»
    En este punto puedes revisar la estructura general de las diapositivas, el contenido de cada una, el plan de imágenes y el plan de diagramas. Si hay que cambiar algo, ajusta el rumbo aquí.
  2. Gate 5 (obligatorio) — aprobación del PDF de muestra
    En el Stage 11, el agente pdf-export crea primero el sample_5slides.pdf de 5 páginas. El PM solicita la aprobación así:
    «Revisa la maquetación y las fuentes. ¿Genero el PDF completo?»
    En el PDF de muestra comprueba el renderizado de fuentes, la colocación del diseño, la reproducción de colores, etc. Si algo falla, pide correcciones.

Gates opcionales

Los siguientes Gates son opcionales; el PM avanza automáticamente o tras una revisión:

Gate Momento Contenido revisado Forma de avanzar
Gate 1.5 Tras el Stage 1.5 Trust Score de source-verification.md Muestra el Trust Score y avanza automáticamente si es del 70% o más
Gate 3 Tras el Stage 4 Resumen de tema/estilo de design_spec.md Muestra el resumen y avanza automáticamente
Gate 4 Tras el Stage 5-8 Archivo del mazo de diapositivas HTML Muestra la información del archivo y avanza automáticamente

Condiciones para superar un Gate

  • Gate 2: el usuario revisa el contenido de las diapositivas (estructura, textos de cada una, planes de imagen/diagramas) y «aprueba» explícitamente. Si pide cambios, esas partes se corrigen y se vuelve a solicitar la aprobación.
  • Gate 5: el usuario revisa la maquetación del PDF de muestra (fuentes, márgenes, colores, colocación) y «aprueba» explícitamente. Si hay problemas de maquetación, se corrigen y se vuelve a pedir la aprobación.
  • Gate 1.5: se supera automáticamente si el Trust Score es del 70% o más. Por debajo del 70%, el proyecto se detiene y el PM avisa al usuario.
Atención: aprobar en el Gate 2 pone en marcha trabajo pesado (diseño, búsqueda de imágenes, producción HTML, generación del PDF). Revisa muy bien el contenido de las diapositivas. Si cambias el contenido después del Gate 2, puede que haya que reejecutar desde esa fase.

Cómo hablarle al PM

Para usar co-deck, abre el proyecto co-deck en Claude Desktop App y envía una petición al agente PM. Una petición eficaz eleva mucho la calidad de la presentación.

Los cinco elementos clave de una petición

Una buena petición contiene estos cinco elementos.

  1. Tema (Topic) — ¿Sobre qué trata la presentación?
  2. Público (Audience) — ¿Para quién es la presentación?
  3. Nivel (Level) — ¿Nivel principiante o nivel experto?
  4. Extensión (Volume) — ¿Cuántas diapositivas hacen falta?
  5. Idioma (Language) — ¿Coreano, inglés o ambos?

Ejemplos de peticiones

Ejemplo 1: material docente universitario
«Prepárame el material de la asignatura Introducción a la IA. Nivel universitario, unas 20 diapositivas. En coreano.»
Ejemplo 2: presentación de resultados trimestrales
«Prepárame la presentación de resultados Q3 de nuestra empresa. Para inversores. Unas 15 diapositivas. En coreano.»
Ejemplo 3: seminario técnico
«Prepárame el material de un seminario básico de arquitectura cloud. Para personal nuevo del departamento de TI, unas 10 diapositivas. En inglés.»
Ejemplo 4: minipresentación sencilla
«Prepárame una minipresentación sobre los 5 conceptos clave del machine learning. 5 diapositivas. Para principiantes. En coreano.»

Buenas peticiones vs. peticiones flojas

Buena petición

  • Tema claro: «Introducción a la IA»
  • Público concreto: «estudiantes universitarios»
  • Nivel declarado: «nivel introductorio»
  • Extensión indicada: «unas 20 diapositivas»
  • Idioma declarado: «coreano»
  • El PM puede despachar agentes de inmediato

Petición floja

  • Tema vago: «hazme algo»
  • Sin público: no se sabe ante quién se expondrá
  • Nivel ambiguo: no se sabe si es para expertos o principiantes
  • Sin extensión: imposible distinguir 5 de 50 diapositivas
  • Sin idioma: coreano o inglés sin especificar
  • El PM tiene que hacer preguntas adicionales al usuario
Empieza con un tema sencillo. Recomendamos familiarizarte con el funcionamiento de co-deck mediante una petición simple como «conceptos básicos de machine learning, 5 diapositivas, para principiantes, en coreano».

Práctica: crear una minipresentación

En este ejercicio usarás co-deck para crear una minipresentación de 5 páginas. El tema es «los 5 conceptos clave del machine learning», un material sencillo dirigido a principiantes.

Objetivos del ejercicio

  • Clonar el repositorio del workspace y configurar el proyecto
  • Enviar una petición al agente PM desde Claude Desktop App
  • Observar el avance del pipeline de 11 etapas
  • Experimentar las aprobaciones del Gate 2 y del Gate 5
  • Comprobar los resultados finales (HTML y PDF)

Requisitos previos

Comprueba que las herramientas instaladas en el capítulo 3 funcionan correctamente.

  1. Claude Desktop App — debe poder conversar con Claude AI
  2. Git — debe poder clonar repositorios
  3. Navegador — un navegador capaz de abrir el mazo de diapositivas HTML

Pasos del ejercicio

  1. Clonar el workspace y generar el proyecto
    Si todavía no has clonado el workspace en capítulos anteriores, clónalo primero; después, genera un proyecto nuevo desde la variante co-deck con new-project.ts.
    git clone https://github.com/5throck/ai-workspace-standards.git
    cd ai-workspace-standards
    bun scripts/new-project.ts "co-deck" --variant co-deck
    Este comando crea Projects/co-deck/ como repositorio Git independiente, ya poblado con los agentes, skills y configuraciones de la variante co-deck.
  2. Abrir el proyecto en Claude Desktop App
    Inicia Claude Desktop App y abre la carpeta Projects/co-deck/ como proyecto. Dile a Claude lo siguiente para arrancar el PM:
    «Quiero empezar un proyecto nuevo.»
    El PM entra en el Stage 0 (configuración del proyecto) y pregunta por el tema, el público, el Theme, el Style, etc.
  3. Hacer la petición al PM
    Responde a las preguntas del PM para configurar el proyecto. Contesta así:
    «Prepárame una minipresentación sobre los 5 conceptos clave del machine learning. 5 diapositivas. Para principiantes. En coreano.»
    El PM analiza la petición y te guía por los ajustes de lecture-profile.md (Theme, Style, source_verification, etc.).
  4. Configuración del Stage 0 (tema, público, idioma)
    El PM confirma los siguientes elementos. A los principiantes les recomendamos mantener los valores predeterminados:
    • Rendering theme: pitch-enhanced (predeterminado)
    • Visual style: classic (predeterminado)
    • Source verification: true (predeterminado)
    • Divider mode: auto (predeterminado)
    Confirma todos los ajustes e indica al PM que continúe.
  5. Aprobar el Gate 2 (revisar el contenido de las diapositivas)
    Cuando terminan el Stage 1 (investigación) y el Stage 2-3 (contenido), el PM solicita la aprobación en el Gate 2. Abre slide_deck.md y comprueba lo siguiente:
    • ¿La estructura de las diapositivas es lógica?
    • ¿El contenido de cada diapositiva es correcto?
    • ¿La portada y la diapositiva de cierre son adecuadas?
    Tras la revisión, contesta así:
    «He revisado el contenido de las diapositivas. Continúa con la siguiente fase.»
    Si necesitas cambios, indícalos con concreción:
    «Explica la diapositiva 3 de forma más sencilla.»
  6. Aprobar el Gate 5 (revisar el PDF de muestra)
    Cuando se genere el sample_5slides.pdf en el Stage 11, el PM solicitará la aprobación en el Gate 5. Comprueba esto en el PDF de muestra:
    • ¿Las fuentes se ven bien y sin romperse?
    • ¿La colocación de la maquetación es adecuada?
    • ¿Los colores se reproducen tal como estaban pensados?
    Tras la revisión, contesta así:
    «El PDF de muestra está bien. Genera el PDF completo.»
  7. Comprobar los resultados finales
    Cuando todas las etapas terminen, encontrarás los resultados finales en la carpeta presentations/<project>/. La sección siguiente explica exactamente cómo inspeccionarlos.
Empieza con presentaciones cortas de 5-10 páginas. Con menos diapositivas el pipeline completo termina pronto y entenderás rápido cómo funciona co-deck. Cuando ganes experiencia, atrévete con material docente serio de 20-30 páginas o más.
Atención: los agentes de co-deck funcionan a través de la API de Claude. Durante el ejercicio, la velocidad de respuesta de Claude puede bajar u ocasionales tiempos de espera agotados. Las presentaciones complejas (con muchas imágenes o diagramas) tardan más — es un comportamiento normal.

Revisión de los resultados

Cuando el proyecto co-deck termina, se han generado varios tipos de resultado. Esta sección explica dónde está cada uno y cómo examinarlo.

Dónde están los resultados

Todos los resultados se guardan en el directorio presentations/<project>/. Desde la raíz del proyecto se accede por la ruta siguiente.

Projects/co-deck/presentations/<project-name>/

Entregables principales

Archivo Descripción Etapa que lo genera
lecture-profile.md Archivo de configuración del proyecto (tema, público, Theme, Style, etc.) Stage 0
project_state.json Estado de avance del proyecto (finalización por etapa, estado de aprobación de los Gate) Stage 0+
research_notes.md Organización de los materiales, estadísticas y fuentes recogidas por búsqueda web Stage 1
source-verification.md Resultado de la verificación de credibilidad de fuentes y Trust Score (opcional) Stage 1.5
storyline.md Estructura global y diseño narrativo de las diapositivas Stage 2-3
slide_deck.md Contenido por diapositiva (títulos, texto, plan de imágenes, plan de diagramas) Stage 2-3
design_spec.md Especificación de diseño (colores, fuentes, variables CSS de maquetación) Stage 4
image-manifest.json Lista y metadatos de las imágenes descargadas (opcional) Stage 3.5
diagram-manifest.json Lista y metadatos de los diagramas generados (opcional) Stage 3.5
lecture_v1.html Mazo de diapositivas HTML en un único archivo (interactivo, adaptable) Stage 5-8
sample_5slides.pdf PDF de muestra de 5 páginas (para aprobar en el Gate 5) Stage 11
<project>.pdf PDF completo (generado tras la aprobación del Gate 5) Stage 11

Rasgos del mazo de diapositivas HTML

lecture_v1.html es el resultado central de co-deck. Tiene estas características:

  • Un solo archivo: todas las diapositivas, imágenes (codificadas), CSS y JavaScript van dentro de un único archivo HTML. Basta enviar ese archivo para abrirlo en cualquier sitio.
  • Interactivo: admite transiciones de diapositivas, navegación con teclado, cajón de índice (TOC), modo presentador, TTS (texto a voz) y más.
  • Adaptable: la maquetación se ajusta automáticamente al tamaño de pantalla. Sirve tanto en escritorio como en móvil.
  • Sin conexión: ábrelo directamente en el navegador y presenta sin conexión a internet.

Rasgos del PDF

<project>.pdf es el resultado orientado a impresión:

  • Para imprimir: conserva maquetación, fuentes y colores; ideal para imprimir en papel A4 o Letter.
  • Para distribuir: fácil de compartir por correo o plataformas de documentos.
  • Para archivar: para conservación a largo plazo, el formato PDF es el más estable.

Cómo abrir los resultados

  1. Abrir la carpeta del proyecto
    Muévete a la carpeta del proyecto en la terminal.
    cd Projects/co-deck/presentations/<project-name>/
    ls
  2. Abrir el mazo de diapositivas HTML
    Abre lecture_v1.html en el navegador. Prueba las transiciones, el TOC, el modo presentador y más.
    # macOS
    open lecture_v1.html
    # Windows
    start lecture_v1.html
    # Linux
    xdg-open lecture_v1.html
  3. Abrir el PDF
    Abre <project>.pdf en un visor de PDF y examina la maquetación de impresión. Compara si fuentes, márgenes y colores coinciden con la versión HTML.
  4. Revisar los entregables intermedios
    Abre slide_deck.md para estudiar la estructura de contenido de cada diapositiva. En research_notes.md puedes ver los materiales que reunió el agente de investigación.
    cat slide_deck.md
    cat research_notes.md
  5. Consultar project_state.json
    Puedes ver el avance global del proyecto. Ahí quedan registrados el estado de finalización de cada etapa y las aprobaciones de los Gate.
    cat project_state.json
