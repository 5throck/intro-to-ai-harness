Capítulo 7

co-deck: AI Presentation in Practice

co-deck es un sistema donde los equipos de agents de IA producen presentaciones (materiales de clase, presentaciones de diapositivas). Este capítulo cubre el pipeline de 11 etapas y te guía en la creación de una mini presentación.

Lo que cubre este capítulo
  • co-deck system introduction and architecture
  • 11-Stage pipeline
  • Theme and Style selection
  • Gate approvals (Gate 2: content, Gate 5: sample PDF)
  • Practice: create a mini presentation
  • HTML and PDF output review

What is co-deck

Definition

co-deck es una variante del ecosistema ai-workspace-standards especializada en producir lecture materials and presentation slide decks. Es un proyecto variante L2 que hereda la estructura común del workspace (agents, skills, reglas de gobernanza) y añade sus propios agents especializados y un pipeline de producción de 11 etapas.

El nombre "co-deck" significa collaborative deck — una presentación producida mediante la colaboración entre un presentador humano y un equipo de agents de IA.

What co-deck Produces

co-deck produces two primary output types:

Single-File HTML Slide Deck

  • Un archivo .html autónomo con todas las diapositivas, CSS, imágenes y JavaScript incrustados
  • Open in any browser — no installation required
  • Supports presenter mode, TTS narration, keyboard navigation, and fullscreen
  • Five HTML themes available (outline, vertical, pitch-enhanced, outlook, zen)

Print-Ready PDF

  • A pixel-perfect PDF suitable for printing or distribution
  • 16:9 aspect ratio, matched to the HTML layout
  • Generado a partir de los mismos datos de diapositivas que la versión HTML
  • PDF de muestra (5 diapositivas) para revisión, luego exportación del PDF completo tras la aprobación

The Presentation Production Company Analogy

Imagina que diriges una presentation production company. Tú eres el productor ejecutivo (el humano) y tienes un equipo de especialistas trabajando bajo un gestor de proyecto. Así se mapea la analogía:

Presentation Company

  • Executive Producer (you) — defines the topic, reviews drafts, gives final approval
  • Project Manager — orchestrates the team, schedules tasks, enforces quality
  • Research Team — gathers sources and fact-checks
  • Content Writer — structures the narrative and writes slide content
  • Art Director — picks colors, fonts, and visual style
  • Photographer — finds and downloads images
  • Graphics Team — creates diagrams and charts
  • Web Developer — builds the HTML slide deck
  • Print Specialist — produces the final PDF

co-deck

  • Tú (el usuario) — proporciona el tema, revisa el contenido en el Gate 2, aprueba el PDF en el Gate 5
  • PM Agent — orchestrates all specialist agents, manages pipeline stages
  • research + source-verifier — web research and URL validation
  • storyline — creates storyline.md and slide_deck.md
  • design — writes design_spec.md with color palette and fonts
  • image-curator — searches Pixabay, Unsplash, Pexels for images
  • diagram-specialist — generates SVG diagrams and data charts
  • html-build — generates the single-file HTML slide deck
  • pdf-export — produces sample and full PDF output
El control de versiones está integrado. El agent version actúa como el gestor del archivo documental de una empresa — toma una instantánea de cada archivo antes de cualquier cambio, de modo que siempre puedas revertir a un estado anterior. Piénsalo como un "Guardar como" automático antes de cada edición.

System Architecture

La arquitectura de co-deck sigue el PM + Specialist Agent pattern de ai-workspace-standards. El Agent PM actúa como orquestador central, y un equipo de agents especializados maneja cada aspecto de la producción de la presentación.

Agent Roles Table

Agent Tier Stage Role
PM High 0 – 11 Orchestrates the entire pipeline, dispatches specialists, enforces gates
research Medium 1 Gathers web sources and writes research_notes.md
source-verifier Medium 1.5 Validates URLs and produces source-verification.md with Trust Score
storyline Medium 2 – 3 Writes storyline.md and slide_deck.md
design Medium 4 Locks visual design — color palette, fonts, layout into design_spec.md
image-curator Medium 3.5 Searches and downloads commercial-use images to assets/images/
diagram-specialist Medium 3.5 Generates SVG concept diagrams and data charts to assets/diagrams/
html-build Medium 5 – 8 Generates the single-file HTML slide deck from slide_deck.md
measure Medium 9 – 10 Auto-measures HTML layout with Playwright, downloads TTF fonts for PDF
pdf-export Medium 11 Generates sample and full PDF from slide data
version Low 0 – 11 Snapshots files before every edit; restores prior states on demand

Agent Composition Diagram

El diagrama de abajo muestra cómo el Agent PM se sitúa en el centro, despachando a los agents especializados para cada etapa del pipeline. El agent version se ejecuta en paralelo como una preocupación transversal.

El usuario solo habla con el PM. Nunca instruyes directamente a los agents especializados. Le dices al PM lo que quieres (por ejemplo, "haz una presentación sobre el cambio climático"), y el PM despacha a los agents adecuados en el orden correcto. Este es el patrón PM Gateway que aprendimos en el Capítulo 4.

11-Stage Pipeline

El pipeline de co-deck consta de 11 stages, cada una manejada por un agent especialista específico (o por el PM directamente). Las etapas se ejecutan secuencialmente, con algunos gates de revisión opcionales en el camino. Aquí tienes un recorrido detallado de cada etapa.

Stage 0 — Config (Mandatory)

El PM lee el docs/lecture-profile.md maestro, lo copia a presentations/<name>/lecture-profile.md y te pide que completes los detalles específicos de la clase: title, audience, level, keywords. También debes confirmar el rendering theme, visual style, si source verification está habilitado, divider mode y las preferencias background image. El PM inicializa project_state.json y memory/keywords.md.

Stage 1 — Research

El research agent realiza investigación web sobre el tema (en coreano e inglés si es necesario), recopilando fuentes y escribiendo research_notes.md con secciones para fuentes, hechos clave y notas de credibilidad. Esto se convierte en la base de conocimiento de toda la presentación.

Stage 1.5 — Source Verification (Optional)

Si la verificación de fuentes está habilitada (el valor predeterminado), el source-verifier agent valida cada URL de research_notes.md mediante comprobación HTTP y verificación cruzada de contenido, produciendo source-verification.md con un Trust Score. El pipeline se detiene solo si el Trust Score cae por debajo del 70%.

Stage 2 – 3 — Content (Storyline + Slide Deck)

El storyline agent diseña el arco narrativo y escribe storyline.md, luego compone slide_deck.md con contenido por diapositiva que incluye títulos, viñetas, notas del orador y campos de rol/consulta de imagen para cada diapositiva.

Stage 4 — Design

El design agent fija el estilo de diseño visual: paleta de colores, familias de fuentes, espaciado y reglas de disposición. Produce design_spec.md con todas las variables CSS y decisiones tipográficas.

Stage 3.5 — Image Curation + Diagram Generation

Los agents image-curator y diagram-specialist se ejecutan en paralelo. Image-curator busca imágenes de uso comercial en Pixabay, Unsplash y Pexels. Diagram-specialist genera diagramas conceptuales SVG y gráficos de datos. Ambos producen archivos manifiesto (image-manifest.json y diagram-manifest.json).

Stage 5 – 8 — HTML Build

El html-build agent genera la presentación HTML de archivo único combinando el contenido de slide_deck.md con la plantilla de tema seleccionada, la especificación de diseño, las imágenes y los diagramas. El resultado es un archivo .html autónomo que funciona en cualquier navegador.

Stage 9 – 10 — Layout Measure

El measure agent usa Playwright para medir automáticamente las diapositivas HTML renderizadas, extrayendo coordenadas de píxeles, fuentes y colores para una generación precisa del PDF. También descarga las fuentes TTF necesarias.

Stage 11 — PDF Export

El pdf-export agent primero genera un sample PDF (5 diapositivas) para tu revisión. Una vez que lo apruebas, genera el full PDF a partir de los datos completos de las diapositivas.

Pipeline Flow Diagram

Gates Obligatorios vs. Opcionales: Solo Gate 2 (aprobación del contenido) y Gate 5 (aprobación del PDF de muestra) requieren tu aprobación explícita. Los Gates 1.5, 3 y 4 son opcionales — el PM puede avanzar automáticamente tras una breve revisión. El pipeline se detiene en el Gate 1.5 solo si el Trust Score cae por debajo del 70%.

Themes and Styles

Una de las características más poderosas de co-deck es la separación de themes y styles. Estos dos conceptos trabajan juntos para darte control total sobre el aspecto de tu presentación, sin tocar una sola línea de código.

Theme vs. Style

Theme (Rendering Paradigm)

  • What: El motor de renderizado HTML y la estructura de las diapositivas
  • Controls: Cómo se disponen las diapositivas, el comportamiento de la navegación, los efectos de transición, la estructura del TOC
  • Examples: outline (vertical outline), vertical (scroll-based), pitch-enhanced (PPT-style), outlook (horizontal scroll), zen (minimal zen)
  • Packaged as: 4 files — template.html, theme.json, theme.css, pdf_layout_spec.json
  • Analogía: El floor plan de una casa — determina la forma y el flujo de las habitaciones

Style (Visual Appearance)

  • What: El conjunto de variables CSS que define colores, fuentes y ambiente visual
  • Controls: Background color, text color, accent color, heading fonts, border styles, shadows, and other visual properties
  • Examples: classic (light, professional), premium-dark (dark, sleek), minimal (ultra-clean), academic (scholarly), visual-heavy (image-forward)
  • Packaged as: Single style.css file defining CSS variable overrides
  • Analogía: El interior design de una casa — mismo plano, aspecto y sensación completamente diferentes

Compatibility Matrix

No todos los estilos funcionan con todos los temas. Cada tema declara sus compatible styles en theme.json. Por ejemplo, el tema pitch solo soporta classic, minimal y premium-dark, mientras que el tema outline soporta los cinco estilos.

La matriz de compatibilidad está documentada en docs/html-themes/THEMES.md y la aplica el PM en el Stage 0. Si intentas combinar un tema y un estilo incompatibles, el PM rechazará la combinación y explicará por qué.

Wide Compatibility

  • outline — classic, minimal, premium-dark, academic, visual-heavy (5 styles)
  • vertical — classic, minimal, premium-dark, academic, visual-heavy (5 styles)
  • zen — classic, minimal, premium-dark, academic (4 styles)

Narrower Compatibility

  • pitch-enhanced — classic, minimal, premium-dark, academic, visual-heavy (5, but visual-heavy is partial)
  • pitch — classic, minimal, premium-dark (3 styles)
  • outlook — classic, minimal, premium-dark, academic, visual-heavy (5 styles)
Consejo para principiantes: Si no estás seguro de qué tema y estilo elegir, empieza con el tema outline + estilo classic. Esta combinación tiene la mayor compatibilidad, produce una disposición vertical limpia y funciona bien para la mayoría de los tipos de presentación. Siempre puedes cambiarlo más tarde sin rehacer tu contenido.

Gate Approvals

Los gates son puntos de control del pipeline donde el flujo de trabajo hace una pausa para tu revisión. Existen para que tú mantienes el control de la presentación en los puntos de decisión críticos. El PM nunca avanza más allá de un gate obligatorio sin tu aprobación explícita.

Mandatory Gates

Dos gates son mandatory — debes aprobar explícitamente antes de que el pipeline continúe.

Gate 2 — Content Approval

  • When: Después de que el agent de storyline termina storyline.md y slide_deck.md
  • Lo que revisas: La estructura narrativa, el esquema de capítulos, los títulos de las diapositivas, el contenido de las viñetas y las ubicaciones de las imágenes
  • Why it matters: Una vez que apruebas, los agents de diseño, imagen y construcción comienzan a trabajar basándose en este contenido. Cambiar el contenido más tarde significa re-ejecutar múltiples etapas
  • PM message: "Approving starts design and HTML. Approve?"

Gate 5 — Sample PDF Approval

  • When: After the pdf-export agent generates a 5-slide sample PDF
  • Lo que revisas: Disposición, fuentes, colores, espaciado y calidad visual general de la muestra
  • Why it matters: Esta es tu oportunidad de detectar problemas visuales antes de que se genere el PDF completo
  • PM message: "Check layout and fonts. Generate full PDF? Approve?"

Optional Gates

Tres gates son optional — el PM revisa el resultado y avanza automáticamente a menos que haya un problema.

  • Gate 1.5 (Source Verification) — Después de que source-verifier produce source-verification.md. El PM muestra el Trust Score y continúa automáticamente. Se detiene solo si el Trust Score &lt; 70%.
  • Gate 3 (Design Spec) — Después de que el agent de diseño produce design_spec.md. El PM muestra un resumen del tema y la especificación visual, luego continúa.
  • Gate 4 (HTML Draft) — After the html-build agent generates the HTML slide deck. The PM outputs built file details, then proceeds.
El Gate 2 es el punto de decisión más importante. Aprobar el Gate 2 dispara las etapas de diseño, curación de imágenes, generación de diagramas, construcción HTML y exportación a PDF. Si más adelante quieres cambiar la estructura del contenido (por ejemplo, añadir un capítulo, eliminar diapositivas o reorganizar el flujo), el PM tendrá que reiniciar las etapas posteriores y re-ejecutarlas. Revisa el contenido cuidadosamente antes de aprobar.
Rework rules: Si solicitas cambios después de un gate, el PM identifica qué etapas posteriores necesitan re-ejecutarse, llama al agent version para tomar instantáneas de los archivos actuales, despacha al especialista apropiado y restablece las etapas afectadas a "pendiente" en project_state.json. Las etapas cuyo resultado no cambia (por ejemplo, la investigación) se omiten.

Cómo hablar con el PM

Dado que el Agent PM es tu punto único de contacto, saber comunicarte eficazmente hace que todo el proceso sea más fluido. Interactúas con el PM mediante lenguaje natural en tu sesión de Claude Code o Antigravity CLI.

Starting a New Presentation

Para iniciar una nueva presentación, simplemente dile al PM qué quieres crear. Aquí tienes algunos prompts de ejemplo.

Example prompts for starting a presentation:
  • "Create a presentation about renewable energy for university students."
  • "Make a 20-slide lecture deck on machine learning basics for beginners."
  • "Necesito una presentación sobre el cambio climático con muchos diagramas y gráficos de datos."
  • "Crea una presentación sobre la historia de internet para una audiencia de bachillerato."

Good vs. Bad Requests

La calidad de tu solicitud afecta la calidad del resultado. Aquí tienes una comparación para ayudarte a formular solicitudes eficaces.

Good Requests

  • "Create a presentation about renewable energy for university students. Include data charts showing growth trends."
  • "Haz una clase 15-slide sobre AI ethics para un general audience. Usa el outline theme con premium-dark style."
  • "Quiero una presentación sobre space exploration con chapter dividers y speaker notes en cada diapositiva."

Requests That Need Improvement

  • "Haz una presentación." — Demasiado vago. El PM necesita un tema y una audiencia.
  • "Hazlo todo." — El PM necesita detalles específicos para despachar a los agents correctos.
  • "Que se vea bien." — Especifica un tema y estilo, o deja que el PM sugiera uno basándose en tu contenido.

Requesting Changes

Después de revisar los resultados de los gates, puedes solicitar cambios en lenguaje natural. El PM determinará qué agents re-despachar y qué etapas re-ejecutar.

Example prompts for requesting changes:
  • "La storyline tiene demasiadas diapositivas en el Capítulo 2. Fusiona algunas."
  • "¿Puedes cambiar el color de acento a azul en la especificación de diseño?"
  • "I want to add a comparison diagram on slide 8."
  • "Las fuentes del PDF de muestra se ven mal. ¿Puedes volver a medir?"
Tip: No necesitas saber qué agent maneja tu solicitud. Simplemente describe lo que quieres cambiar, y el PM se encargará del resto. Por ejemplo, decir "añade más imágenes al Capítulo 3" activa automáticamente el agent image-curator — no necesitas mencionar el agent por su nombre.

Practice: Create a Mini Presentation

En este ejercicio, usarás co-deck para construir una mini presentación de 5 diapositivas. El tema es "5 Conceptos Clave del Machine Learning" — una presentación simple dirigida a principiantes.

Practice Objectives

  • Clona el repositorio de co-deck y configura el proyecto
  • Envía una solicitud al Agent PM desde Claude Desktop App
  • Observe the 11-Stage pipeline in action
  • Experience the Gate 2 and Gate 5 approval process
  • Review the final outputs (HTML and PDF)

Prerequisites

Asegúrate de que las herramientas que instalaste en el Capítulo 3 funcionen correctamente.

  1. Claude Desktop App — debe poder mantener una conversación con Claude
  2. Git — must be able to clone repositories
  3. Browser — un navegador que pueda abrir la presentación HTML

Step-by-Step Walkthrough

  1. Clona el workspace y genera el proyecto
    If you haven't already cloned the workspace in an earlier chapter, do that first, then scaffold a new project from the co-deck variant using new-project.ts.
    git clone https://github.com/5throck/ai-workspace-standards.git
    cd ai-workspace-standards
    bun scripts/new-project.ts "co-deck" --variant co-deck
    This creates Proyectos/co-deck/ as its own independent Git repository, with the co-deck variant's agents, skills, and configuration already copied in.
  2. Abre el proyecto en Claude Desktop App
    Launch Claude Desktop App and open the Proyectos/co-deck/ folder as a project. Start the PM by telling Claude the following.
    "Let's start a new project."
    The PM enters Stage 0 (project configuration) and asks about the topic, audience, theme, and style.
  3. Talk to the PM
    Answer the PM's questions to configure the project. Try responding like this.
    "Create a mini presentation about the 5 core concepts of machine learning. 5 slides. For beginners. In English."
    The PM analyzes your request and walks you through the configuration fields in lecture-profile.md (theme, style, source_verification, etc.).
  4. Stage 0 configuration (topic, audience, language)
    The PM confirms the following items. Beginners should stick with the defaults.
    • Rendering theme: pitch-enhanced (default)
    • Visual style: classic (default)
    • Source verification: true (default)
    • Divider mode: auto (default)
    Confirm all the settings and tell the PM to proceed.
  5. Approve Gate 2 (review slide content)
    Once Stage 1 (research) and Stage 2–3 (content) finish, the PM asks for your approval at Gate 2. Review slide_deck.md and check the following.
    • Is the slide structure logical?
    • ¿Es preciso el contenido de cada diapositiva?
    • ¿Son apropiadas la diapositiva de portada y la de cierre?
    After reviewing, respond like this.
    "I've reviewed the slide content. Please proceed to the next stage."
    If changes are needed, be specific.
    "Please explain slide 3's content in simpler terms."
  6. Approve Gate 5 (review the sample PDF)
    Once Stage 11 produces sample_5slides.pdf, the PM asks for your approval at Gate 5. In the sample PDF, check the following.
    • Do the fonts render correctly without breaking?
    • Is the layout well arranged?
    • ¿Aparecen los colores como se pretendía?
    After reviewing, respond like this.
    "I've reviewed the sample PDF. Please generate the full PDF."
  7. Review the final outputs
    Una vez completadas todas las etapas, puedes encontrar los resultados finales en la carpeta presentations/<project>/. La siguiente sección explica exactamente cómo revisarlos.
Start with a short 5–10 slide presentation. Una presentación más pequeña permite que todo el pipeline termine rápidamente para que te familiarices con cómo funciona co-deck. Una vez que te sientas cómodo, prueba una presentación completa de 20–30+ diapositivas.
Note: Los agents de co-deck se ejecutan a través de la API de Claude. Las respuestas de Claude pueden ralentizarse o agotar el tiempo de espera durante el ejercicio. Las presentaciones con muchas imágenes o diagramas pueden tardar más — este es un comportamiento esperado.

Reviewing Resultados

Después de que el pipeline termina, los resultados de tu presentación viven en el directorio del proyecto. Veamos dónde encontrarlos y cómo revisar cada tipo de resultado.

Resultado Locations

Todos los resultados de tu presentación se almacenan bajo presentations/<project-name>/. Aquí tienes la disposición de directorios que verás después de una ejecución completa del pipeline.

Proyectos/co-deck/presentations/<project-name>/
File / Directory Descripción
lecture-profile.md Your project configuration (topic, audience, theme, style)
research_notes.md Fuentes de investigación web y hechos clave recopilados por el agent de investigación
storyline.md Arco narrativo y estructura de capítulos diseñados por el agent de storyline
slide_deck.md Per-slide content: titles, bullets, speaker notes, image roles
design_spec.md Visual design: color palette, fonts, CSS variables
assets/images/ Downloaded commercial-use images + image-manifest.json
assets/diagrams/ Generated SVG diagrams + diagram-manifest.json
lecture_v1.html The final single-file HTML slide deck
<project>.pdf The final print-ready PDF
sample_5slides.pdf The 5-slide sample PDF used for Gate 5 review
project_state.json Pipeline progress tracker (status of each stage)

Opening and Reviewing Your Resultados

  1. Open the HTML slide deck. Navega a presentations/<project-name>/lecture_v1.html y ábrelo en tu navegador web. Deberías ver tu presentación completa con todas las diapositivas, imágenes, diagramas y navegación. Prueba a hacer clic por las diapositivas, usar las flechas del teclado y alternar el panel de notas del orador.
  2. Test HTML features. Presiona F para pantalla completa, T para abrir la tabla de contenidos, S para ver las notas del orador y Escape para salir. Estos controles te permiten practicar tu presentación igual que en una aplicación real de diapositivas.
  3. Open the PDF. Navega a presentations/<project-name>/<project>.pdf y ábrelo en tu visor de PDF. Compara la disposición del PDF con la versión HTML — deberían coincidir estrechamente en colores, fuentes y espaciado.
  4. Review intermediate files (optional). Si quieres entender cómo funciona el pipeline, abre research_notes.md para ver lo que encontró el agent de investigación, slide_deck.md para ver el contenido estructurado y design_spec.md para ver las decisiones de diseño visual. Estos archivos te dan total visibilidad sobre cada decisión que tomaron los agents de IA.
Pro tip: La presentación HTML es el entregable principal. Es autónoma (no requiere servidor), soporta funciones interactivas como el modo presentador y la narración TTS, y funciona sin conexión. El PDF es mejor para imprimir o compartir con personas que prefieren un documento estático. Usa ambos: presenta desde el HTML, distribuye el PDF.
