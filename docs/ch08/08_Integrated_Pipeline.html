co-consult + co-deck 통합 파이프라인

co-consult에서 분석한 결과를 co-deck에서 발표자료로 만드는 통합 워크플로우를 배웁니다. 컨설팅 보고서에서 프레젠테이션까지, 주제 입력 후 30~45분이면 완성됩니다.

이 장에서 다루는 것
  • 왜 co-consult와 co-deck을 통합하는가
  • 수동 핸드오프 방법 (보고서 → 발표자료)
  • 풀 파이프라인 실습 (주제 → 30~45분 후 완성)
  • 두 시스템의 에이전트 구성 차이
  • 성공적인 통합을 위한 팁

왜 통합하는가

컨설팅 결과를 발표로 전달하는 자연스러운 흐름

실무에서 컨설팅 프로젝트를 진행하면 일반적으로 다음과 같은 흐름이 발생합니다. 먼저 시장이나 주제에 대한 조사와 분석을 수행하고, 그 결과를 보고서로 정리합니다. 그리고 이 보고서를 바탕으로 발표자료(프레젠테이션)를 만들어 이해관계자에게 전달합니다.

co-consult는 이 흐름에서 조사와 분석을 담당하고, co-deck은 발표자료 제작을 담당합니다. 두 시스템을 연결하면, 주제 하나를 입력하는 것만으로 분석 보고서부터 프레젠테이션까지 전체 과정을 자동화할 수 있습니다.

초보자를 위한 비유

co-consult가 '조사 보고서'를 쓰면, co-deck이 그 보고서를 바탕으로 '발표 슬라이드'를 만드는 것입니다. 회사에서 기획팀이 조사한 내용을 디자인팀이 프레젠테이션으로 바꾸어 주는 것과 같은 흐름입니다.

핵심: 두 시스템은 각각 독립적으로도 사용할 수 있지만, 함께 사용하면 "조사 → 분석 → 보고서 → 프레젠테이션"이라는 전체 워크플로우가 하나의 주제 입력으로 완성됩니다.

산출물의 흐름

co-consult에서 생성되는 핵심 산출물은 research_notes.md입니다. 이 파일에는 웹 검색으로 수집한 자료, 핵심 팩트, 출처 정보가 정리되어 있습니다. co-deck의 리서치 에이전트도 research_notes.md를 생성하므로, 두 시스템 간의 공통 인터페이스 역할을 합니다.

  • co-consult 산출물 — research_notes.md, 분석 보고서, 시장 인사이트
  • co-deck 입력 — research_notes.md를 기반으로 슬라이드 구성
  • co-deck 산출물 — slide_deck.md, design_spec.md, HTML 슬라이드, PDF

통합 워크플로우 전체도

위 다이어그램에서 보듯, co-consult에서 research_notes.md를 생성한 뒤 이를 co-deck 프로젝트로 핸드오프(Handoff)하면 됩니다. 핸드오프가 완료되면 co-deck의 PM 에이전트가 나머지 과정을 자동으로 진행합니다.

전체 과정이 30~45분 정도 소요됩니다. co-consult의 분석 단계에 약 15~20분, co-deck의 발표자료 제작에 약 15~25분이 걸립니다. 병렬 에이전트 실행 덕분에 이렇게 짧은 시간에 완성됩니다.

수동 핸드오프 방법

현재 핸드오프는 수동 방식

co-consult와 co-deck은 각각 독립적인 프로젝트로 동작합니다. 현재 두 시스템 간의 자동 연동 기능은 아직 지원되지 않습니다. 따라서 사용자가 직접 파일을 복사하고 co-deck에 요청하는 수동 핸드오프 과정을 거쳐야 합니다.

하지만 걱정하지 마세요. 수동 핸드오프는 몇 분이면 완료할 수 있는 간단한 작업입니다. 파일 하나를 복사하고 PM에게 한 줄 요청하면 됩니다.

핸드오프 순서

핸드오프는 다음 세 단계로 진행됩니다.

1. co-consult에서 research_notes.md 확인 — co-consult 프로젝트 폴더에서 생성된 research_notes.md를 엽니다. 내용이 충분한지, 핵심 정보가 잘 정리되어 있는지 확인합니다.
2. co-deck 프로젝트의 research 폴더에 복사 — research_notes.md 파일을 co-deck 프로젝트의 presentations/<프로젝트명>/ 폴더에 복사합니다.
3. co-deck PM에게 요청 — co-deck 프로젝트의 Claude Desktop App에서 PM에게 "이 연구를 바탕으로 발표자료를 만들어줘"라고 요청합니다.

핸드오프 상세 단계

  1. co-consult 프로젝트 열기 — Claude Desktop App에서 co-consult 프로젝트 폴더를 엽니다.
  2. research_notes.md 경로 확인 — 일반적으로 engagements/<프로젝트명>/research/research_notes.md 경로에 있습니다.
  3. 파일 내용 검토 — research_notes.md를 열어서 다음 내용이 포함되어 있는지 확인합니다:
    • 주제에 대한 핵심 팩트와 통계
    • 시장 동향 및 인사이트
    • 출처 URL (신뢰도 확인용)
    • 핵심 키워드 목록
  4. co-deck 프로젝트 열기 — 별도의 Claude Desktop App 창에서 co-deck 프로젝트 폴더를 엽니다.
  5. research_notes.md 복사 — co-consult의 research_notes.md 내용을 co-deck 프로젝트의 presentations/<프로젝트명>/ 폴더에 research_notes.md 파일로 저장합니다.
  6. PM에게 요청 — co-deck의 Claude에 다음과 같이 입력합니다:
    "research_notes.md에 정리된 내용을 바탕으로 발표자료를 만들어줘"
팁: research_notes.md의 핵심 내용을 co-deck의 slide_deck.md에 반영하려면, PM에게 "이전 연구 내용을 기반으로 슬라이드를 구성해줘"라고 추가 요청하세요. 이렇게 하면 PM이 스토리라인 에이전트에게 research_notes.md를 참고하도록 지시합니다.

핸드오프 예시 대화

co-deck의 PM에게 요청할 때의 예시 대화입니다.

사용자: "research_notes.md에 한국 배달 앱 시장 분석 내용이 있어. 이걸 바탕으로 15장짜리 프레젠테이션을 만들어줘. 대상 청중은 일반 대중이야."
PM: "프로젝트를 초기화합니다. research_notes.md를 읽어 스토리라인 에이전트에게 전달하겠습니다."
PM: "Gate 2 — 슬라이드 내용이 준비되었습니다. 승인하시겠습니까?"
사용자: "승인해."
PM: "디자인과 HTML 빌드를 진행합니다. 완료되면 알려드리겠습니다."

풀 파이프라인 실습

실습 목표

이번 실습에서는 "한국의 배달 앱 시장"이라는 주제로 co-consult에서 시장 분석을 수행한 뒤, 그 결과를 co-deck에서 프레젠테이션으로 변환하는 전체 과정을 경험합니다.

전체 과정이 30~45분 정도 소요됩니다. 병렬 에이전트 실행 덕분에 이렇게 짧은 시간에 완성됩니다. 중간에 Gate 승인 대기 시간이 포함된 시간입니다.

전체 단계

  1. co-consult 프로젝트에서 시장 분석 실행 (약 15~20분)
    Claude Desktop App에서 co-consult 프로젝트를 열고 PM 에이전트에게 요청합니다. 6장에서 배운 내용을 복습하며 진행하세요.

    예시 대화:
    "한국의 배달 앱 시장에 대한 시장 분석을 해줘. 배달의민족, 요기요, 쿠팡이츠의 경쟁 구도와 최근 트렌드를 중심으로."
  2. research_notes.md와 보고서 내용 확인 (약 3~5분)
    co-consult의 리서치 에이전트와 분석 에이전트가 작업을 완료하면, research_notes.md와 최종 보고서를 확인합니다. 핵심 통계, 시장 규모, 경쟁사 비교 내용이 포함되어 있는지 검토합니다.
  3. co-deck 프로젝트에 핸드오프 (파일 복사) (약 2분)
    research_notes.md 파일을 co-deck 프로젝트의 presentations/<프로젝트명>/ 폴더에 복사합니다. 파일 이름은 research_notes.md로 그대로 사용합니다.
  4. co-deck PM에게 요청 (약 1분)
    co-deck 프로젝트의 Claude에서 PM 에이전트에게 요청합니다.

    예시 대화:
    "research_notes.md의 한국 배달 앱 시장 분석을 바탕으로 발표자료를 만들어줘. 15장 정도, 대상은 일반 대중."
  5. Gate 2 승인 — 슬라이드 내용 검토 (약 5분)
    PM이 스토리라인 에이전트와 리서치 에이전트를 거쳐 slide_deck.md를 생성한 뒤, Gate 2 승인을 요청합니다. 슬라이드 제목, 순서, 핵심 메시지를 확인하고 승인합니다.

    예시 대화:
    "슬라이드 구성을 확인했습니다. 시장 개요 → 경쟁사 비교 → 트렌드 → 전망 순서로 좋네요. 승인합니다."
  6. Gate 5 승인 — 샘플 PDF 검토 (약 5분)
    PM이 디자인, 이미지 큐레이션, HTML 빌드, PDF 생성을 차례로 진행한 뒤, 5장 분량의 샘플 PDF를 보여줍니다. 레이아웃, 폰트, 색상을 확인하고 승인하면 전체 PDF가 생성됩니다.

    예시 대화:
    "샘플 PDF 확인했습니다. 레이아웃과 폰트가 깔끔하네요. 전체 PDF를 생성해주세요."
  7. 최종 산출물 확인 (약 2분)
    전체 PDF가 생성되면 최종 파일을 열어서 확인합니다. co-deck의 presentations/<프로젝트명>/ 폴더에 HTML 파일과 PDF 파일이 함께 저장됩니다.

풀 파이프라인 타임라인

Gate 2와 Gate 5는 필수 승인 단계입니다. PM이 승인을 요청할 때 반드시 내용을 확인한 뒤 "승인해" 또는 "Approve"라고 응답해야 다음 단계로 진행됩니다. 수정이 필요하면 그때 피드백을 주면 됩니다.

각 단계에서 확인할 점

  • co-consult 분석 단계 — research_notes.md에 출처가 명확한지, 핵심 통계 숫자가 있는지 확인합니다. 신뢰할 수 없는 출처가 포함되어 있으면 이 단계에서 수정하는 것이 좋습니다.
  • 핸드오프 단계 — 파일 경로가 정확한지, 파일 내용이 완전히 복사되었는지 확인합니다. 파일이 손상되면 co-deck의 PM이 내용을 읽지 못합니다.
  • Gate 2 — slide_deck.md의 슬라이드 순서가 논리적인지, 각 슬라이드의 핵심 메시지가 명확한지 확인합니다. 이때 수정 요청을 하면 스토리라인 에이전트가 다시 내용을 구성합니다.
  • Gate 5 — 샘플 PDF의 레이아웃, 폰트 크기, 색상 대비를 확인합니다. 텍스트가 잘리거나 읽기 어렵다면 이때 피드백을 줍니다.

에이전트 구성 차이

co-consult와 co-deck은 비슷한 구조의 멀티 에이전트 하네스를 사용하지만, 각 시스템의 목적에 맞게 전문 에이전트 구성이 다릅니다. 컨설팅에 필요한 에이전트와 프레젠테이션 제작에 필요한 에이전트는 자연히 다를 수밖에 없습니다.

co-consult 전용 에이전트

co-consult는 시장 분석과 컨설팅에 특화된 에이전트를 보유합니다.

  • strategy-analyst — 시장 분석, 경쟁사 리서치, 재무 모델링을 수행합니다.
  • industry-expert — 산업별 인사이트, 경쟁 역학, 규제 환경을 분석합니다.
  • sme — HR, 재무, 운영, 마케팅 등 기능별 전문 분야를 담당합니다.
  • data-analyst — 통계 분석, 데이터 모델링, 시각화를 수행합니다.
  • communications-lead — 클라이언트 커뮤니케이션, 프레젠테이션, 전략 내러티브를 작성합니다.
  • change-management-partner — 조직 변화 관리, 조직문화 전략, 이해관계자 얼라인먼트를 담당합니다.
  • solutions-architect — 기술 솔루션 설계, 시스템 아키텍처, 실행 로드맵을 수립합니다.
  • workstream-lead / delivery-manager — 워크스트림 및 딜리버리 조율을 담당합니다.
co-consult에는 co-deck과 같은 고정된 파이프라인이 없습니다. PM(Engagement Leader)이 인게이지먼트의 요구에 따라 위 전문가들을 그때그때 디스패치합니다.

co-deck 전용 에이전트

co-deck는 프레젠테이션 제작에 특화된 에이전트를 보유합니다.

  • design — 시각적 디자인 결정. 색상 팔레트, 폰트, 레이아웃을 design_spec.md에 정의합니다.
  • image-curator — 슬라이드용 이미지 검색 및 다운로드. Pixabay, Unsplash, Pexels에서 상업용 이미지를 찾습니다.
  • diagram-specialist — SVG 다이어그램과 차트 생성. 순서도, 비교표, 타임라인 등을 만듭니다.
  • measure — HTML 슬라이드 레이아웃 측정. PDF 변환을 위한 픽셀 좌표를 추출합니다.

공통 에이전트

두 시스템 모두 다음 에이전트를 공유하거나 비슷한 역할의 에이전트를 보유합니다.

  • PM — 프로젝트 전체를 오케스트레이션. 에이전트 배치, Gate 관리, 진행 상황 추적을 담당합니다.
  • research — 웹 검색 및 자료 수집. research_notes.md를 생성합니다.
  • source-verifier — 출처 URL 검증 및 신뢰도 평가.
  • storyline — 내용 구조 설계. slide_deck.md 또는 보고서 구조를 작성합니다.
  • html-build — HTML 파일 생성 (co-deck 전용이지만, 구조는 비슷합니다).
  • pdf-export — PDF 변환.
  • version — 파일 버전 관리. 수정 전 자동 백업.

에이전트 비교표

co-consult 에이전트

  • strategy-analyst — 시장/경쟁 분석
  • industry-expert — 산업 인사이트
  • sme — 기능별 전문성
  • data-analyst — 데이터 분석
  • communications-lead — 커뮤니케이션
  • change-management-partner — 변화 관리
  • solutions-architect — 솔루션 설계
  • workstream-lead — 워크스트림 조율
  • delivery-manager — 딜리버리 조율
  • technology-specialist — 기술 도입 지원
  • PM (Engagement Leader) — 오케스트레이션 (고정 파이프라인 없음)

co-deck 에이전트

  • design — 시각적 디자인
  • image-curator — 이미지 큐레이션
  • diagram-specialist — 다이어그램
  • measure — 레이아웃 측정
  • PM — 오케스트레이션
  • research — 웹 리서치
  • source-verifier — 출처 검증
  • storyline — 슬라이드 구성
  • html-build — HTML 생성
  • pdf-export — PDF 변환
  • version — 버전 관리
공통 에이전트는 역할이 비슷하지만, 각 시스템의 맥락에 맞게 설정이 다릅니다. 예를 들어 co-consult의 research 에이전트는 컨설팅 질문에 초점을 맞추고, co-deck의 research 에이전트는 프레젠테이션에 필요한 정보를 중심으로 수집합니다.

성공 팁

co-consult와 co-deck을 통합하여 사용할 때 알아두면 좋은 팁을 정리합니다.

핸드오프 전: co-consult 보고서의 품질 확인

핸드오프하기 전에 co-consult에서 생성한 research_notes.md의 품질을 확인하는 것이 중요합니다. co-deck은 이 파일을 기반으로 슬라이드 내용을 구성하므로, 입력의 품질이 출력의 품질을 결정합니다.

  • 핵심 팩트와 통계 숫자가 정확한지 확인
  • 출처 URL이 유효한지 확인
  • 주제와 관련 없는 내용이 포함되지 않았는지 확인
  • 내용이 충분히 상세한지 확인 (너무 짧으면 슬라이드 내용이 빈약해짐)

핸드오프 시: 핵심 내용을 요약해서 전달

co-deck의 PM에게 단순히 "이 파일로 발표자료 만들어줘"라고만 요청하면, PM이 research_notes.md의 방대한 내용에서 무엇을 우선시할지 알기 어려울 수 있습니다. 핵심 메시지와 대상 청중을 함께 전달하면 훨씬 좋은 결과를 얻을 수 있습니다.

추천 요청 형식: "research_notes.md를 바탕으로 발표자료를 만들어줘. 핵심 메시지는 [OOO]이고, 대상 청중은 [OOO]입니다. [N]장 정도로 구성해줘."

co-deck 설정: Theme와 Style 미리 결정

co-deck는 Theme(HTML 구조)와 Style(CSS 스타일)을 선택할 수 있습니다. 핸드오프를 시작하기 전에 이 두 가지를 미리 결정해 두면 PM이 Stage 0 설정 과정을 빠르게 진행할 수 있습니다.

  • Theme — pitch-enhanced(비즈니스 프레젠테이션), outline(강의/교육용) 등 5종
  • Style — 색상, 폰트 등 시각적 스타일 (예: premium-dark, academic) 등 5종
Theme와 Style의 호환성은 docs/html-themes/THEMES.md에서 확인할 수 있습니다. 모든 Theme와 Style이 호환되는 것은 아니므로, PM이 Stage 0에서 호환성을 자동으로 검사합니다.

Gate 승인: 슬라이드 내용을 꼼꼼히 확인

Gate 2와 Gate 5는 수정 기회입니다. 한 번 승인하면 다시 돌아오기 위해서는 전체 파이프라인을 다시 실행해야 할 수 있습니다. 다음 사항을 꼼꼼히 확인하세요.

  • Gate 2에서: 슬라이드의 순서가 논리적인가? 중복되는 내용은 없는가? 핵심 메시지가 잘 드러나는가?
  • Gate 5에서: 폰트가 잘 보이는가? 레이아웃에 텍스트가 잘리지 않는가? 색상 대비가 충분한가?
팁: 처음 통합 파이프라인을 시도할 때는 간단한 주제로 시작하세요. 예를 들어 "우리 동네 카페 시장" 같은 좁은 주제로 연습해 보고, 익숙해진 후에 "한국 배달 앱 시장" 같은 더 복잡한 주제로 나아가세요.
주의: 핸드오프 시 파일 경로를 정확히 확인하세요. co-deck의 PM은 presentations/<프로젝트명>/research_notes.md 경로에서 파일을 읽습니다. 잘못된 경로에 파일을 저장하면 PM이 파일을 찾지 못하고, 리서치 에이전트를 새로 실행해야 합니다.

문제 해결

통합 파이프라인을 실행하다가 문제가 발생하면 다음을 확인하세요.

  • co-deck이 research_notes.md를 못 읽는 경우 — 파일 경로가 맞는지, 파일 이름이 정확히 research_notes.md인지 확인하세요.
  • 슬라이드 내용이 co-consult와 다른 경우 — PM에게 "research_notes.md의 내용을 우선해서 반영해줘"라고 명시적으로 요청하세요.
  • PDF가 깨지는 경우 — Gate 5에서 샘플 PDF를 꼼꼼히 확인하고, 한글 폰트가 포함되어 있는지 확인하세요.
  • 시간이 너무 오래 걸리는 경우 — Claude Desktop App의 응답 속도에 따라 달라집니다. 네트워크 환경을 확인하고, 너무 많은 슬라이드를 요청하지 않았는지 점검하세요.
이 장의 핵심 정리
  • co-consult(분석) + co-deck(발표) = 조사부터 프레젠테이션까지 자동화
  • 핸드오프는 research_notes.md 파일 복사로 간단히 완료
  • PM에게 핵심 메시지와 대상 청중을 명확히 전달하면 결과 품질이 향상
  • Gate 2(내용)와 Gate 5(디자인)에서 꼼꼼히 확인하는 것이 핵심
  • 처음에는 간단한 주제로 연습하고, 점차 복잡한 주제로 도전하세요
