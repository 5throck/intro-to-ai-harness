Chapter 8

Combined co-consult + co-deck Pipeline

Learn the integrated workflow that turns the results analyzed in co-consult into presentation materials with co-deck. From consulting report to presentation — enter a topic and it is finished in 30-45 minutes.

What This Chapter Covers
  • Why integrate co-consult and co-deck
  • Manual handoff method (report → presentation)
  • Full pipeline practice (topic → finished in 30-45 minutes)
  • Agent composition differences between the two systems
  • Tips for successful integration

Why Integrate

A Natural Flow from Consulting Results to Presentation

In real-world consulting projects, work generally follows this flow: first you carry out research and analysis on a market or topic and organize the results into a report. Then, based on that report, you build presentation slides and deliver them to stakeholders.

co-consult handles the research and analysis part of this flow, and co-deck handles presentation production. Connect the two systems, and entering a single topic automates the entire journey from analysis report to presentation.

An Analogy for Beginners

When co-consult writes the "research report," co-deck builds "presentation slides" from that report. It is the same flow as a planning team researching a subject at a company and a design team turning it into a presentation.

Key point: Both systems can be used independently, but together the entire workflow of "research → analysis → report → presentation" is completed from a single topic input.

Flow of Deliverables

The core deliverable produced by co-consult is research_notes.md. This file organizes the material gathered through web search, the key facts, and the source information. co-deck's research agent also generates research_notes.md, so it serves as the shared interface between the two systems.

  • co-consult deliverables — research_notes.md, analysis report, market insights
  • co-deck input — slide composition based on research_notes.md
  • co-deck deliverables — slide_deck.md, design_spec.md, HTML slides, PDF

Integrated Workflow Overview

As the diagram above shows, once co-consult generates research_notes.md, you simply hand off the file to the co-deck project. Once the handoff is complete, co-deck's PM agent automatically carries out the rest of the process.

The whole process takes about 30-45 minutes. co-consult's analysis phase takes roughly 15-20 minutes, and co-deck's presentation production takes roughly 15-25 minutes. Parallel agent execution is what makes it possible to finish this quickly.

Manual Handoff Method

The Current Handoff Is Manual

co-consult and co-deck operate as independent projects. Automatic integration between the two systems is not yet supported. You therefore have to go through a manual handoff, copying the file yourself and making the request to co-deck.

But do not worry. The manual handoff is a simple task that takes only a few minutes: copy one file and send the PM a one-line request.

Handoff Sequence

The handoff proceeds in the following three steps.

1. Check research_notes.md in co-consult — Open the research_notes.md generated in the co-consult project folder. Check whether the content is sufficient and whether the key information is well organized.
2. Copy it into the co-deck project's research folder — Copy the research_notes.md file into the co-deck project's presentations/<project-name>/ folder.
3. Ask the co-deck PM — In the co-deck project's Claude Desktop App, ask the PM: "Create the presentation materials based on this research."

Handoff Step by Step

  1. Open the co-consult project — Open the co-consult project folder in Claude Desktop App.
  2. Locate research_notes.md — It is usually found at the path engagements/<project-name>/research/research_notes.md.
  3. Review the file contents — Open research_notes.md and confirm it contains the following:
    • Key facts and statistics about the topic
    • Market trends and insights
    • Source URLs (for credibility checks)
    • A list of core keywords
  4. Open the co-deck project — Open the co-deck project folder in a separate Claude Desktop App window.
  5. Copy research_notes.md — Save the contents of co-consult's research_notes.md as a research_notes.md file in the co-deck project's presentations/<project-name>/ folder, keeping the file name unchanged.
  6. Ask the PM — Enter the following in co-deck's Claude:
    "Create the presentation materials based on what is organized in research_notes.md"
Tip: To reflect the key content of research_notes.md in co-deck's slide_deck.md, add a follow-up request to the PM such as "Compose the slides based on the earlier research content." The PM will then instruct the storyline agent to refer to research_notes.md.

Example Handoff Conversation

This is an example conversation when asking co-deck's PM.

User: "research_notes.md contains an analysis of the Korean food delivery app market. Build a 15-slide presentation from it. The target audience is the general public."
PM: "Initializing the project. I will read research_notes.md and pass it to the storyline agent."
PM: "Gate 2 — the slide content is ready. Do you approve?"
User: "Approved."
PM: "Proceeding with design and the HTML build. I will let you know when it is done."

Full Pipeline Practice

Practice Goal

In this exercise you will experience the entire process of running a market analysis in co-consult on the topic "the Korean food delivery app market" and then converting the results into a presentation with co-deck.

The whole process takes about 30-45 minutes. Parallel agent execution is what makes it possible to finish this quickly. The estimate includes the time spent waiting for gate approvals along the way.

All Steps

  1. Run the market analysis in the co-consult project (about 15-20 minutes)
    Open the co-consult project in Claude Desktop App and place a request with the PM agent. Proceed while reviewing what you learned in Chapter 6.

    Example conversation:
    "Run a market analysis of the Korean food delivery app market, focusing on the competitive landscape of Baedal Minjok, Yogiyo, and Coupang Eats and on recent trends."
  2. Check research_notes.md and the report (about 3-5 minutes)
    When co-consult's research agent and analysis agent finish their work, review research_notes.md and the final report. Check that they include the key statistics, the market size, and the competitor comparisons.
  3. Hand off to the co-deck project (file copy) (about 2 minutes)
    Copy the research_notes.md file into the co-deck project's presentations/<project-name>/ folder. Keep the file name as research_notes.md exactly as it is.
  4. Ask the co-deck PM (about 1 minute)
    Place a request with the PM agent in the co-deck project's Claude.

    Example conversation:
    "Create presentation materials based on the Korean food delivery app market analysis in research_notes.md. About 15 slides, for a general audience."
  5. Gate 2 approval — review the slide content (about 5 minutes)
    After passing through the storyline agent and the research agent, the PM generates slide_deck.md and requests Gate 2 approval. Check the slide titles, order, and key messages, then approve.

    Example conversation:
    "I reviewed the slide composition. The order — market overview → competitor comparison → trends → outlook — looks good. Approved."
  6. Gate 5 approval — review the sample PDF (about 5 minutes)
    The PM proceeds through design, image curation, HTML build, and PDF generation in turn, then shows a sample PDF covering 5 slides. Check the layout, fonts, and colors; once you approve, the full PDF is generated.

    Example conversation:
    "I checked the sample PDF. The layout and fonts look clean. Please generate the full PDF."
  7. Check the final deliverables (about 2 minutes)
    Once the full PDF is generated, open the final files and verify them. The HTML file and the PDF file are saved together in co-deck's presentations/<project-name>/ folder.

Full Pipeline Timeline

Gate 2 and Gate 5 are mandatory approval points. When the PM asks for approval, you must review the content and answer "Approve" before the pipeline moves to the next step. If something needs fixing, give your feedback right then.

What to Check at Each Step

  • co-consult analysis step — Check that research_notes.md has clearly identified sources and includes the key statistical figures. If unreliable sources are included, it is best to fix them at this step.
  • Handoff step — Verify that the file path is exact and that the file content was copied completely. If the file is damaged, co-deck's PM cannot read the content.
  • Gate 2 — Check that the slide order in slide_deck.md is logical and that each slide's key message is clear. If you request changes here, the storyline agent reorganizes the content.
  • Gate 5 — Check the sample PDF's layout, font sizes, and color contrast. If text is cut off or hard to read, give feedback at this point.

Agent Composition Differences

co-consult and co-deck use multi-agent harnesses with a similar structure, but their specialist agent compositions differ to match each system's purpose. The agents a consulting engagement needs and the agents presentation production needs are bound to be different.

co-consult-Only Agents

co-consult holds agents specialized in market analysis and consulting.

  • strategy-analyst — Performs market analysis, competitor research, and financial modeling.
  • industry-expert — Analyzes industry-specific insights, competitive dynamics, and the regulatory environment.
  • sme — Covers functional domains such as HR, finance, operations, and marketing.
  • data-analyst — Performs statistical analysis, data modeling, and visualization.
  • communications-lead — Writes client communications, presentations, and strategic narratives.
  • change-management-partner — Handles organizational change management, culture strategy, and stakeholder alignment.
  • solutions-architect — Establishes technical solution design, system architecture, and execution roadmaps.
  • workstream-lead / delivery-manager — Handle workstream and delivery coordination.
co-consult has no fixed pipeline like co-deck does. The PM (Engagement Leader) dispatches the specialists above as the engagement demands, moment by moment.

co-deck-Only Agents

co-deck holds agents specialized in presentation production.

  • design — Makes visual design decisions. Defines the color palette, fonts, and layout in design_spec.md.
  • image-curator — Searches and downloads images for the slides. Finds commercially usable images on Pixabay, Unsplash, and Pexels.
  • diagram-specialist — Generates SVG diagrams and charts. Creates flowcharts, comparison tables, timelines, and more.
  • measure — Measures the HTML slide layout. Extracts pixel coordinates for PDF conversion.

Shared Agents

Both systems share the following agents, or hold agents with similar roles.

  • PM — Orchestrates the entire project. Handles agent dispatch, gate management, and progress tracking.
  • research — Web search and data collection. Generates research_notes.md.
  • source-verifier — Validates source URLs and evaluates credibility.
  • storyline — Designs the content structure. Writes slide_deck.md or the report structure.
  • html-build — Generates the HTML files (exclusive to co-deck, but the structure is similar).
  • pdf-export — Converts to PDF.
  • version — Manages file versions. Automatic backup before any modification.

  • sme — Functional expertise

co-deck Agents

  • PM — Orchestration
  • research — Web research

  • pdf-export — PDF conversion
  • version — Version management
The shared agents have similar roles, but their settings differ to fit each system's context. For example, co-consult's research agent focuses on the consulting questions, while co-deck's research agent collects information centered on what the presentation needs.

Success Tips

Here is a roundup of tips worth knowing when you use co-consult and co-deck together.

Before the Handoff: Check the Quality of the co-consult Report

Before handing off, it is important to check the quality of the research_notes.md generated by co-consult. co-deck builds its slide content from this file, so the quality of the input determines the quality of the output.

  • Confirm the key facts and statistical figures are accurate
  • Confirm the source URLs are valid
  • Confirm nothing unrelated to the topic slipped in
  • Confirm the content is sufficiently detailed (if it is too short, the slides become thin)

During the Handoff: Pass Along a Summary of the Core Content

If you simply ask co-deck's PM "make the presentation from this file," the PM may find it hard to know what to prioritize from the vast contents of research_notes.md. Passing the core message and target audience along as well gets you far better results.

Recommended request format: "Create the presentation materials based on research_notes.md. The core message is [XXX], and the target audience is [XXX]. Compose it in about [N] slides."

co-deck Setup: Decide the Theme and Style in Advance

co-deck lets you choose a Theme (HTML structure) and a Style (CSS styling). Deciding these two things before starting the handoff lets the PM move quickly through the Stage 0 setup.

  • Theme — 5 kinds, including pitch-enhanced (business presentations) and outline (lectures/education)
  • Style — 5 kinds of visual styles such as colors and fonts (e.g., premium-dark, academic)
Theme and Style compatibility can be checked in docs/html-themes/THEMES.md. Not every Theme and Style combination is compatible, so the PM automatically checks compatibility at Stage 0.

Gate Approval: Review the Slide Content Thoroughly

Gate 2 and Gate 5 are your chances to make corrections. Once you approve, getting back may require running the whole pipeline again. Check the following carefully.

  • At Gate 2: Is the slide order logical? Is there duplicated content? Do the key messages come through?
  • At Gate 5: Are the fonts readable? Does the layout clip any text? Is the color contrast sufficient?
Tip: When you try the integrated pipeline for the first time, start with a simple topic. Practice with a narrow topic such as "the cafe market in my neighborhood," and once you are comfortable, move on to more complex topics such as "the Korean food delivery app market."
Caution: During the handoff, verify the file path precisely. co-deck's PM reads the file from the path presentations/<project-name>/research_notes.md. If you save it to a wrong path, the PM cannot find the file and the research agent has to run all over again.

Troubleshooting

If a problem occurs while running the integrated pipeline, check the following.

  • co-deck cannot read research_notes.md — Check that the file path is correct and that the file name is exactly research_notes.md.
  • The slide content differs from co-consult — Explicitly tell the PM to "reflect the contents of research_notes.md with priority."
  • The PDF comes out broken — Review the sample PDF carefully at Gate 5 and check that a Korean font is included.
  • It takes too long — This depends on the response speed of the Claude Desktop App. Check your network conditions and make sure you did not request too many slides.
Chapter Takeaways
  • co-consult (analysis) + co-deck (presentation) = automation from research to presentation
  • The handoff completes simply by copying the research_notes.md file
  • Clearly conveying the core message and target audience to the PM improves result quality
  • Careful review at Gate 2 (content) and Gate 5 (design) is the key
  • Start by practicing with simple topics, then take on more complex ones
