Chapter 11

Building Your Own Agent Team

By now you know how to create agents (Chapter 9), author skills (Chapter 10), and understand the overall harness structure (Chapters 3–4). In this chapter, you will learn how to bring all of these pieces together into your own agent team. We will walk through, step by step, how the team-builder skill collects requirements, benchmarks industry practices, and generates a proposal — and then you will ask Claude to build a team yourself.

What You’ll Learn in This Chapter

  • Why agent team composition is needed
  • The team-builder skill’s AI layer and Script layer
  • The 5-step workflow: Interview → Benchmarking → Diagnosis → Proposal → Approval
  • Hands-on: Build your own custom agent team

Why Build an Agent Team?

Real-World Scenarios

AI agents are used across many fields. Composing agents to match the characteristics of each field lets you build a far more powerful system. Let’s look at a few real-world scenarios.

Marketing Team

  • Market research, content planning, design, review
  • Brand guideline compliance
  • Campaign performance analysis

Research Lab

  • Literature search, data analysis, paper drafting
  • Source verification and citation management
  • Peer review

Education Institution

  • Lecture material creation, exam question writing, learning analytics
  • Curriculum design
  • Student feedback collection and analysis

Software Development

  • Code writing, testing, code review
  • Documentation and deployment automation
  • Security checks and quality management

Limitations of a Single AI

A single AI assistant can accomplish a great deal. On complex projects, however, the limitations of a single AI become clear.

  • Difficult to separate roles — when one AI plans, writes, and reviews everything, quality drops in every role. Having it “review its own writing” invites bias.
  • Lack of specialization — tasks that require domain expertise, such as security checks, documentation quality review, and performance analysis, are handled better by dedicated specialist agents.
  • Scalability — as a project grows, a single AI must process work sequentially, which takes time. A team composition enables parallel processing.

Benefits of an Agent Team

When multiple specialist agents cooperate, you gain the following benefits:

  • Division of labor — each agent focuses solely on its own specialty, raising output quality.
  • Quality gates — writer and reviewer agents are separated, enabling objective quality review.
  • Reusability — skills can be shared across agents, reducing duplicated work and producing consistent results.
  • Parallel processing — independent tasks run simultaneously, shortening overall project time.
Analogy: A single AI is like an “all-purpose chef.” One person doing ingredient prep, cooking, plating, and tasting has a hard limit on quality. An agent team is a “kitchen brigade” where each member owns a specialty: the head chef (PM) coordinates, each chef focuses on their own station, and a taster reviews quality objectively.

Introducing the team-builder Skill

What Is team-builder?

team-builder is a skill that composes a custom agent team matched to your project’s purpose and requirements. It collects requirements through an interview with you, consults industry benchmarks via web search, diagnoses the current state of your existing team, and then proposes the optimal team composition.

This skill consists of two layers:

  • AI Layer (Steps 1–5) — Steps performed directly by Claude (the AI). Includes the requirements interview, benchmarking, diagnosis, proposal generation, and the user approval gate.
  • Script Layer (Steps 6–14) — Based on the proposal JSON you approved, the bun scripts/team-builder.ts script automatically creates agent files and registers them into the system.
Important: The script layer runs only when you explicitly approve at Step 5. The AI layer merely proposes; the actual file creation is handled by the script. This separation of the two layers serves as a safety mechanism.

Why Two Layers?

You might wonder: “Couldn’t we just leave everything to the AI?” The answer comes down to reliability and accountability.

  • What AI excels at — understanding intent, conducting research, evaluating trade-offs, and generating creative proposals. Steps 1–4 leverage exactly these strengths.
  • What scripts excel at — deterministic file operations: creating directories, writing files in exact formats, updating multiple cross-referenced documents simultaneously, and producing consistent results every time. Steps 6–14 require exactly this reliability.
  • You are the gate — Step 5 guarantees that no change occurs without your consent. This prevents accidents where the AI deletes agents by mistake, breaks handoff chains, or leaves governance documents inconsistent.

4 Team Composition Patterns in the Existing System

The co-consult system already ships with 4 proven team composition patterns. team-builder references these patterns when proposing a new team.

  1. Quick Assessment — a lightweight evaluation team of 3 agents. Suited to small projects and quick diagnostics.
  2. Standard — a standard team of 5 agents. Suited to most general projects.
  3. Complex Transformation — a large-scale team of 8 agents. Suited to complex organizational change and large projects.
  4. Specialized Expert — an expert team of 4 agents. Suited to deep analysis in a specific domain.

AI Layer 5-step Workflow

The AI layer proceeds through the following 5 steps. Follow each step in order: Claude converses with you while proposing the optimal team composition.

Step 1: Requirements Interview

In the first step, Claude asks you 6 mandatory questions. Your answers to these questions become the baseline for the team design.

Question Purpose Example Answer
Domain/Purpose Identify the team’s area of activity Digital marketing agency
Team Size Plan the number of agents 4–6 agents
Primary Tasks Identify the specialist roles needed Content production, SEO, analytics
Tech Stack Determine required skills and tools Google Analytics, WordPress
Collaboration Style Design handoffs between agents Sequential pipeline
Success Metrics Set quality gate criteria Conversion rate, content quality score
All 6 questions must be answered before moving on to Step 2. Claude summarizes your answers back to you and asks for confirmation. Defining requirements clearly at this stage determines the quality of the entire team design.

Step 2: Benchmarking

Once your requirements are confirmed, Claude researches industry-standard team structures via web search. It consults at least 2 authoritative sources (McKinsey, BCG, Gartner, Forrester, etc.) and scores each reference team’s fit on a 1–5 scale.

  • Source reliability verification (published within the last 5 years, official domains)
  • Analysis of each reference team’s roles, hierarchy, and strengths/weaknesses
  • Fit score calculation against your requirements

Step 3: Current Team Diagnosis

Based on the benchmarking results, Claude diagnoses the current state of your team. It inventories the agents, skills, and dependencies already present in your project to avoid unnecessary duplication and make maximum use of existing assets.

  • Agent inventory — the list and status of existing agents/*.md files
  • Skill inventory — the list and owners of existing skills/*/SKILL.md files
  • Dependency map — handoff relationships between agents, and skill ownership relationships
  • Skill transfer plan — the plan that moves a deleted agent’s skills to another agent

Step 4: Proposal Generation

Synthesizing the diagnosis with the benchmarking, Claude generates a structured proposal. The proposal contains a team comparison table, agent change details, a skill change plan, workflow design, and benchmarking evidence.

Step 5: User Approval (MANDATORY GATE)

When the proposal is ready, Claude shows you the full proposal and requests explicit approval. Because this step is a mandatory gate, nothing proceeds until you explicitly reply “approve”.

Approval gate rule: After presenting the proposal, Claude guides you to choose one of three replies: approve, revise, or cancel. When you reply “approve”, Claude saves the proposal as a JSON file and instructs you to run bun scripts/team-builder.ts. Claude never runs the script itself.

Proposal Format

Proposal JSON Structure

The proposal generated by team-builder is saved in JSON format. This JSON serves as the input to the script layer (bun scripts/team-builder.ts). The main fields of the proposal are as follows.

Field Description
teamName Name of the team
benchmarkSources List of source URLs referenced during benchmarking
agentsToCreate[] Agents to create (name, role, tier, skills, etc.)
agentsToConvert[] Existing agents to convert to different roles
agentsToDelete[] Agents to delete along with the skills to transfer
skillsToCreate[] New skills to create
skillsToReassign[] Skills to transfer to another agent
workflowPhases[] Definitions of the team’s pipeline phases
changeHistoryEntry Summary to record in the change history

Proposal JSON Example

Here is an abbreviated example of the proposal JSON.

{
  "version": "1.0.0",
  "timestamp": "2026-08-10T14:30:00Z",
  "teamName": "digital-marketing",
  "benchmarkSources": [
    "https://www.mckinsey.com/.../marketing-operations"
  ],
  "changes": {
    "agentsToCreate": [
      {
        "name": "content-strategist",
        "formalName": "Content Strategist",
        "tier": { "claude": "medium" },
        "description": "Plans and outlines content strategy",
        "phases": ["1", "2"],
        "requiredSkills": ["research", "seo-analysis"],
        "rationale": "Benchmarking: a content strategy role is essential"
      }
    ],
    "agentsToDelete": [],
    "skillsToCreate": [
      {
        "name": "seo-analysis",
        "owner": "content-strategist",
        "description": "Performs SEO keyword and trend analysis"
      }
    ],
    "workflowPhases": [
      { "phase": 0, "name": "Initiation", "lead": "pm" },
      { "phase": 1, "name": "Research", "lead": "content-strategist" }
    ]
  },
  "approvedBy": "user",
  "approvedAt": "2026-08-10T15:00:00Z"
}
Beginner Tip: Claude generates the proposal JSON automatically, so you never write JSON by hand. Review the proposal contents Claude presents (agent names, roles, skills, etc.), request changes if needed, and simply reply “approve” when you agree with the content.

Top-Level Fields

The top-level fields of the proposal JSON divide into metadata fields and the change arrays inside the changes object.

Metadata Fields

  • version — Schema version (e.g., "1.0.0")
  • timestamp — When the proposal was generated
  • teamName — Human-readable team name
  • benchmarkSources — URLs or citations referenced
  • changeHistoryEntry — One-paragraph change summary
  • approvedBy / approvedAt — Who approved and when

Change Arrays (inside changes)

  • agentsToCreate[] — New agents to add
  • agentsToConvert[] — Existing agents to rename or repurpose
  • agentsToDelete[] — Agents to remove
  • skillsToCreate[] — New skills to author
  • skillsToModify[] — Existing skills to update
  • skillsToReassign[] — Skills whose ownership will transfer
  • workflowPhases[] — Phase definitions and dispatch order

Workflow Phase Entry

The workflowPhases array defines how agents coordinate across the project lifecycle:

{
  "phase": 0,
  "name": "Project Initiation",
  "lead": "engagement-leader",
  "supporting": ["strategy-analyst"]
}

Each phase specifies a lead agent who orchestrates the work and optional supporting agents who contribute. This structure maps directly onto the dispatch tables in AGENTS.md you saw in earlier chapters.

Skill Reassignment Entry

Whenever an agent is deleted, the skills it owns must be transferred to a remaining agent. The proposal records this as follows:

{
  "skill": "research",
  "fromOwner": "old-analyst",
  "toOwner": "strategy-analyst"
}

This ensures that no orphaned skills are left behind even when an agent is removed. The proactive skill transfer plan from Step 3 guarantees that every skill has a valid owner before any deletion occurs.

Script Layer

From Proposal JSON to Real Files

Once you approve the proposal at Step 5, Claude saves it to a JSON file (memory/team-builder-proposal-YYYY-MM-DD.json). When you then run the bun scripts/team-builder.ts script, it reads the JSON and automatically performs the following tasks.

  1. Create agent files — Generates the agents/<name>.md file for each agent in the agentsToCreate list, including frontmatter (name, tier, role, skills) and body.
  2. Convert agents — Renames the agent files in the agentsToConvert list and updates their roles and skills.
  3. Delete agents — Before deleting the agent files in the agentsToDelete list, transfers the skills they own to their new owners.
  4. Register in AGENTS.md — Registers the created agents in the Agent Roster table and Subagent dispatch table of AGENTS.md.
  5. Install skills — Creates the skill directories and SKILL.md files from the skillsToCreate list and registers them in VERSION_MANIFEST.md.
  6. Configure workflows — Defines pipeline phases and agent dispatch order based on workflowPhases.
  7. Validation — Runs validation scripts to verify every file was created correctly. 
# Script layer execution command
bun scripts/team-builder.ts memory/team-builder-proposal-2026-08-10.json

How the Script Works

Running the script with the command above reads the proposal JSON and applies changes in a fixed, safe order, logging a checkpoint at every step:

  1. Dry-run validation — Parses the JSON and checks all required fields without making changes.
  2. Delete agents — Removes agent files marked for deletion (after skill transfers complete).
  3. Convert agents — Renames and repurposes existing agents.
  4. Create agents — Generates new agents/<name>.md files from templates.
  5. Create skills — Generates new skills/<name>/SKILL.md stub files.
  6. Modify skills — Applies specified changes to existing skill files.
  7. Reassign skills — Updates the owner fields in skill frontmatter.
  8. Register in AGENTS.md — Adds new agents to the Agent Roster table and Subagent dispatch table.
  9. Update phase tables — Adjusts dispatch triggers and phase-gate mappings.
  10. Log change history — Writes the summary to memory/YYYY-MM-DD.md.
The script layer runs as a TypeScript script, not through Claude. Separating the roles this way — the AI only proposes while a validated script performs the actual file manipulation — greatly improves safety. At any time, you can revise the proposal or inspect the JSON contents before running the script.

What Happens If Something Goes Wrong?

The script performs checkpoint logging at every step. If an error occurs midway (for example, a file already exists or a permission is denied), the script reports exactly which step failed and what had already completed. Fix the problem and re-run the script — it skips the steps that already completed successfully.

Backup before running: The script is designed to be safe, but committing your current project state to Git before running team-builder.ts gives you a clean rollback point if anything unexpected happens.

Existing Team Composition Patterns

The co-consult system ships with 4 proven team composition patterns. Referencing these patterns lets you start building a new team quickly.

Quick Assessment

  • Agents: 3
  • Characteristics: Lightweight evaluation team
  • Best for: Small projects, quick diagnostics
  • Composition: PM + 2 specialist agents
  • Advantage: Simple composition and a fast start

Standard

  • Agents: 5
  • Characteristics: Standard multi-purpose team
  • Best for: Most general projects
  • Composition: PM + 4 specialist agents
  • Advantage: Clear role division and high extensibility

Complex Transformation

  • Agents: 8
  • Characteristics: Large-scale composite team
  • Best for: Organizational change, large projects
  • Composition: PM + 7 specialist agents
  • Advantage: Handles complex work systematically, phase by phase

Specialized Expert

  • Agents: 4
  • Characteristics: Deep-dive expert team
  • Best for: Deep analysis in a specific domain
  • Composition: PM + 3 specialist agents
  • Advantage: Deep, focused expertise in one domain

Pattern Agent Rosters

The actual agent rosters that make up each pattern are as follows.

Quick Assessment

Agents: 3  |  Best for: Rapid, focused evaluations

  • Engagement Leader (orchestrator)
  • Industry Expert (domain knowledge)
  • Strategy Analyst (research and analysis)

When to use: You need a quick market scan, competitive overview, or initial assessment within a single session.

Standard

Agents: 5  |  Best for: Typical consulting engagements

  • Engagement Leader (orchestrator)
  • Strategy Analyst (research)
  • Industry Expert (domain)
  • Communications Lead (deliverables)
  • Delivery Manager (operations)

When to use: Most standard engagements that require research, deliverable creation, and project coordination.

Complex Transformation

Agents: 8  |  Best for: Large-scale organizational change

  • Engagement Leader (orchestrator)
  • Change Management Partner (change management)
  • Strategy Analyst (research)
  • Industry Expert (domain)
  • Solutions Architect (technical design)
  • Communications Lead (deliverables)
  • Workstream Lead (coordination)
  • Delivery Manager (operations)

When to use: Multi-phase transformation programs involving technology, people, and process changes.

Specialized Expert

Agents: 4  |  Best for: Deep-domain technical work

  • Engagement Leader (orchestrator)
  • Subject Matter Expert (functional depth)
  • Technology Specialist (tools and automation)
  • Data Analyst (metrics and modeling)

When to use: Highly specialized tasks such as financial modeling, HR analytics, or technology stack evaluation.

Pattern Selection Guide

Use this guide when choosing the pattern that fits your situation:

Small Scope

  • Single research question
  • One-off analysis task
  • Tight deadline (same session)
  • → Quick Assessment

Medium Scope

  • Multi-week engagement
  • Client deliverables expected
  • Research + writing + coordination
  • → Standard

Large Scope

  • Multi-phase program
  • Stakeholder management needed
  • Technology + people + process
  • → Complex Transformation

Deep Domain

  • Heavy data analysis
  • Specialized tooling
  • Functional expertise required
  • → Specialized Expert
Pattern Selection Guide: If you are building a team for the first time, we recommend starting from the Standard (5 agents) pattern. It provides the basic structure of a PM, researcher, writer, reviewer, and automation lead, and you can customize it by adding or removing agents as needed.

Hands-On: Build Your Own Agent Team

Practice Goal

In this exercise, you will use the /team-builder command in the Claude Desktop App to compose your own custom agent team. Pick a domain you care about, prepare your requirements, and ask Claude to build the team.

Practice Steps

  1. Choose your domain — Pick a single field you are interested in. Examples: educational content production, software development, marketing campaigns, research projects. The domain determines which agents and skills you need.
  2. Prepare your requirements — Prepare answers to the 6 questions from Step 1 in advance. Thinking through the domain, team size, primary tasks, tech stack, collaboration style, and success metrics makes your conversation with Claude far more efficient.
  3. Ask Claude to build the team — In the Claude Desktop App, send a request similar to the example prompt below. Claude activates the team-builder skill and starts the 5-step workflow.
  4. Review the proposal — Carefully review the proposal Claude generates. Check that the agent names, roles, tiers, skills, and workflow match your requirements. Tell Claude what to change if anything needs adjustment.
  5. Approve — If you agree with the proposal, reply “approve”. Claude saves the proposal to a JSON file.
  6. Verify the results — Follow Claude’s guidance to run bun scripts/team-builder.ts, then check the generated agent files and the AGENTS.md updates.

Example Prompt

Example message to send to Claude: 
/team-builder

I want to build an agent team for educational content production.

1. Domain: Online educational content production
2. Team size: 4-5 agents
3. Primary tasks: Lecture material planning, slide creation, quiz writing, quality review
4. Tech stack: Markdown, HTML, Claude Code
5. Collaboration style: Sequential pipeline (plan → write → review → finalize)
6. Success metrics: Completeness, consistency, learning goal achievement rate
Practice Tip: Start with the Standard (5 agents) pattern, then add or remove agents as needed once you are comfortable with team composition. team-builder reuses existing agents wherever possible, so any agents you have already created can be kept without deletion or conversion.

Summary

Key Takeaways

  • An agent team is a system where multiple specialist agents collaborate. It overcomes the limitations of a single AI (no role separation, bias, sequential processing) and produces high-quality output.
  • The team-builder skill consists of two layers: an AI layer (performed by Claude) and a script layer (performed by an automated script). For safety, no files are created without user approval.
  • 5-step workflow: requirements interview (6 mandatory questions) → benchmarking (web search) → current team diagnosis (agents/skills/dependencies) → proposal generation (JSON) → user approval (mandatory gate).
  • The proposal JSON holds the agents to create/convert/delete, the skills to create, the workflow phases, and more. Claude generates it automatically, so you never write it yourself.
  • The script layer runs bun scripts/team-builder.ts, which reads the proposal JSON and automatically creates agent files, registers them in AGENTS.md, installs skills, configures workflows, and validates the result.
  • The existing patterns (Quick Assessment, Standard, Complex Transformation, Specialized Expert) provide excellent starting points for designing a new team.
