Learning Roadmap

If you have read all 13 chapters and appendices of this handbook, you have already finished the beginner track. Here is a stage-by-stage roadmap for how you might go deeper from here.

Beginner — Done!

You have completed the beginner stage once you have finished all of the following.

Chapters 1–13 — a complete read, from core concepts all the way to workflow automation
Appendix A — remote access setup completed
Appendix B — Claude Code CLI basics mastered
Appendix C — low-cost backend integration understood
Practice — at least one co-consult or co-deck project carried out yourself
Tip: The goal of the beginner stage is a broad understanding of "which tools exist and how they work." You do not need to memorize everything perfectly. Just refer back to the handbook whenever you need it.

Recommended Intermediate Path

After finishing the beginner track, work through these five paths in order.

1. Master the Claude Code CLI — building on Appendix B, carry out a project entirely within the CLI environment. Getting comfortable with terminal commands will greatly speed up your work.
2. Integrate low-cost backends — using Ollama or LM Studio introduced in Appendix C, hook up local models. You can experiment with many models while cutting costs dramatically.
3. Run a real co-consult project — using the consulting harness learned in Chapter 3, run a market analysis project on a topic of personal interest. The key is experiencing the full pipeline: research → storyline → slide production → PDF output.
4. Produce real presentation material with co-deck — using the workflows covered in Chapter 12, build a slide deck you can actually use in academic talks, business presentations, or training materials.
5. Write custom agents/skills — review agent authoring from Chapter 9 and skill authoring from Chapters 10–11, then create agents and skills tailored to your own work. Add files under the agents/ directory and register them in CLAUDE.md to start using them immediately.

Advanced Challenges

If you have completed the intermediate path and want to push further, try these four challenges.

  1. Create a custom variant for your field — understand ai-workspace-standards' L0 → L1 → L2 structure and build a variant project specialized in your domain (healthcare, law, education, etc.). This involves customizing agents, scripts, and skills on top of the common template.
  2. Set up CI/CD pipelines — use GitHub Actions to configure pipelines for agent configuration validation, documentation builds, and automated deployment. Integrating scripts like audit.ts and validate-templates.ts into CI keeps the whole team consistent.
  3. Build a multi-user collaboration environment — set up an environment where several people can work together in the same harness project. Include Git branch strategy, code review process, and version management of agent configuration files.
  4. Contribute to open source — contribute bug fixes, documentation improvements, or proposals for new agents/skills to the ai-workspace-standards repository. Open source contribution is one of the fastest ways to grow.
Note: Everyone learns at a different pace. At any step along the intermediate paths, feel free to reorder things based on your interests and needs, or linger longer on a particular step. What matters is practicing consistently.

Community

Learning alone is fine, but learning alongside others gets you much further. Use the community channels below to ask questions, share experiences, and stay up to date.

The ai-workspace-standards GitHub

This is the project on which the handbook is based. GitHub offers several ways to get involved.

Issues

Leave reports about problems you hit while using the system, improvement suggestions, and feature requests. If you find a bug, open an issue so the development team hears about it.

Discussions

Join free-form questions and debates. Read other users' stories and share your own know-how too.

Pull Requests (PR)

You can contribute directly: fixing typos in docs, proposing new agents/skills, improving code, and more. Beginners are welcome!

Wiki

Tips, tutorials, and usage examples beyond the official docs are collected here. It is a knowledge storehouse written together by community members.

Official Claude Community

On Anthropic's official forum you can find Claude's latest feature updates, usage tips, and shared case studies. Visit the Community section of the official Anthropic website.

Discord / Slack Channels

If an ai-workspace-standards community channel exists, you can talk with other users in real time. Conversations there include:

  • Help requests — setup problems, agent-writing questions, error troubleshooting
  • Project sharing — showing off your own agents, skills, and variants
  • Study groups — recruiting groups that study the handbook together
  • Latest news — updates, events, and new feature introductions
Tip: If you have a question, file it as a GitHub issue. When asking, include your Claude version, operating system, and the error message — you will get faster, more accurate answers. And be sure to post a follow-up on "how it got solved" — it helps other beginners enormously!

Application Scenarios

The multi-agent harness you learned in this handbook can be applied across many fields. Here are five representative scenarios.

1. Education

In education, the harness lets you produce lecture materials and student guides efficiently.

  • Lecture material production (co-deck) — enter a topic and the pipeline runs automatically: research → storyline → slide production → PDF output. Instructors only review the final deliverable.
  • Student guides (handbook) — automatically generate a handbook matching your lecture so students have reference material before and after class.
  • Core agents — research, storyline, html-build, pdf-export, handbook-writer

2. Consulting

In consulting, you can automate the entire process from market analysis to presentation.

  • Market analysis (co-consult) — an agent team performs research on a specific industry or market → framework application → analytical report writing.
  • Presentation (co-deck) — based on the analysis, build a client-facing slide deck. Data charts and visual diagrams are generated automatically too.
  • Core agents — research, storyline, design, image-curator, diagram-specialist, html-build, pdf-export

3. Research

In research, you can systematically produce everything from literature search to conference presentations.

  • Literature search — the research agent collects related papers, reports, and articles from the web, and source-verifier validates source reliability.
  • Research reports — from the collected material, the storyline agent writes a structured report.
  • Conference talks — feed the report into the co-deck pipeline to build a conference slide deck.
  • Core agents — research, source-verifier, storyline, diagram-specialist, html-build

4. Marketing

In marketing, you can streamline everything from market research to campaign presentations.

  • Market research — the research agent handles competitor analysis, trend identification, and target-audience insight extraction.
  • Campaign planning — based on the findings, establish campaign strategy, messaging, and channel plans.
  • Presentation — produce executive-report slide decks that convey the strategy alongside visuals.
  • Core agents — research, storyline, design, image-curator, html-build

5. Legal

In legal work, you can build a systematic workflow from legal research to client reporting.

  • Legal research — collect relevant statutes, case law, and doctrine while source-verifier cross-checks sources.
  • Opinion writing — based on the research results, write structured legal opinions.
  • Client reporting — convert complex legal content into an easy-to-understand slide deck for clients.
  • Core agents — research, source-verifier, storyline, html-build, pdf-export
Tip: Try applying what you learned in this handbook to your own field. Start with a small project (say, a five-slide mini presentation) and scale up gradually. It does not need to be perfect — let the agents create drafts and refine them yourself.

Frequently Asked Questions (FAQ)

Here are the questions handbook readers ask most often, with answers.

Q1: Can I do this without the Claude Desktop App?

Yes. The Claude Code CLI alone gives you access to every feature of the harness. The Claude Desktop App is a convenient way to use Claude in a graphical environment, but it is not required. Appendix B covers installing and using the Claude Code CLI in detail.

Note: The Claude Code CLI offers more customization options than the Claude Desktop App. If you want to configure agents per project and run scripts, the CLI environment is the better fit.

Q2: Is it free to use?

Claude offers a Claude Free plan and a Claude Pro plan. The Free plan has usage limits; for complex projects we recommend Pro. In particular, when an agent team performs many stages of work, token consumption rises, so the generous allowance of the Pro plan helps.

Saving tip: Using the low-cost backends introduced in Appendix C (Ollama, LM Studio, etc.), you can process simple tasks on local models and assign only the complex ones to Claude — cutting costs substantially.

Q3: Can I converse in my own language?

Yes, it is fully supported. Claude understands and generates many languages fluently. This handbook itself was written in Korean, and you can give instructions in Korean and receive results in Korean. Note, however, that technical terms or error messages may appear in English, so basic English reading ability helps.

Q4: Can I use other AI models?

Yes, you can. Besides Claude, various AI models such as DeepSeek, GLM (ChatGLM), Gemini, and Llama can be integrated into the harness. Appendix C covers low-cost backend integration; with Ollama in particular you can run open-source models from Hugging Face locally.

Note: Each model has different strengths. Claude excels at complex reasoning and long-form generation, DeepSeek shines at coding, and GLM is especially strong at Chinese/Korean processing. Choose or combine models according to your purpose.

Q5: How many agents can I create?

Technically, there is no limit. You can add as many agent definition files to the agents/ directory as you like. For manageability, however, around 5–15 is a good range. Too many agents cause role overlap and can confuse the PM agent about where to assign tasks. Create as many as you need, and tidy up unused agents.

Q6: Does it work without internet?

No. An internet connection is required to use Claude. Claude is cloud-based AI running on Anthropic's servers. Moreover, much of the harness needs the network: the research agent performing web searches, source-verifier checking URL accessibility, image-curator downloading images, and so on.

Caution: You cannot use Claude itself offline. That said, local models such as Ollama (Appendix C) let you use some AI features without internet. Keep in mind downloading model files does require internet.

Q7: Can I use it on mobile?

iOS and Android mobile apps are available for Claude. Simple conversations and basic tasks are possible on mobile. But complex projects run by agent teams (file creation, multi-agent coordination, Git integration, etc.) are best done in a desktop environment. Use mobile for quick questions and checking results.

Q8: Is my data safe?

Anthropic operates industry-leading security and privacy policies. Conversation content is not used for AI model training without user consent, and API traffic is encrypted. Claude Pro and Team plans meet enterprise-grade security standards. For details, see the Privacy Policy and Security pages on Anthropic's official website.

Security tip: Do not put sensitive personal information, passwords, API keys, and similar content into what you send Claude. If your project has a .env file, add it to .gitignore so it never reaches Git. For security-related matters, refer to Anthropic's latest security guidelines.

Q9: Can I share it with others?

Yes — sharing via GitHub comes most highly recommended. Push the whole project to a GitHub repository and teammates can recreate the identical environment instantly with git clone. It includes everything: agent configurations, skills, storylines, slide decks, and all other deliverables. With a private repository you can share without exposing anything publicly.

Note: The Projects feature of the Claude Desktop App also lets you share conversation Artifacts with teammates. Export the chat history, generated files, and prompts used, then share them.

Q10: Can I apply it directly to real work?

Yes — you can start right now with this handbook. This handbook was written with practical application as its goal. Once you understand Chapters 1–13 and the appendices, follow these steps to start a real project.

1. Create a new project repository on GitHub and apply the ai-workspace-standards template.
2. Open the project in the Claude Desktop App or the Claude Code CLI.
3. Run the co-consult or co-deck pipeline on a real work topic (e.g., Q3 market analysis, lecture materials, new product planning report).
4. Review and revise the drafts the agents produced.
5. Share the results with teammates and reflect their feedback.
Tip: At first, do not expect "perfect output." Treating the agents' drafts as a starting point and adding your expertise and experience is the most effective approach. Quality improves steadily the more you use it.

Q11: What if I don't like the output the agents produce?

You can improve output quality in several ways.

  1. Make prompts more specific — instead of "analyze OOO," say something like "analyze the OOO industry's 2024 market size, its top three competitors, and growth outlook in three pages."
  2. Improve research_notes.md quality — collecting more sources and richer detail during Stage 1 research greatly improves the quality of every later stage.
  3. Tune agent settings — the agent definition files in agents/ let you customize prompts, tone, output formats, and more.
  4. Review stage by stage — rather than running the whole pipeline at once, check and revise the result of each stage (research → storyline → slides → PDF).

Q12: Can I work on multiple projects at once?

Yes, absolutely. Each project has its own independent directory structure, so you can run several projects concurrently. The Projects feature of the Claude Desktop App keeps each project's context separated. In the Claude Code CLI, create multiple projects under the presentations/ directory and manage them there.
