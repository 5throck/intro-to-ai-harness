Lecture Guide

Materials for instructors teaching this handbook (Chapters 1–13 + Appendices A/B/C).

This document is an instructor-only operational reference, not part of the handbook body. It does not need to be shared with learners.
Before finalizing, re-read the full text and check for typos, awkward phrasing, and chapter/section number mismatches. AI-generated drafts may contain errors or unnatural wording.

Consolidated Prerequisites Checklist

This brings together items scattered across the setup documents (see Chapter 3 · Setting Up Your Lab) so you can verify everything before the course begins. Notify participants of this list at least a day before class so on-site setup issues don't waste time.

☐ Active Claude Pro subscription (a subscription account, not an API key)
☐ A Claude.ai account created and login verified
☐ macOS or Windows 10/11 environment (Linux users use Claude Code CLI from Appendix B)
☐ At least 2GB of free disk space and a stable internet connection
☐ Claude Desktop App installed (detailed in Ch 2; installing in advance makes class smoother)
☐ The C:\git\project\setup pre-installation script folder ready (recommended)
☐ (For Ch 6–8 labs) ai-workspace-standards clone: git clone https://github.com/5throck/ai-workspace-standards.git
For the Ch 11 team-builder exercise, ask participants to think about their own work domain (e.g., marketing, education, research) in advance — this greatly shortens the interview. Notify participants to prepare "one recurring task of their own."

Chapter-by-Chapter Instructor Notes

Ch 1: Why AI Agent Teams? (Introduction)

This chapter establishes motivation for "why multiple AIs should work as a team" before the technical concepts in Ch 4. Use the single AI vs agent team comparison table to make the difference tangible, and introduce the harness concept lightly as a "framework for moving AI teams."

The expected-outcomes section is a preview of what participants will experience in the Ch 6–8 labs. Convey the "feel" here and defer technical detail to Ch 4.

Participant activity Ask for a show of hands: "When using AI solo, have you ever wished several AIs would split the work?" This builds curiosity that carries into Ch 4.

Ch 2: Getting Started with Claude Desktop App

This is the handbook's default tool, so the most important thing is that participants actually install it and start their first conversation. Participants who already installed it can focus on the subscription comparison and project creation lab.

Linux users have no desktop app, so point them to Appendix B (Claude Code CLI). Do not cover the CLI itself in this chapter.

Participant activity Have participants create an "AI Learning" project and enter this Custom Instruction: "Answer in Korean. Explain simply for beginners." They will keep using this project throughout the handbook.

Ch 3: Setting Up Your Lab

Check the prerequisite checklist first, run the OS-specific setup scripts, then verify installation. Since macOS/Windows/Linux are all covered, demonstrate once on your own OS and let others follow the matching script.

Make sure the verification step (bun setup-common.ts) passes. Saving time here makes the Ch 6–8 labs go smoothly.

Ch 4: Multi-Agent Harness Concepts

This chapter is the reference point for all terms used later (agents, skills, workflows, PM, 3-Tier, PM Gateway), so it's worth slowing down. Analogies like "agent = an employee with a role, skill = a reusable procedure manual" work well on a whiteboard.

Participant activity Show the dispatch-flow SVG, then have participants talk to a neighbor for one minute about "how would PM orchestration apply to our team's work?"

Ch 5: Exploring ai-workspace-standards

Convey the L0→L1→L2 hierarchy and the variant concept. For beginners, the analogy "a template system that stamps out projects from a standard repository" works well. Use a table to clarify the different roles of AGENTS.md and CLAUDE.md.

Ch 6: co-consult — AI Consulting in Practice (core afternoon lab)

This chapter is dedicated to using an existing variant. Participants run a market analysis project by talking with the PM agent. Emphasize how each phase of the 7-phase workflow progresses automatically and how Gates 2 and 5 request user approval.

Have them confirm that deliverables (deliverables/reports/) are actually generated, and reinforce: "The AI didn't do this alone — agents divided roles and collaborated."

Participant activity Let participants pick one of the four team-composition scenarios (Quick Assessment, Standard, Complex Transformation, Specialized Expert) and talk with the PM agent about it.

Ch 7: co-deck — AI Presentation in Practice

Build a mini presentation with the 11-stage pipeline: theme/style selection, Gate 2 and 5 approvals, and HTML+PDF deliverables. Unlike Ch 6, a clear "presentation" output appears, which participants find satisfying.

Participant activity Have participants screen-share one finished slide so they can compare and feel how theme/style choices affect the result.

Ch 8: Combined co-consult + co-deck Pipeline

An integration lab that passes the Ch 6 report into the Ch 7 input. Show the full flow — "topic in → finished deck in 30–45 minutes" — and have participants compare the agent compositions of the two systems.

Participant activity Let participants feed their Ch 6 report directly into co-deck in Ch 7 to experience the value of integration first-hand.

Ch 9: Creating & Modifying Agents

Cover the agent file format (frontmatter, role definition, Tier) and use agent-lifecycle-manager to write, register, and validate a simple specialist agent. For beginners, the analogy "résumé (frontmatter) + job manual (body)" works well.

Participant activity Have participants register the agents/my-analyst.md they created in the lab into AGENTS.md and validate it with bun scripts/agent-lifecycle-audit.ts.

Ch 10: Creating & Modifying Skills

Cover the skill file format (frontmatter, triggers, steps) and use skill-lifecycle-manager + skill-creator to write and test a custom skill. Use the "cook's recipe" analogy for the relationship between agents and skills.

Participant activity Have participants register the skills/my-reviewer/SKILL.md they created in the lab and invoke it to verify it works.

Ch 11: Building Your Own Agent Team

Cover team-builder's AI-layer 5-step workflow (requirements interview → benchmarking → current team diagnosis → proposal generation → approval) and the script layer (bun scripts/team-builder.ts).

If participants decide their domain in advance, the interview goes fast. Have them review the proposal and complete approval (MANDATORY GATE).

Participant activity Have participants get a custom agent team proposal for their domain (marketing, education, research, etc.) and complete the approval step.

Ch 12: Understanding Workflows & Automation

Explain /sync, Git/GitHub PR automation, hooks, CI/CD basics, and how dev-sync.ts works. Start beginners with the analogy "automation = delegating repetitive work to a system."

Frame this chapter as a concept-awareness / follow-up study module rather than a hands-on lab. Keep it concept-focused and point CLI-savvy participants to Appendix B for deeper material. For interested participants, offer an optional post-class exercise (commit a sample project with /sync, verify hook behavior) and emphasize automation as a self-directed next-step area.

Ch 13: Next Steps + Wrap-Up

Wrap up with the learning roadmap, community, application scenarios, and FAQ. Review the whole day and connect everything built in Ch 1–12 (projects, lab deliverables, agents, skills, team proposal).

Participant activity Have participants present the team proposal from Ch 11 and ask, "Do you want to actually build this team next?" to reinforce motivation for continued learning.

Chapter Comprehension Questions

Ask the following questions at the end of each chapter to check understanding. The goal is not getting the right answer — it's having participants explain in their own words.

Ch 1 Comprehension Check
  1. What is the biggest difference between a single AI and a multi-agent team? (context, role, parallelism)
  2. How would you define a "harness"?
  3. What becomes possible when multiple AIs collaborate?
Ch 2 Comprehension Check
  1. What is the difference between Claude Desktop App and the Claude.ai web version?
  2. Why is the Projects feature useful?
  3. What can you build with Artifacts?
Ch 3 Comprehension Check
  1. Did you run the setup script for your OS?
  2. What command verifies that the installation succeeded?
  3. Why should pre-installation be done in advance?
Ch 4 Comprehension Check
  1. Explain the difference between agents, skills, and workflows in one sentence each.
  2. What role does the PM (Project Manager) agent play?
  3. Why is the 3-Tier strategy (High/Medium/Low) needed?
Ch 5 Comprehension Check
  1. What role does each of AGENTS.md and CLAUDE.md play?
  2. What is the L0→L1→L2 hierarchy?
  3. What is a variant?
Ch 6 Comprehension Check
  1. What are Gates 2 and 5 in co-consult's 7-phase workflow?
  2. What is the difference between the four team-composition scenarios?
  3. Where are the deliverables stored?
Ch 7 Comprehension Check
  1. In co-deck's 11-stage pipeline, at which stage do you choose theme/style?
  2. What do Gate 2 (content) and Gate 5 (sample PDF) each approve?
  3. How are the HTML and PDF deliverables produced?
Ch 8 Comprehension Check
  1. How do you pass a co-consult report into co-deck as input?
  2. Why are the agent compositions of the two systems different?
  3. Describe the full flow of the integrated pipeline.
Ch 9 Comprehension Check
  1. What goes into an agent file's frontmatter?
  2. What does Tier (High/Medium/Low) determine?
  3. What are the 5 steps of agent-lifecycle-manager?
Ch 10 Comprehension Check
  1. What role does a skill file's metadata.triggers play?
  2. What is the relationship between agents and skills?
  3. What are the 6 steps of skill-lifecycle-manager?
Ch 11 Comprehension Check
  1. Recite the 5 steps of team-builder's AI layer in order.
  2. Why is proposal approval a MANDATORY GATE?
  3. What does the script layer (bun scripts/team-builder.ts) do?
Ch 12 Comprehension Check
  1. What does the /sync command handle in one go?
  2. Why do you need a PR (Pull Request) in Git/GitHub?
  3. What is a hook?
Ch 13 Comprehension Check
  1. Summarize what you built today (project, deliverables, agents, skills, team proposal) in one sentence each.
  2. What will you learn next?
  3. What will you apply to your own work first?
