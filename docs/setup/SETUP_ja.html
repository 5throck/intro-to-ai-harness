ワークショップ環境セットアップガイド

ワークショップ開始前にインストールを完了してください——目標は、セッション開始時に追加の環境設定なしで、すぐにハンズオン実践に取り組めるようにすることです。

セットアップの流れ

1. OS updates
   └─ Windows: winget upgrade --all
   └─ macOS:   brew update && brew upgrade
   └─ Linux:   apt update && apt upgrade

2. Foundational tools
   └─ Windows: PowerShell 7+, Windows Terminal, Git (+ Git Bash)
   └─ macOS / Linux: curl, git

3. Runtimes
   └─ bun  (default runtime & package manager)
   └─ python3
   └─ uv   (Python package manager)

4. CLI tools
   └─ gh  (GitHub CLI)
   └─ claude  (Claude Code CLI)
   └─ agy  (Antigravity CLI)

5. Desktop apps
   └─ Google Chrome
   └─ Claude Desktop app
   └─ Antigravity Desktop app
   └─ Mark  (Markdown viewer)

6. Final verification ✅
   └─ bun setup-common.ts

ステップ0 — セットアップスクリプトリポジトリのクローン

ワークショップのインストールスクリプトは別のリポジトリ（5throck/setup）で管理されています。以下のコマンドでクローンし、以降のすべてのコマンドをクローンしたsetup/フォルダ内から実行してください。

git clone https://github.com/5throck/setup.git
cd setup

ステップ1 — チェックリストの完了

スクリプトを実行する前に、まず事前インストールチェックリストを読んで完了してください。

確認すべき主要項目

  • Claude Pro/MaxとGemini Advancedのアクティブなサブスクリプション（APIキーではなく、サブスクリプションプラン）
  • GitHubアカウントを作成済みで、gh auth loginの準備ができている
  • 少なくとも5 GBの空きディスク容量と管理者/sudo権限の確認

ステップ2 — OS別スクリプトの実行

管理者 / sudo権限でターミナルを開き、OSに応じたスクリプトを実行します。

macOS

bash setup-mac.sh
# 任意: WezTermもインストール（GPUアクセラレーションターミナル）
bash setup-mac.sh --wezterm
# 任意: Docker Desktopもインストール
bash setup-mac.sh --docker
# 両方:
bash setup-mac.sh --wezterm --docker

Linux (Ubuntu / Debian)

bash setup-linux.sh
# 任意: WezTermもインストール
bash setup-linux.sh --wezterm
# 任意: Dockerもインストール
bash setup-linux.sh --docker
# 両方:
bash setup-linux.sh --wezterm --docker

Windows

PowerShellを管理者として実行し、以下のコマンドを入力してください。

# デフォルト実行（スクリプトが実行ポリシーを自動設定）
.\setup-windows.ps1

# オプション:
.\setup-windows.ps1 -WSL2             # WSL2もインストール（再起動が必要）
.\setup-windows.ps1 -WezTerm          # WezTermもインストール
.\setup-windows.ps1 -Docker           # Docker Desktopもインストール
.\setup-windows.ps1 -Force            # 既存インストール済みのツールも含め全て再インストール
.\setup-windows.ps1 -WSL2 -WezTerm -Docker  # すべてのオプションをインストール
実行後： PATHの変更を適用するため、ターミナルを閉じて再開してください。

ステップ3 — インストールの確認

bun setup-common.ts

インストール済みツールの検証テーブルが表示されます。すべての項目が ✅ になれば準備完了です。

トラブルシューティング

インストール後にbun: command not found

ターミナルを再起動してください。Windowsでは、bunはユーザー環境変数に自動的に登録されます。macOS/Linux:

export PATH="$HOME/.bun/bin:$PATH"

bun install -gの後にclaude: command not found

スクリプトはbunが失敗した場合、npmフォールバックで自動的にリトライします。問題が続く場合は、bun pm ls -gでパスを確認し、PATHに追加してください。

インストール後にagy: command not found

Antigravity CLIインストーラーはバイナリを~/.local/binまたは/usr/local/binに配置します。source ~/.bashrcを実行するか、ターミナルを再起動してください。

Windows: 「このシステムではスクリプトの実行が無効になっています」

スクリプトは自動的にこれをRemoteSignedに設定します。手動で変更する場合：

Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
Windows: 管理者権限なしで実行 — スクリプトは警告を表示しますが継続します。wingetなどの一部のインストールが失敗する場合があるため、PowerShellを管理者として再実行することをお勧めします。

インストールログの確認

Windowsスクリプトの実行ログは%USERPROFILE%\workshop-setup-logs\に自動的に保存されます。

bun setup-common.tsを実行し、すべての項目が ✅ になれば、ワークショップ環境の準備は完了です。
